## 1. 项目概述

### 1.1 项目定位

**Trendy Process Portal**（群顶流程引擎）是一个基于 **Vue 3** 的**可视化流程编排与管理平台**，作为微前端子应用通过 `wujie` 框架嵌入到主系统中。核心价值在于为业务人员提供**零代码的流程设计、配置、执行与实时监控**能力。

### 1.2 核心能力矩阵

| 能力域 | 能力项 | 说明 |
|--------|--------|------|
| 流程设计 | 可视化编排 | 基于 AntV X6 的拖拽式流程图设计器，支持 20+ 种节点类型 |
| 流程设计 | 节点配置 | 声明式动态表单系统，每个节点类型拥有独立的配置 Schema |
| 流程设计 | 连线规则 | 支持普通连线 + 条件表达式连线，内置连线合法性校验 |
| 流程管理 | 生命周期管理 | 流程的创建、编辑、删除、触发执行 |
| 流程管理 | 任务监控 | 历史执行记录查询，按状态/结果多维筛选 |
| 流程管理 | 强制干预 | 支持强制终止执行中的任务 |
| 数据管理 | 变量管理 | 全局变量与节点变量的 CRUD，支持多数据类型 |
| 运行监控 | 实时追踪 | WebSocket 实时推送流程实例执行状态 |
| 运行监控 | 状态可视化 | 节点颜色编码（绿/橙/灰）+ 连线高亮展示执行路径 |
| 运行监控 | 错误诊断 | 失败节点展示详细错误信息（Popover） |

### 1.3 运行环境

| 配置项 | 值 | 说明 |
|--------|-----|------|
| 部署路径 | `/process-console` | Vite `base` 配置 |
| 开发端口 | `3006` | Vite dev server |
| API 代理前缀 | `/trendy-process-api` | 开发环境代理到后端服务 |
| 容器化 | Docker + Nginx:1.23.1 | 生产环境部署 |
| 路由模式 | Hash 模式 (`createWebHashHistory`) | 兼容微前端嵌入场景 |
| 页面标题 | 群顶流程引擎 | `index.html` `<title>` |

## 3. 前端工程化实践

### 3.1 项目初始化：Vite 工程骨架

**入口文件** `index.html`：

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <link rel="icon" href="/favicon.ico" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>群顶流程引擎</title>
  </head>
  <body>
    <div id="app"></div>
    <script type="module" src="/src/main.ts"></script>
    <!-- 运行时配置：在应用代码之前加载，挂载 window.BASE_CONFIG -->
    <script src="/config.js"></script>
  </body>
</html>
```

**设计要点**：
- `<script type="module">` 利用浏览器原生 ESM 加载入口
- `config.js` 在 `main.ts` 之前加载，确保 `window.BASE_CONFIG` 可用
- viewport 设置 `width=device-width` 保证移动端适配基础

### 3.2 应用入口：`main.ts`

```typescript
// 关键初始化流程
1. 创建 Pinia 实例 → app.use(store)
2. 创建 Router 实例 → app.use(router)
3. 安装 Element Plus → app.use(ElementPlus)
4. 全局注册所有 Element Plus 图标组件
5. 全局注册 ShowTooltip 组件
6. 解析 URL Hash 参数 → window.routeParameters
7. 挂载到 #app
```

**设计决策**：
- 全局注册所有图标组件 — 避免每个组件单独 import 图标，简化使用
- `sessionStorage.clear()` 在入口执行 — 确保每次加载时缓存状态干净
- URL Hash 参数解析 — 微前端场景下主应用通过 Hash 传递 token/processId 等参数

### 3.3 TypeScript 配置体系

**三层 tsconfig 架构**：

| 配置文件 | 用途 | 关键配置 |
|---------|------|---------|
| `tsconfig.json` | 根配置，引用子配置 | `references` 指向 3 个子配置；`paths: {"@": ["./src"]}` |
| `tsconfig.app.json` | 应用代码 | `extends @vue/tsconfig`；`include: src/**/*` |
| `tsconfig.config.json` | Vite 配置文件 | 用于 `vite.config.ts` 类型检查 |
| `tsconfig.vitest.json` | 测试文件 | 用于 `vue-tsc --noEmit` 类型检查 |

**路径别名**：`@/` → `src/`，在 `tsconfig` 和 `vite.config.ts` 中双重配置。

**类型声明**：
- `env.d.ts` — `/// <reference types="vite/client" />` Vite 客户端类型
- `shims-vue.d.ts` — `.vue` 文件模块声明，使 TypeScript 识别 `.vue` 文件

### 3.4 代码规范体系

#### ESLint 配置 (`.eslintrc.js`)

```javascript
{
  extends: [
    'plugin:vue/vue3-recommended',         // Vue 3 推荐规则
    'plugin:vue/vue3-strongly-recommended', // Vue 3 强力推荐规则
    'eslint:recommended'                    // ESLint 内置推荐
  ],
  parser: 'vue-eslint-parser',  // 解析 .vue 文件
  parserOptions: {
    ecmaVersion: '2020',
    ecmaFeatures: { jsx: true }  // 支持 JSX 语法
  },
  globals: {
    // 声明全局变量，避免 no-undef 报错
    ElMessage: true, ElMessageBox: true,
    ElNotification: true, ElLoading: true
  }
}
```

**关键规则**：
- `indent: [2, 2]` — 2 空格缩进
- `comma-dangle: [2, 'never']` — 禁止尾逗号
- `block-spacing: [2, 'always']` — 块内空格

#### Prettier 配置 (`.prettierrc`)

```json
{
  "singleQuote": true,      // 单引号
  "semi": false,            // 无分号
  "trailingComma": "none",  // 无尾逗号
  "arrowParens": "none"     // 箭头函数单参数省略括号
}
```

### 3.5 Vite 构建配置

```typescript
// vite.config.ts 核心配置
{
  plugins: [vue(), vueJsx()],          // Vue SFC + JSX 支持
  base: '/process-console',            // 部署基础路径
  server: {
    port: 3006,
    proxy: {
      '/trendy-process-api': {
        target: 'http://192.168.37.129:8088/'  // 后端 API 代理
      }
    }
  },
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url)),
      // 强制使用 X6 的 CommonJS 版本，避免 ESM 兼容问题
      '@antv/x6': '@antv/x6/dist/x6.js',
      '@antv/x6-vue-shape': '@antv/x6-vue-shape/lib'
    }
  }
}
```

**关键决策**：
- `@antv/x6` 别名指向 `dist/x6.js` — 解决 X6 ESM 版本在某些场景下的兼容性问题
- 代理配置包含大量注释的测试/开发环境地址 — 多人协作时切换后端，建议迁移到 `.env` 文件

### 3.6 构建脚本

```json
{
  "dev": "vite --host",                              // 开发服务器，暴露到局域网
  "build": "run-p type-check build-only",            // 并行：类型检查 + 构建
  "build-only": "vite build",                        // 仅构建
  "type-check": "vue-tsc --noEmit ...",              // 仅类型检查，不生成文件
  "preview": "vite preview --port 4173",             // 预览构建产物
  "lint": "eslint . --ext .vue,.js,.ts --fix"        // 代码检查 + 自动修复
}
```

### 3.7 Docker 部署

```dockerfile
FROM 172.20.15.4/library/nginx:1.23.1
MAINTAINER trendytech
ADD dist/index.html /usr/share/nginx/html
ADD dist /usr/share/nginx/html/
```

静态资源部署到 Nginx，适合微前端子应用的独立部署方式。

**分层原则**：
- **单向依赖**：上层依赖下层，下层不感知上层
- **展示层**只负责 UI 渲染和事件绑定，不包含业务逻辑
- **业务逻辑层**通过 Composition API Hooks 封装，可独立测试
- **数据层**通过拦截器统一处理认证、错误、缓存
- **基础设施层**纯函数，无副作用

### 4.3 模块化设计原则

1. **按功能领域划分**：`views/` 下每个页面独立目录，Hooks 按职责拆分
2. **配置驱动**：节点类型定义在 `constant/treeModules/`，通过 Schema 驱动 UI 渲染
3. **关注点分离**：`operator/index.vue` 只负责表单渲染框架，具体配置项由 `modules/` 下的组件处理
4. **依赖注入**：通过 `provide/inject` 传递 Graph 实例和 FlowState，避免 Prop Drilling
5. **发布订阅解耦**：`useClick.js` 和 `useRules.js` 实现组件间松散耦合通信

**`getDeviceSignalAjax` — 设备信号获取（带缓存）**：

```javascript
getDeviceSignalAjax(params, optionalObj) {
  const key = `SIGNAL_${params?.dataType || 'ALL'}_LIST`
  return new Promise((resolve, reject) => {
    this.signalTreeObj[key] = []
    // 优先从 sessionStorage 读取缓存
    if (sessionStorage.getItem(key) && !optionalObj) {
      resolve(JSON.parse(sessionStorage.getItem(key)))
    } else {
      getDeviceSignalList(params).then((res) => {
        const list = res ? [res] : []
        setDisabled(list, optionalObj)  // 处理禁用项
        this.signalTreeObj[key] = list
        if (!optionalObj) {
          sessionStorage.setItem(key, JSON.stringify(list))  // 写入缓存
        }
        resolve(list)
      })
    }
  })
}
```

**设计亮点**：
- **缓存策略**：`sessionStorage` 按 `dataType` 分 key 缓存，避免重复请求
- **禁用项处理**：传入 `optionalObj` 时跳过缓存，确保禁用项不被缓存污染
- **Promise 封装**：异步操作统一返回 Promise

### 7.2 请求拦截器

```javascript
service.interceptors.request.use((config) => {
  // 1. Token 注入
  const token = window.routeParameters?.token
  if (token) {
    config.headers['Authorization'] = 'Bearer ' + token
  } else {
    tokenLimitTip()  // 无 Token 时提示登录失效
  }

  // 2. URL 编码 — 特殊字符转义
  let url = ''
  config.url.split('/').forEach((v) => {
    url += `${encodeURIComponent(v)}/`
  })
  config.url = url.substring(0, url.length - 1)

  // 3. GET 请求防缓存 — 添加时间戳参数
  if (config.method === 'get') {
    const now = `${Date.now()}`
    if (config.params) {
      config.params[now] = now
    } else {
      const hasParams = config.url.includes('?')
      config.url = config.url + (hasParams ? '&' : '?') + `${now}=${now}`
    }
  }
  return config
})
```

### 7.3 响应拦截器

```javascript
service.interceptors.response.use(
  (response) => {
    // 1. 业务错误码处理
    const errCode = ['-1', '002004']
    if (errCode.includes(res.data.code)) {
      errorTip(res.data.message)  // 防抖错误提示
      return Promise.reject(res)
    }

    // 2. 文件下载自动处理
    const dis = res.headers['content-disposition']
    const contentType = res.headers['content-type']
    if (dis && contentType 匹配下载类型) {
      saveAs(res.data, decodeURIComponent(文件名))
    }

    return res.data  // 统一返回 res.data
  },
  (error) => {
    // 3. HTTP 错误处理
    if (error.response?.status === 401 || 500 + code '000003') {
      tokenLimitTip()  // Token 过期 → 跳转登录
    }
    if (error.response?.status === 406) {
      ElMessage({ message: '未授权！', type: 'error' })
    }
    // 4. 错误弹窗防抖 — 避免同一错误重复弹窗
    if (error.response?.data?.message) {
      if (messageInstance) messageInstance.close()
      messageInstance = ElMessage({ message: error.response.data.message, type: 'error' })
    }
    return Promise.reject(error)
  }
)
```

### 7.4 错误处理策略

| 错误类型 | 处理方式 | 实现 |
|---------|---------|------|
| 业务错误码 (-1, 002004) | 防抖错误提示（500ms） | `debounce(500, errorTip)` |
| Token 过期 (401, 000003) | 确认弹窗 → 跳转登录页 | `debounce(500, tokenLimitTip)` |
| 未授权 (406) | 错误提示 | `ElMessage.error` |
| 服务端错误消息 | 单例错误弹窗（关闭旧弹窗再开新） | `messageInstance` 变量控制 |
| 网络错误 | 通用错误提示 | `ElMessage.error` |

```
8. 通过 configData 传递配置项元数据到子组件
```

**数据序列化关键代码**（`useParams.js`）：

```javascript
const handleParams = (configuration) => {
  const { input, key, id } = configuration
  const inputList = []

  // 处理 input 数组中的 paramName 前缀
  if (input) {
    input.forEach((v) => {
      v.paramName = `${id}_input_${v.paramName}`
      v.value = v.value.split('_prefixParamName_')[0]  // 去除后缀
    })
  }

  // 处理 joinOrNotInput 字段
  Object.keys(configuration).forEach((key) => {
    if (configuration[key]?.joinOrNotInput) {
      const keyValue = configuration[key]
      keyValue.paramName = `${id}_input_${keyValue.paramName}`
      inputList.push(configuration[key])
      delete configuration[key]
    }
  })

  // 处理 filterConditions → 拆分为独立字段
  if (key == 'filterConditions') {
    configuration.filterConditions.forEach((item, index) => {
      inputList.push(
        { value: item.signalCode, paramType: 5, paramName: `${id}_input_signalCode_${index+1}` },
        { value: item.filterSymbol, paramType: 1, paramName: `${id}_input_filterSymbol_${index+1}` },
        { value: item.value, paramType: 1, paramName: `${id}_input_value_${index+1}` }
      )
    })
    delete configuration[key]
  }
  // ...
}
```

### 10.3 WebSocket 实时通信

**文件**：`src/utils/websocket.js`

```javascript
class SocketService {
  constructor(param) {
    this.websocket = null
    this.isConnect = false
    this.isActivelyClose = false
    this.timeout = param.timeout || 9 * 60 * 1000  // 9分钟心跳间隔
  }

  // 心跳机制
  start() {
    this.serverTimeoutObj = setInterval(() => {
      if (this.websocket?.readyState == 1) {
        this.send('ping')          // 发送心跳
        this.reset().start()       // 重置定时器
      } else {
        this.reconnectSocket()     // 重连
      }
    }, this.timeout)
  }

  // 重连机制
  reconnectSocket(param) {
    if (this.isConnect) return false
    this.isConnect = true
    this.timeoutNum = setTimeout(() => {
      this.connect(param)          // 10秒后重连
      this.isConnect = false
    }, 10000)
  }

  // 优雅关闭
  close() {
    this.isActivelyClose = true    // 标记手动关闭，不触发重连
    this.websocket?.close()
    clearTimeout(this.timeoutNum)
  }
}
```

**生命周期**：
- 连接建立 → 启动心跳 → 接收消息 → 回调处理
- 连接断开 → 10秒后自动重连（非手动关闭）
- 手动关闭 → 清理定时器，不重连

### 11.2 节点间数据引用机制

**文件**：`src/utils/index.js` — `getGraphNodes`

```javascript
// 获取画布中所有节点的输出和输入（作为其他节点的可选变量）
export const getGraphNodes = (graph, filterData = {}) => {
  const list = graph.getNodes()
    .filter(v => {
      // 过滤无输出节点 + 未配置节点
      return !noOutputNodeList.includes(v.data.nodeData.data.key)
        && v.data.nodeData.data.configuration?.validStatus
    })
    .map(item => {
      const nodeData = item.data.nodeData.data
      const configuration = nodeData.configuration
      const validInputList = []

      // 提取节点的输入作为变量（标记 inputAndOutputItem 的字段）
      if (inputAndOutput && configuration.validStatus) {
        Object.keys(configuration).forEach((key) => {
          if (configuration[key]?.inputAndOutputItem && configuration[key].value) {
            configuration[key].isInput = true
            configuration[key].label = configuration[key].paramNameZh
            configuration[key].inputNodePUid = item.id
            validInputList.push(configuration[key])
          }
        })
      }

      return {
        key: nodeData.key,
        value: nodeData.id,
        label: configuration.name,
        output: [...(nodeData.output || []), ...validInputList],
      }
    })
}
```

**设计意图**：允许下游节点引用上游节点的输出值或输入值作为自己的参数，实现节点间的数据流转。

## 12. 前端性能优化

### 12.1 优化策略总览

| 优化维度 | 具体措施 | 实现位置 | 效果 |
|---------|---------|---------|------|
| 加载性能 | 路由懒加载 | `router/index.ts` | 按需加载页面组件，减少首屏包体积 |
| 加载性能 | `keep-alive` 缓存 | `App.vue` | Tab 切换时保留组件状态，避免重建 |
| 渲染性能 | `v-if` 条件渲染 | 多处 | Tab 切换时销毁非活跃组件 |
| 渲染性能 | `v-memo` 可选 | 未使用 | 可用于列表项跳过不必要更新 |
| 网络性能 | GET 请求时间戳防缓存 | `request.js` | 确保每次请求获取最新数据 |
| 网络性能 | `sessionStorage` 缓存 | `stores/base.ts` | 信号树/设备类型/全局变量缓存 |
| 交互性能 | 防抖处理 | `throttle-debounce` | 错误弹窗、搜索输入、节点数据更新 |
| 交互性能 | X6 批量更新 | `graph.batchUpdate()` | 节点选中时批量更新连线样式 |
| 内存管理 | 事件监听清理 | `onUnmounted` | 避免内存泄漏 |
| 内存管理 | WebSocket 生命周期管理 | `websocket.js` | 手动关闭 + 定时器清理 |

## 14. 安全策略

### 14.1 认证与授权

| 机制 | 实现 |
|------|------|
| Token 传递 | `Authorization: Bearer ${token}` 通过请求拦截器注入 |
| Token 来源 | URL Hash 参数 `?token=xxx` 解析后存入 `window.routeParameters` |
| Token 过期 | 401 或 500+000003 → 弹窗确认 → 跳转 `/login` |
| 未授权 | 406 → 错误提示"未授权！" |

### 14.2 输入安全

| 措施 | 实现 |
|------|------|
| URL 编码 | 请求路径 `encodeURIComponent` 转义 |
| 表单校验 | 前端通过 `el-form` rules + `validate.js` 校验函数集 |
| 名称校验 | `validateName` 限制字符集：数字/汉字/字母/下划线/中划线/# |
| 数字校验 | `validateNumber` / `validatePositive` / `validateFixed` 等 |
| 变量名校验 | `validateVariableName` 限制格式：字母开头+字母数字下划线 |

### 14.3 操作安全

| 措施 | 实现 |
|------|------|
| 删除确认 | `ElMessageBox.confirm` 二次确认 |
| 强制终止确认 | 二次确认 + 操作说明 |
| 系统模式保护 | `noEditAutoProcess` / `noDetailHistory` 参数控制 |
| 离开确认 | Tab 切换时 `beforeLeave` 确认（画布未保存提示） |

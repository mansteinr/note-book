## 一、整体架构分层

该项目是一个标准的 **Spring Boot + MyBatis-Plus 三层架构** 项目,没有自定义拦截器/过滤器/Spring Security,请求链路较为简洁。

```
┌─────────────────────────────────────────────────────────┐
│  客户端 (浏览器/Postman)                                  │
└───────────────────────┬─────────────────────────────────┘
                        │ HTTP 请求
                        ▼
┌─────────────────────────────────────────────────────────┐
│  Spring Boot 内置 Tomcat (端口 8090)                     │
│  + DispatcherServlet (前端控制器,分发请求)                │
└───────────────────────┬─────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────────┐
│  Controller 层 (@RestController)                         │
│  - JobController          /job/**                       │
│  - JobCategoryController  /category 等路径                │
└───────────────────────┬─────────────────────────────────┘
                        │ 调用
                        ▼
┌─────────────────────────────────────────────────────────┐
│  Service 层 (@Service)                                   │
│  - JobsService (接口) → JobsServiceImpl (实现)           │
│  处理业务逻辑、构造分页对象、QueryWrapper                   │
└───────────────────────┬─────────────────────────────────┘
                        │ 调用
                        ▼
┌─────────────────────────────────────────────────────────┐
│  Mapper 层 (MyBatis-Plus)                                │
│  - JobsMapper extends BaseMapper<Jobs>                   │
│  + PaginationInnerInterceptor (分页拦截器)                │
└───────────────────────┬─────────────────────────────────┘
                        │ SQL
                        ▼
┌─────────────────────────────────────────────────────────┐
│  MySQL 数据库 (job库, localhost:3306)                     │
└─────────────────────────────────────────────────────────┘
```

## 二、请求处理完整流程(以分页查询为例)

请求示例:`GET http://localhost:8090/job/v1/page?pageNum=1&pageSize=10`

### 第 1 步:启动阶段(容器初始化)

- `JavaJobApplication` 主启动类通过 `@SpringBootApplication` 启动 Spring 容器
- `@MapperScan("com.trendy.javajob.mapper")` 扫描 Mapper 接口并生成代理对象
- `MybatisPlusConfig` 配置类注册 `MybatisPlusInterceptor`(分页拦截器 Bean)
- Spring 自动扫描 `@RestController`、`@Service` 并通过 `@Resource` 注入依赖

### 第 2 步:请求到达 → DispatcherServlet

- 内嵌 Tomcat 监听 **8090** 端口接收请求
- `DispatcherServlet` 根据 `@RequestMapping("/job")` 路由到 `JobController`

### 第 3 步:Controller 接收请求

`JobController` 中的分页查询方法:

```java
@GetMapping("/v1/page")
public ReponseResult getByPage(@RequestParam("pageNum") Integer pageNum,
                               @RequestParam("pageSize") Integer pageSize) {
    IPage<Jobs> jobsByPage = jobsService.getJobsByPage(pageNum,pageSize);
    // 日志输出 + 包装返回
    return new ReponseResult(jobsByPage);
}
```

- `@RequestParam` 绑定查询参数
- 调用 `jobsService`(由 Spring 注入的 `JobsServiceImpl`)

### 第 4 步:Service 处理业务逻辑

`JobsServiceImpl` 中的业务处理:

```java
Page<Jobs> page = new Page<>(pageNum, pageSize);              // 构造分页对象
QueryWrapper<Jobs> queryWrapper = new QueryWrapper<>();
queryWrapper.select("id","job_title",...);                   // 指定查询字段
queryWrapper.orderByDesc("publish_time");                    // 排序条件
Page<Jobs> jobsPage = jobsMapper.selectPage(page, queryWrapper);
```

- Service 层职责:构造分页对象、组装查询条件、调用 Mapper

### 第 5 步:Mapper 层 + MyBatis-Plus 拦截器执行 SQL

- `jobsMapper.selectPage()` 是 MyBatis-Plus `BaseMapper` 提供的内置方法
- **分页拦截器** `PaginationInnerInterceptor` 介入:自动在 SQL 上追加 `LIMIT` 和 `COUNT` 语句
- 最终执行的 SQL 类似:

```sql
SELECT id,job_title,category_name,salary,city,company,publish_time
FROM jobs
ORDER BY publish_time DESC
LIMIT 0, 10
```

- 对于自定义统计方法(如 `countByCategoryName`、`countByCity`),SQL 定义在 `JobsMapper.xml` 中,包含 `JOIN` + `GROUP BY` 查询

### 第 6 步:数据库返回结果 → 逐层回传

MySQL 返回结果 → MyBatis 结果映射(`resultMap`/`resultType`)→ `Jobs` 实体 / VO 对象 → Mapper 返回 → Service 返回 `IPage<Jobs>` → Controller

### 第 7 步:统一响应包装

`ReponseResult` 将结果包装成统一格式:

```json
{
  "code": 200,
  "msg": "成功",
  "data": { }
}
```

### 第 8 步:响应返回客户端

- `@RestController` 默认通过 Jackson 将 `ReponseResult` 序列化为 JSON
- DispatcherServlet → Tomcat → 客户端收到 JSON 响应

## 三、关键链路总结

```
HTTP 请求
  → Tomcat:8090
  → DispatcherServlet
  → JobController (@RequestMapping 匹配)
  → JobsServiceImpl (业务逻辑/分页构造)
  → JobsMapper (MyBatis-Plus 接口)
  → PaginationInnerInterceptor (改写SQL: 加 LIMIT)
  → MySQL (job 数据库)
  → 结果映射为 Jobs / VO
  → ReponseResult 统一包装
  → JSON 响应返回
```

## 四、项目特点说明

1. **无拦截器/过滤器/Security**:该项目未配置 Spring Security、Servlet Filter、HandlerInterceptor,请求直接到达 Controller
2. **唯一的"拦截"行为**:MyBatis-Plus 的分页拦截器作用于 **SQL 层**(非 HTTP 层),用于自动追加 `LIMIT`
3. **统一响应**:`ReponseResult` 作为所有接口的统一返回包装,包含 `code`、`msg`、`data`
4. **分层清晰**:Controller(路由+参数) → Service(业务) → Mapper(数据) 三层职责分明,典型的 Spring Boot Web 项目结构

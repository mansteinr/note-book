## 一、基础概念题

### Q1.1 什么是请求取消？为什么需要取消请求？

**题目难度**：⭐ 基础

**问题描述**：请说明前端请求取消的概念，以及在实际开发中为什么需要取消请求。

**参考答案**：

**请求取消**是指在 HTTP 请求发出后、响应返回前，主动终止该请求的能力。取消后，浏览器会停止等待响应，释放相关资源。

**需要取消请求的典型场景**：

| 场景 | 说明 | 不取消的后果 |
| --- | --- | --- |
| **搜索框输入** | 用户连续输入，每次触发新请求 | 旧请求响应可能覆盖新请求结果（竞态） |
| **页面/路由切换** | 用户离开当前页 | 无用请求占用带宽、回调执行报错（组件已卸载） |
| **请求超时** | 服务器响应慢 | 用户长时间等待，体验差 |
| **组件卸载** | React/Vue 组件被销毁 | setState 报错（内存泄漏警告） |
| **用户主动取消** | 点击"取消"按钮 | 请求继续占用资源 |
| **文件上传取消** | 用户取消上传 | 继续上传浪费带宽 |

**不取消请求的危害**：

1. **竞态条件（Race Condition）**：旧请求后返回，覆盖新数据
   ```
   用户输入 "a" → 请求1发出
   用户输入 "ab" → 请求2发出
   请求2先返回，显示 "ab" 结果 ✅
   请求1后返回，覆盖为 "a" 结果 ❌（数据错乱）
   ```

2. **内存泄漏**：组件卸载后回调仍执行，操作已销毁的 DOM/状态

3. **资源浪费**：带宽、CPU、连接数被无用请求占用

4. **状态混乱**：Promise 链继续执行，操作不存在的数据

### Q1.2 AJAX 与 Fetch 取消机制的本质区别是什么？

**题目难度**：⭐⭐ 中级

**问题描述**：请对比 AJAX（XMLHttpRequest）与 Fetch API 在请求取消机制上的本质区别。

**参考答案**：

| 维度 | AJAX (XMLHttpRequest) | Fetch API |
| --- | --- | --- |
| **取消方式** | `xhr.abort()` 方法 | `AbortController.abort()` |
| **取消信号** | 直接调用对象方法 | 通过 AbortSignal 信号传递 |
| **设计模式** | 命令式（对象方法） | 声明式（信号注入） |
| **耦合度** | 高（需持有 xhr 引用） | 低（信号与请求解耦） |
| **复用性** | 一个 xhr 一个 abort | 一个 controller 可控多个请求 |
| **标准化** | 私有 API | Web 标准（DOM 规范） |
| **错误类型** | `error` 事件，无统一标识 | `AbortError`（name 字段） |
| **与现代 API** | 仅限 XHR | 可用于 fetch、axios、addEventListener 等 |

**本质区别**：

```
AJAX 取消（命令式）：
  const xhr = new XMLHttpRequest()
  xhr.open('GET', '/api')
  xhr.send()
  xhr.abort()  // ← 直接调用对象方法，需持有 xhr 引用

Fetch 取消（声明式信号注入）：
  const controller = new AbortController()
  fetch('/api', { signal: controller.signal })  // ← 注入信号
  controller.abort()  // ← 通过信号取消，无需持有 fetch 引用
```

**Fetch 的信号机制优势**：

```javascript
// 优势1：一个 controller 控制多个请求（批量取消）
const controller = new AbortController()
fetch('/api/a', { signal: controller.signal })
fetch('/api/b', { signal: controller.signal })
fetch('/api/c', { signal: controller.signal })
controller.abort()  // 三个请求同时取消

// 优势2：信号可复用于其他 API
const controller = new AbortController()
fetch('/api', { signal: controller.signal })
document.addEventListener('click', handler, { signal: controller.signal })
controller.abort()  // 同时取消 fetch 和事件监听
```

### Q1.3 什么是 AbortController？它的核心作用是什么？

**题目难度**：⭐⭐ 中级

**问题描述**：请介绍 AbortController 的概念、核心作用及基本用法。

**参考答案**：

**AbortController** 是 DOM 规范定义的 Web API，用于**统一中止一个或多个异步操作**。它通过信号机制（Signal）实现异步操作的控制。

**核心组成**：

```
AbortController（控制器）
  └─ signal: AbortSignal（信号）
       └─ aborted: boolean       是否已中止
       └─ reason: any            中止原因
       └─ onabort: Function      中止回调
       └─ addEventListener()     监听 abort 事件

AbortController 方法：
  └─ abort(reason?)  触发中止
```

**基本用法**：

```javascript
// 1. 创建控制器
const controller = new AbortController()
const signal = controller.signal

// 2. 将信号传入异步操作（如 fetch）
fetch('/api/data', { signal })
  .then(res => res.json())
  .then(data => console.log(data))
  .catch(err => {
    if (err.name === 'AbortError') {
      console.log('请求被取消')
    } else {
      console.error('其他错误', err)
    }
  })

// 3. 触发取消
controller.abort()
```

**核心作用**：

1. **解耦控制与执行**：控制器与异步操作分离，无需持有异步操作引用
2. **统一中止接口**：fetch、addEventListener、axios 等都支持同一信号
3. **批量控制**：一个信号可控制多个异步操作
4. **传递中止原因**（新特性）：`controller.abort(new Error('用户取消'))`

**中止原因传递**（现代浏览器支持）：

```javascript
const controller = new AbortController()

// 监听 abort 事件，获取原因
controller.signal.addEventListener('abort', (e) => {
  console.log('取消原因:', controller.signal.reason)  // '用户主动取消'
})

// 触发取消并携带原因
controller.abort('用户主动取消')

// fetch 错误中也能获取原因
fetch('/api', { signal: controller.signal }).catch(err => {
  console.log(err.cause)  // '用户主动取消'（部分浏览器）
})
```

### Q1.4 AbortSignal 在请求取消中扮演什么角色？

**题目难度**：⭐⭐ 中级

**问题描述**：请说明 AbortSignal 在请求取消机制中的作用，以及它如何与 fetch 协作。

**参考答案**：

**AbortSignal** 是 AbortController 的只读属性，代表一个**中止信号**。它是控制器与异步操作之间的**通信桥梁**。

**角色与职责**：

```
┌──────────────────┐     传递信号      ┌──────────────────┐
│  AbortController │ ───────────────▶ │   AbortSignal    │
│  （控制方）       │                   │   （信号载体）    │
│  - abort()       │                   │  - aborted       │
└──────────────────┘                   │  - reason        │
                                       │  - onabort       │
                                       └────────┬─────────┘
                                                │ 注入
                                                ▼
                                       ┌──────────────────┐
                                       │  异步操作（fetch）│
                                       │  （执行方）       │
                                       │  监听 signal 变化 │
                                       └──────────────────┘
```

**fetch 内部如何使用 signal**：

```javascript
// fetch 内部伪代码
function fetch(url, options) {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest()
    xhr.open('GET', url)
    
    // 监听 signal
    const signal = options.signal
    if (signal) {
      if (signal.aborted) {
        // 信号已中止，直接拒绝
        reject(new DOMException('Aborted', 'AbortError'))
        return
      }
      // 监听中止事件
      signal.addEventListener('abort', () => {
        xhr.abort()  // 底层仍调用 xhr.abort()
        reject(new DOMException('Aborted', 'AbortError'))
      })
    }
    
    xhr.onload = () => resolve(new Response(xhr.responseText))
    xhr.onerror = () => reject(new TypeError('Network Error'))
    xhr.send()
  })
}
```

**AbortSignal 的关键属性**：

```javascript
const controller = new AbortController()
const signal = controller.signal

console.log(signal.aborted)  // false（初始未中止）

controller.abort()

console.log(signal.aborted)  // true（已中止）
console.log(signal.reason)   // undefined 或 AbortError
```

**AbortSignal 的静态方法**（实用工具）：

```javascript
// 1. AbortSignal.timeout() - 创建超时自动中止的信号
const signal = AbortSignal.timeout(5000)  // 5 秒后自动 abort
fetch('/api', { signal }).catch(err => {
  if (err.name === 'TimeoutError') console.log('超时')
})

// 2. AbortSignal.abort() - 创建已中止的信号
const signal = AbortSignal.abort()  // 立即中止
fetch('/api', { signal })  // 直接 reject

// 3. AbortSignal.any() - 组合多个信号（任一触发即中止）
const controller1 = new AbortController()
const controller2 = new AbortController()
const combined = AbortSignal.any([controller1.signal, controller2.signal])
fetch('/api', { signal: combined })
controller1.abort()  // 或 controller2.abort() 都会取消 fetch
```

## 二、AJAX 请求取消

### Q2.1【代码实现题】用 XMLHttpRequest 实现可取消的请求

**题目难度**：⭐⭐ 中级

**问题描述**：请用原生 XMLHttpRequest 实现一个 GET 请求，并支持在响应返回前取消请求。

**参考答案**：

```javascript
// 创建可取消的 AJAX 请求
function createCancellableRequest(url, onSuccess, onError) {
  // 1. 创建 XMLHttpRequest 实例
  const xhr = new XMLHttpRequest()
  
  // 2. 初始化请求
  xhr.open('GET', url, true)
  
  // 3. 监听响应
  xhr.onload = function () {
    if (xhr.status >= 200 && xhr.status < 300) {
      onSuccess(xhr.responseText)
    } else {
      onError(new Error(`HTTP ${xhr.status}`))
    }
  }
  
  // 4. 监听网络错误
  xhr.onerror = function () {
    onError(new Error('网络错误'))
  }
  
  // 5. 监听 abort 事件（取消后触发）
  xhr.onabort = function () {
    console.log('请求已取消')
  }
  
  // 6. 发送请求
  xhr.send()
  
  // 7. 返回取消函数
  return function cancel() {
    if (xhr.readyState !== XMLHttpRequest.DONE) {
      xhr.abort()  // 调用 abort 取消请求
    }
  }
}

// 使用示例
const cancel = createCancellableRequest(
  '/api/users',
  (data) => console.log('成功:', data),
  (err) => console.error('失败:', err)
)

// 2 秒后取消请求（若未返回）
setTimeout(() => {
  cancel()
}, 2000)
```

**关键点**：
- `xhr.abort()` 是取消的核心方法
- 取消后触发 `onabort` 事件，而非 `onerror`
- `xhr.readyState` 变为 0（UNSENT）状态需注意
- 必须在 `readyState !== DONE` 时才取消

### Q2.2 XMLHttpRequest 的 abort() 原理是什么？

**题目难度**：⭐⭐⭐ 高级

**问题描述**：请深入分析 XMLHttpRequest.abort() 的底层原理及取消后的状态变化。

**参考答案**：

**abort() 的底层行为**：

```
调用 xhr.abort()
       ↓
┌─────────────────────────────────────┐
│  浏览器网络层行为                    │
│  1. 终止当前 HTTP 请求               │
│     - 若请求未发出：取消发送          │
│     - 若请求已发出：关闭 TCP 连接     │
│     - 服务器可能仍在处理（请求已发）  │
│  2. 设置 readyState = 0 (UNSENT)    │
│  3. 触发 onabort 事件                │
│  4. 触发readystatechange 事件        │
│  5. 不触发 onload / onerror          │
└─────────────────────────────────────┘
```

**取消后的状态变化**：

```javascript
const xhr = new XMLHttpRequest()
xhr.open('GET', '/api')
xhr.send()

xhr.onreadystatechange = function () {
  console.log('readyState:', xhr.readyState)
  // 正常流程：1(OPENED) → 2(HEADERS_RECEIVED) → 3(LOADING) → 4(DONE)
  // abort 后：可能从任意状态跳回 0
}

xhr.onabort = function () {
  console.log('abort 事件触发')
  console.log('readyState:', xhr.readyState)  // 0
  console.log('status:', xhr.status)          // 0
  console.log('responseText:', xhr.responseText)  // ''
}

xhr.abort()
// 输出：abort 事件触发
// 输出：readyState: 0, status: 0, responseText: ''
```

**abort() 的事件触发顺序**：

```
xhr.abort() 调用
       ↓
readystatechange 事件（readyState=0）
       ↓
abort 事件
       ↓
（结束，不触发 load / error / loadend）
```

**重要注意事项**：

1. **服务器侧请求不会真正取消**：
   ```
   浏览器 abort → 关闭连接 → 服务器仍可能继续处理
   服务器处理完成后发现连接已断 → 丢弃响应
   ```
   即 abort 只取消"等待响应"，不能阻止服务器执行。

2. **abort 后不能复用 xhr**：
   ```javascript
   xhr.abort()
   xhr.send()  // ❌ 报错，需重新 new XMLHttpRequest()
   ```

3. **abort 在同步请求中的行为**：
   ```javascript
   xhr.open('GET', '/api', false)  // 同步
   xhr.send()
   xhr.abort()  // 同步请求主线程阻塞，abort 无意义
   ```

### Q2.3【代码实现题】封装一个支持取消的 AJAX 工具函数

**题目难度**：⭐⭐⭐ 高级

**问题描述**：请封装一个 Promise 化的 AJAX 工具函数，支持取消请求与超时控制。

**参考答案**：

```javascript
/**
 * Promise 化的可取消 AJAX 请求
 * @param {Object} options 请求配置
 * @param {string} options.url 请求地址
 * @param {string} options.method 请求方法
 * @param {Object} options.data 请求数据
 * @param {Object} options.headers 请求头
 * @param {number} options.timeout 超时时间（ms）
 * @returns {Object} { promise, cancel }
 */
function ajax({ url, method = 'GET', data = null, headers = {}, timeout = 0 }) {
  let xhr
  let timer
  
  const promise = new Promise((resolve, reject) => {
    xhr = new XMLHttpRequest()
    xhr.open(method, url, true)
    
    // 设置请求头
    Object.keys(headers).forEach(key => {
      xhr.setRequestHeader(key, headers[key])
    })
    
    // 响应处理
    xhr.onload = function () {
      clearTimeout(timer)
      if (xhr.status >= 200 && xhr.status < 300) {
        try {
          const result = JSON.parse(xhr.responseText)
          resolve(result)
        } catch (e) {
          resolve(xhr.responseText)
        }
      } else {
        reject(new Error(`HTTP ${xhr.status}: ${xhr.statusText}`))
      }
    }
    
    // 网络错误
    xhr.onerror = function () {
      clearTimeout(timer)
      reject(new Error('网络错误'))
    }
    
    // 超时处理
    if (timeout > 0) {
      timer = setTimeout(() => {
        xhr.abort()
        reject(new Error(`请求超时（${timeout}ms）`))
      }, timeout)
    }
    
    // 发送请求
    const body = data ? JSON.stringify(data) : null
    if (body) {
      xhr.setRequestHeader('Content-Type', 'application/json')
    }
    xhr.send(body)
  })
  
  // 取消函数
  function cancel() {
    if (xhr && xhr.readyState !== XMLHttpRequest.DONE) {
      clearTimeout(timer)
      xhr.abort()
    }
  }
  
  return { promise, cancel }
}

// 使用示例
const { promise, cancel } = ajax({
  url: '/api/users',
  method: 'GET',
  timeout: 5000
})

promise
  .then(data => console.log('成功:', data))
  .catch(err => console.error('失败:', err.message))

// 主动取消
// cancel()

// 5 秒超时自动取消
```

**进阶：支持 AbortSignal（统一接口）**：

```javascript
function ajaxWithSignal({ url, method = 'GET', signal, ...options }) {
  return new Promise((resolve, reject) => {
    // 信号已中止，直接拒绝
    if (signal?.aborted) {
      reject(new DOMException('Aborted', 'AbortError'))
      return
    }
    
    const xhr = new XMLHttpRequest()
    xhr.open(method, url, true)
    
    xhr.onload = () => {
      if (xhr.status >= 200 && xhr.status < 300) {
        resolve(JSON.parse(xhr.responseText))
      } else {
        reject(new Error(`HTTP ${xhr.status}`))
      }
    }
    xhr.onerror = () => reject(new Error('网络错误'))
    xhr.send()
    
    // 监听信号
    if (signal) {
      signal.addEventListener('abort', () => {
        xhr.abort()
        reject(new DOMException('Aborted', 'AbortError'))
      })
    }
  })
}

// 使用：与 fetch 接口统一
const controller = new AbortController()
ajaxWithSignal({ url: '/api', signal: controller.signal })
controller.abort()
```

## 三、Fetch 请求取消

### Q3.1【代码实现题】用 AbortController 取消 Fetch 请求

**题目难度**：⭐⭐ 中级

```
│  3. reject Promise                  │
│  4. 错误对象：DOMException           │
│     - name: 'AbortError'            │
│     - message: 'The user aborted... │
└─────────────────────────────────────┘

.catch(err => {
```

**区分取消错误与其他错误**：

```javascript
async function safeFetch(url, signal) {
  try {
    const res = await fetch(url, { signal })
    if (!res.ok) {
      throw new Error(`HTTP ${res.status}: ${res.statusText}`)
    }
    return await res.json()
  } catch (err) {
    // ① 取消错误
    if (err.name === 'AbortError') {
      console.log('请求被取消')
      return null  // 返回 null 表示取消
    }
    
    // ② 超时错误（AbortSignal.timeout 触发）
    if (err.name === 'TimeoutError') {
      console.log('请求超时')
      throw new Error('请求超时，请重试')
    }
    
    // ③ 网络错误（断网、CORS、DNS 失败等）
    if (err instanceof TypeError) {
      console.log('网络错误:', err.message)
      throw new Error('网络连接失败，请检查网络')
    }
    
    // ④ HTTP 错误（4xx、5xx）
    if (err.message.startsWith('HTTP')) {
      console.log('HTTP 错误:', err.message)
      throw err
    }
    
    // ⑤ 其他错误
    throw err
  }
}

// 错误类型对照表：
// ┌──────────────┬──────────────────┬─────────────────┐
// │  错误类型     │  err.name        │  典型场景        │
// ├──────────────┼──────────────────┼─────────────────┤
// │  取消错误     │  AbortError      │  abort() 调用    │
// │  超时错误     │  TimeoutError    │  超时自动取消    │
// │  网络错误     │  TypeError       │  断网、CORS      │
// │  HTTP 错误    │  Error           │  4xx、5xx        │
// └──────────────┴──────────────────┴─────────────────┘
```

**封装统一的错误判断工具**：

```javascript
const ErrorType = {
  ABORT: 'ABORT',
  TIMEOUT: 'TIMEOUT',
  NETWORK: 'NETWORK',
  HTTP: 'HTTP',
  UNKNOWN: 'UNKNOWN'

function classifyError(err) {
  if (err.name === 'AbortError') return ErrorType.ABORT
  if (err.name === 'TimeoutError') return ErrorType.TIMEOUT
  if (err instanceof TypeError) return ErrorType.NETWORK
  if (err.message?.startsWith('HTTP')) return ErrorType.HTTP
  return ErrorType.UNKNOWN
}

// 使用
try {

      break

      break

}
```

### Q3.3【代码实现题】为 Fetch 封装支持超时自动取消的函数

**题目难度**：⭐⭐⭐ 高级

**问题描述**：请封装一个 fetchWithTimeout 函数，支持超时自动取消请求。

**参考答案**：

**方案 1：手动实现超时取消**：

```javascript
/**
 * 支持超时的 fetch
 * @param {string} url 请求地址
 * @param {Object} options fetch 配置
 * @param {number} timeout 超时时间（ms）
 */
function fetchWithTimeout(url, options = {}, timeout = 5000) {
  const controller = new AbortController()
  
  // 若外部已传入 signal，需合并
  const externalSignal = options.signal
  if (externalSignal) {
    if (externalSignal.aborted) {
      controller.abort()
    } else {
      externalSignal.addEventListener('abort', () => controller.abort())
    }
  }
  
  // 超时自动取消
  const timer = setTimeout(() => {
    controller.abort()
  }, timeout)
  
  return fetch(url, { ...options, signal: controller.signal })
    .finally(() => {
      clearTimeout(timer)  // 请求完成清除定时器
    })
    .catch(err => {
      if (err.name === 'AbortError' && !externalSignal?.aborted) {
        // 超时导致的取消
        throw new DOMException(`请求超时（${timeout}ms）`, 'TimeoutError')
      }
      throw err
    })
}

// 使用
fetchWithTimeout('/api/users', {}, 3000)
  .then(res => res.json())
  .then(data => console.log(data))
  .catch(err => {
    if (err.name === 'TimeoutError') console.log('超时了')
  })
```

**方案 2：用 AbortSignal.timeout()（现代浏览器）**：

### Q3.4【综合应用题】实现请求竞态控制（race condition）

**题目难度**：⭐⭐⭐⭐ 资深

**问题描述**：在搜索场景中，用户连续输入会触发多次请求，请实现一个机制确保只处理最后一次请求的结果。

**参考答案**：

**方案 1：每次取消上一次请求**：

```javascript
class SearchService {
  constructor() {
    this.controller = null
  }
  
  async search(keyword) {
    // 取消上一次请求
    if (this.controller) {
      this.controller.abort()
    }
    
    this.controller = new AbortController()
    const signal = this.controller.signal
    
    try {
      const res = await fetch(`/api/search?q=${keyword}`, { signal })
      const data = await res.json()
      return data
    } catch (err) {
      if (err.name === 'AbortError') {
        return null  // 被取消，返回 null
      }
      throw err
    }
  }
}

const searchService = new SearchService()

// 防抖包装
function debounce(fn, delay) {
  let timer
  return function (...args) {
    clearTimeout(timer)
    timer = setTimeout(() => fn.apply(this, args), delay)
  }
}

const debouncedSearch = debounce(async (keyword) => {
  const result = await searchService.search(keyword)
  if (result) renderResults(result)  // 只渲染未被取消的结果
}, 300)

input.addEventListener('input', e => debouncedSearch(e.target.value))
```

**方案 2：用版本号控制（无需取消请求）**：

```javascript
class SearchService {
  constructor() {
    this.version = 0
  }
  
  async search(keyword) {
    const currentVersion = ++this.version
    
    const res = await fetch(`/api/search?q=${keyword}`)
    const data = await res.json()
    
    // 版本号不匹配，说明有新请求发出，丢弃本次结果
    if (currentVersion !== this.version) {
      return null
    }
    return data
  }
}
```

**方案 3：封装通用的竞态控制函数**：

```javascript
/**
 * 竞态控制：只处理最后一次调用的结果
 * @param {Function} fn 返回 Promise 的函数
 * @returns {Function} 包装后的函数
 */
function onlyResolvesLast(fn) {
  let latestVersion = 0
  
  return function (...args) {
    const version = ++latestVersion
    
    return fn.apply(this, args).then(result => {
      if (version !== latestVersion) {
        // 不是最新请求，返回一个永不 resolve 的 Promise（丢弃结果）
        return new Promise(() => {})
      }
      return result
    })
  }
}

// 使用
const search = onlyResolvesLast(async (keyword) => {
  const res = await fetch(`/api/search?q=${keyword}`)
  return res.json()
})

// 连续调用，只有最后一次会 then
search('a').then(data => console.log('a 结果:', data))  // ❌ 不输出
search('ab').then(data => console.log('ab 结果:', data)) // ❌ 不输出
search('abc').then(data => console.log('abc 结果:', data)) // ✅ 输出
```

### Q4.1【代码实现题】axios 的两种取消方式及演进

**题目难度**：⭐⭐⭐ 高级

**问题描述**：请说明 axios 取消请求的两种方式及其演进历史，并给出代码示例。

**参考答案**：

axios 经历了两代取消 API：

**第一代：CancelToken（v0.22.0 前，已废弃）**：

```javascript
const axios = require('axios')
const { CancelToken } = axios

const source = CancelToken.source()

axios.get('/api/users', {
  cancelToken: source.token
}).catch(err => {
  if (axios.isCancel(err)) {

  } else {

  }
})
```

**第二代：AbortController（v0.22.0+ 推荐）**：

```javascript
const controller = new AbortController()

axios.get('/api/users', {
  signal: controller.signal
}).catch(err => {
  if (err.code === 'ERR_CANCELED') {
    console.log('请求被取消:', err.message)
  } else {
    console.error('请求失败:', err)
  }
})

// 取消请求
controller.abort()
```

**演进原因**：
- `CancelToken` 基于 Promise，无法同步中止
- `CancelToken` 是 axios 私有实现，不符合 Web 标准
- `AbortController` 是 DOM 标准，与 fetch 统一
- axios v1.0+ 全面拥抱 AbortController

### Q4.2 axios CancelToken 与 AbortController 的区别？

**题目难度**：⭐⭐⭐ 高级

**问题描述**：请对比 axios 的 CancelToken 与原生 AbortController 的差异。

**参考答案**：

| 维度 | CancelToken | AbortController |
| --- | --- | --- |
| **来源** | axios 私有实现 | DOM Web 标准 |
| **底层机制** | 基于 Promise resolve | 基于事件 + 标志位 |
| **同步/异步** | 异步（Promise 微任务） | 同步 |
| **复用性** | 仅限 axios | 通用（fetch/事件监听等） |
| **错误标识** | `axios.isCancel(err)` | `err.code === 'ERR_CANCELED'` |
| **状态** | v0.22.0 起废弃 | v0.22.0+ 推荐 |
| **批量取消** | 需多个 source | 一个 controller 控制多个 |

**底层机制对比**：

```javascript
// CancelToken 原理：基于 Promise
class CancelToken {
  constructor(executor) {
    let resolvePromise
    this.promise = new Promise(resolve => { resolvePromise = resolve })
    executor(function cancel(message) {
      resolvePromise({ message })  // resolve 触发取消
    })
  }
}

// axios 内部监听 promise
// token.promise.then(() => xhr.abort())
// 问题：Promise 是异步的，abort 在微任务中执行

// AbortController 原理：基于事件
class AbortController {
  constructor() {
    this.signal = { aborted: false, _listeners: [] }
  }
  abort() {
    this.signal.aborted = true
    this.signal._listeners.forEach(fn => fn())  // 同步执行
  }
}

// 同步取消，更及时
```

### Q5.3【综合应用题】实现可取消的并发请求池

**题目难度**：⭐⭐⭐⭐⭐ 专家

**问题描述**：请实现一个并发请求池，支持：1) 最大并发数控制；2) 整体取消；3) 单个任务取消。

**参考答案**：

```javascript
class CancellableTaskPool {
  constructor(maxConcurrency = 5) {
    this.maxConcurrency = maxConcurrency
    this.queue = []           // 待执行任务
    this.active = new Map()   // 执行中任务 { id: { controller, promise } }
    this.poolController = new AbortController()  // 整体控制器
  }
  
  /**
   * 添加任务
   * @param {Function} task (signal) => Promise
   * @param {string} id 任务 ID
   */
  add(task, id) {
    return new Promise((resolve, reject) => {
      this.queue.push({ task, id, resolve, reject })
      this.runNext()
    })
  }
  
  runNext() {
    while (this.active.size < this.maxConcurrency && this.queue.length > 0) {
      const { task, id, resolve, reject } = this.queue.shift()
      
      // 为每个任务创建独立控制器，并关联到整体信号
      const taskController = new AbortController()
      
      // 整体取消时，取消所有任务
      this.poolController.signal.addEventListener('abort', () => {
        taskController.abort()
      })
      
      this.active.set(id, { controller: taskController })
      
      task(taskController.signal)
        .then(result => {
          this.active.delete(id)
          resolve(result)
          this.runNext()
        })
        .catch(err => {
          this.active.delete(id)
          reject(err)
          this.runNext()
        })
    }
  }
  
  // 取消单个任务
  cancelTask(id) {
    const task = this.active.get(id)
    if (task) {
      task.controller.abort()
      this.active.delete(id)
    }
  }
  
  // 取消所有任务
  cancelAll() {
    this.poolController.abort()
    this.active.clear()
    this.queue = []
    // 重新创建整体控制器，供后续使用
    this.poolController = new AbortController()
  }
}

// 使用示例
const pool = new CancellableTaskPool(3)

const urls = ['url1', 'url2', 'url3', 'url4', 'url5']

urls.forEach(url => {
  pool.add(
    (signal) => fetch(url, { signal }).then(r => r.json()),
    url
  ).then(data => console.log(`${data.url} 完成`))
    .catch(err => {
      if (err.name === 'AbortError') {
        console.log('任务被取消')
      }
    })
})

// 取消单个
// pool.cancelTask('url3')

// 取消所有
// pool.cancelAll()
```

```javascript
  }, 300)
})
```

### IE 兼容方案

```javascript
// IE 不支持 AbortController，用 XHR 降级
function fetchWithCancel(url, options = {}) {
  if (typeof AbortController === 'undefined') {
    // 降级为 XHR
    return new Promise((resolve, reject) => {
      const xhr = new XMLHttpRequest()
      xhr.open('GET', url)
      xhr.onload = () => resolve({ json: () => Promise.resolve(JSON.parse(xhr.responseText)) })
      xhr.onerror = () => reject(new Error('网络错误'))
      xhr.send()
      
      // 返回取消函数（非标准）
      return { cancel: () => xhr.abort() }
    })
  }
  
  // 标准方案
  const controller = new AbortController()
  return {
    promise: fetch(url, { ...options, signal: controller.signal }),
    cancel: () => controller.abort()
  }
}
```

## 八、常见问题解答 FAQ

### Q1: fetch 取消后，服务器还会继续处理吗？

**A**: 会。fetch 取消只是关闭了浏览器端的连接，服务器仍可能继续处理请求。取消是"客户端不再等待响应"，而非"停止服务器处理"。

### Q2: abort() 后还能再次发送相同请求吗？

**A**: 可以。每个 AbortController 只能用一次，但可以创建新的 controller 发送新请求：

```javascript
const controller = new AbortController()
fetch('/api', { signal: controller.signal })
controller.abort()  // 这个 controller 已用完

// 新请求用新 controller
const controller2 = new AbortController()
fetch('/api', { signal: controller2.signal })
```

### Q3: AbortController 能取消 Promise 吗？

**A**: 不能直接取消 Promise。但可以配合 AbortSignal 让 Promise 响应取消：

```javascript
function cancellablePromise(signal) {
  return new Promise((resolve, reject) => {
    signal.addEventListener('abort', () => {
      reject(new DOMException('Aborted', 'AbortError'))
    })
    // 异步操作
    setTimeout(() => resolve('done'), 1000)
  })
}
```

### Q4: 一个 signal 能用于多个 fetch 吗？

**A**: 可以。一个 AbortSignal 可以传给多个 fetch，abort 时全部取消：

```javascript
const controller = new AbortController()
fetch('/api/a', { signal: controller.signal })
fetch('/api/b', { signal: controller.signal })
controller.abort()  // 两个都取消
```

### Q5: 如何在 axios 拦截器中统一处理取消？

**A**:

```javascript
axios.interceptors.response.use(
  response => response,
  error => {
    if (error.code === 'ERR_CANCELED') {
      // 取消错误，不提示用户
      return Promise.reject(error)
    }
    // 其他错误提示
    showToast(error.message)
    return Promise.reject(error)
  }
)
```

### Q6: 取消请求会释放网络连接吗？

**A**: 会。abort() 会关闭 TCP 连接，释放浏览器并发连接数配额（同域名通常 6 个）。

### Q7: 如何取消所有正在进行的请求（如用户登出）？

**A**:

```javascript
// 全局控制器
const globalController = new AbortController()

// 所有请求复用全局信号
function request(url) {
  return fetch(url, { signal: globalController.signal })
}

// 用户登出时取消所有
function logout() {
  globalController.abort()
  // 重新创建，供后续登录使用
  globalController = new AbortController()
}
```

### 错误判断速查

| 场景 | 判断方式 |
| --- | --- |
| Fetch 取消 | `err.name === 'AbortError'` |
| Fetch 超时 | `err.name === 'TimeoutError'` |
| Fetch 网络错误 | `err instanceof TypeError` |
| axios 取消 | `err.code === 'ERR_CANCELED'` 或 `axios.isCancel(err)` |
| XHR 取消 | `xhr.onabort` 事件 |

### 最佳实践速查

1. **搜索场景**：防抖 + AbortController 取消旧请求
2. **路由切换**：页面级 AbortController 批量取消
3. **组件卸载**：cleanup 函数调用 abort
4. **文件上传**：暴露 cancel 方法给用户
5. **超时控制**：`AbortSignal.timeout(ms)` 或手动 setTimeout
6. **错误处理**：区分 AbortError，不提示用户

# JavaScript 执行上下文面试题

## 一、核心概念解析

### 1. 什么是执行上下文？

执行上下文（Execution Context）是 JavaScript 引擎执行代码时的**运行环境**。JavaScript 代码运行在三种执行上下文中：

| 类型 | 说明 | 创建时机 |
|------|------|---------|
| **全局执行上下文** | 代码首次加载时创建，全局对象 `window`/`global` | 程序启动 |
| **函数执行上下文** | 每次调用函数时创建 | 函数调用时 |
| **Eval 执行上下文** | `eval()` 函数执行时创建 | eval 调用时 |

### 2. 执行上下文的生命周期

```
创建阶段 (Creation Phase) ──→ 执行阶段 (Execution Phase) ──→ 销毁阶段
```

### 3. 创建阶段的三件事

```
执行上下文 = {
  this: 当前 this 指向,
  VariableEnvironment: 变量环境（var 声明、函数声明）,
  LexicalEnvironment: 词法环境（let、const、函数参数）
}
```

#### 变量环境 vs 词法环境

| 特性 | 变量环境（VariableEnvironment） | 词法环境（LexicalEnvironment） |
|------|-------------------------------|------------------------------|
| 存储 | `var` 声明、函数声明 | `let`、`const`、函数参数 |
| 提升 | 变量提升为 `undefined`，函数声明整体提升 | 不存在提升（暂时性死区） |
| 作用域 | 函数作用域 | 块级作用域 |

### 4. 执行上下文栈（Call Stack）

```
                    ┌──────────────────────┐
                    │   全局执行上下文      │
                    └──────────────────────┘
                              │
              ┌───────────────┼───────────────┐
              │ 函数调用       │ 函数调用       │
              ▼               ▼               ▼
    ┌──────────────────┐  ┌──────────────────┐
    │ funcA 执行上下文  │  │ funcB 执行上下文  │
    ├──────────────────┤  ├──────────────────┤
    │ 全局执行上下文    │  │ funcA 执行上下文  │
    └──────────────────┘  ├──────────────────┤
                          │ 全局执行上下文    │
                          └──────────────────┘
```

### 5. 变量提升（Hoisting）

```javascript
console.log(a); // undefined（变量提升，但未赋值）
var a = 1;

foo(); // 'foo'（函数声明整体提升）
function foo() {
  console.log('foo');
}

bar(); // TypeError: bar is not a function（变量提升，但赋值未提升）
var bar = function () {
  console.log('bar');
};
```

### 6. 暂时性死区（TDZ）

```javascript
console.log(x); // ReferenceError: Cannot access 'x' before initialization
let x = 1;

// 块级作用域中的 TDZ
{
  console.log(y); // ReferenceError
  let y = 2;
}
```

## 二、面试题

### 题目 1：变量提升与函数提升优先级（基础）

#### 题干

```javascript
console.log(foo);

var foo = function () {
  console.log('expression');
};

function foo() {
  console.log('declaration');
}

console.log(foo);
```

#### 解题思路

**函数声明提升优先级高于变量声明提升**（不会被 `var` 声明覆盖，但会被赋值覆盖）：

1. 创建阶段：`function foo(){}` 声明提升 → `var foo` 声明（已被函数声明覆盖，忽略）
2. 执行阶段：第一个 `console.log(foo)` 输出函数本身
3. `foo = function(){...}` 赋值覆盖了函数声明
4. 第二个 `console.log(foo)` 输出函数表达式

#### 正确代码实现

```javascript
// 输出：
// [Function: foo]（函数声明）
// [Function: foo]（函数表达式赋值后）

// 实际执行过程模拟：
// 创建阶段：
//   function foo() { console.log('declaration'); }  // 函数声明提升
//   var foo;  // 变量声明提升，但被函数声明覆盖，忽略
//
// 执行阶段：
//   console.log(foo);  // → 函数声明
//   foo = function() { console.log('expression'); };  // 赋值覆盖
//   console.log(foo);  // → 函数表达式
```

#### 知识点拓展

- 函数声明提升优先级高于 `var` 变量声明（不会被 `var` 覆盖）
- 但函数声明可以被**赋值操作**覆盖
- 尽量使用 `let/const` 替代 `var`，避免变量提升带来的混淆

### 题目 2：`this` 指向的四种绑定规则（基础）

#### 题干

```javascript
const obj = {
  name: 'obj',
  say: function () {
    console.log(this.name);
  },
  sayArrow: () => {
    console.log(this.name);
  }
};

const obj2 = { name: 'obj2' };

obj.say();           // 1. ?
obj.sayArrow();      // 2. ?
obj.say.call(obj2);  // 3. ?
const fn = obj.say;
fn();                // 4. ?
```

#### 解题思路

`this` 指向的四种绑定规则（优先级从低到高）：

1. **默认绑定**：独立函数调用，`this` 指向全局对象（严格模式为 `undefined`）
2. **隐式绑定**：调用点有上下文对象，`this` 指向该对象
3. **显式绑定**：`call/apply/bind` 指定 `this`
4. **new 绑定**：`new` 创建新对象，`this` 指向该对象

**箭头函数没有自己的 `this`**，它从定义时的外层作用域捕获 `this`。

#### 正确代码实现

```javascript
// 1. obj.say() → 'obj'（隐式绑定，this 指向 obj）
// 2. obj.sayArrow() → undefined（严格模式）或 'window'（非严格模式）
//    箭头函数的 this 指向定义时外层作用域的 this，即全局对象
// 3. obj.say.call(obj2) → 'obj2'（显式绑定，call 指定 this 为 obj2）
// 4. fn() → undefined（非严格模式下为 'window'）
//    隐式绑定丢失，this 指向全局对象
```

#### 知识点拓展

- **隐式绑定丢失**：将方法赋值给变量时，会丢失 `this` 绑定
- 箭头函数不能通过 `call/apply/bind` 改变 `this`
- `new` 绑定优先级最高，其次是显式绑定，然后是隐式绑定

### 题目 3：闭包与执行上下文（进阶）

#### 题干

```javascript
function createFunctions() {
  const result = [];
  for (var i = 0; i < 3; i++) {
    result.push(function () {
      console.log(i);
    });
  }
  return result;
}

const fns = createFunctions();
fns[0](); // ?
fns[1](); // ?
fns[2](); // ?
```

请解释输出结果，并说明如何修复。

#### 解题思路

1. `var i` 声明的变量存在于 `createFunctions` 函数的**变量环境**中
2. 三个函数闭包捕获的是同一个变量 `i` 的引用
3. 当函数执行时，`i` 已经是循环结束后的值 `3`
4. 修复方案：使用 `let` 创建块级作用域，或使用 IIFE 创建独立作用域

#### 正确代码实现

```javascript
// 输出：3, 3, 3
// 原因：三个闭包共享同一个变量环境的 i，循环结束后 i = 3

// 修复方案一：使用 let（块级作用域）
function createFunctions() {
  const result = [];
  for (let i = 0; i < 3; i++) {
    // 每次迭代创建独立的词法环境
    result.push(function () {
      console.log(i);
    });
  }
  return result;
}
// 输出：0, 1, 2

// 修复方案二：使用 IIFE
function createFunctions() {
  const result = [];
  for (var i = 0; i < 3; i++) {
    (function (j) {
      result.push(function () {
        console.log(j);
      });
    })(i);
  }
  return result;
}
// 输出：0, 1, 2
```

#### 知识点拓展

- `let` 在 `for` 循环中，每次迭代都会**创建新的词法环境**
- `var` 在整个函数作用域中共享同一个变量
- 闭包捕获的是**变量的引用**，而非变量当前的值

### 题目 4：作用域链与变量查找（进阶）

#### 题干

```javascript
var x = 10;

function foo() {
  console.log(x); // ?
  var x = 20;
  console.log(x); // ?

  function bar() {
    console.log(x); // ?
    var x = 30;
    console.log(x); // ?
  }

  bar();
}

foo();
```

#### 解题思路

每个函数都有自己的变量环境，变量查找从**当前作用域**开始，逐级向上查找。

**关键**：`var` 声明的变量会提升到当前函数作用域的顶部，但赋值不提升。

#### 正确代码实现

```javascript
// 输出：
// undefined（foo 作用域内的 x 提升，但未赋值）
// 20（x 赋值为 20）
// undefined（bar 作用域内的 x 提升，但未赋值）
// 30（x 赋值为 30）

// 实际执行过程模拟：
// function foo() {
//   var x;  // 变量提升，undefined
//   function bar() {
//     var x;  // 变量提升，undefined
//     console.log(x); // undefined（使用 bar 作用域内的 x）
//     x = 30;
//     console.log(x); // 30
//   }
//   console.log(x); // undefined（使用 foo 作用域内的 x）
//   x = 20;
//   console.log(x); // 20
//   bar();
// }
```

#### 知识点拓展

- 作用域链查找：**当前作用域 → 父级作用域 → ... → 全局作用域**
- `var` 的作用域是**函数作用域**，不是块级作用域
- 变量提升发生在当前作用域顶部，而非块级顶部

### 题目 5：严格模式下的 `this`（进阶）

#### 题干

```javascript
'use strict';

const obj = {
  name: 'obj',
  say: function () {
    console.log(this.name);
  }
};

const fn = obj.say;
fn(); // ?

function foo() {
  console.log(this);
}
foo(); // ?

setTimeout(function () {
  console.log(this); // ?
}, 0);
```

#### 解题思路

严格模式下，默认绑定的 `this` 从全局对象变为 `undefined`。

#### 正确代码实现

```javascript
// 输出：
// TypeError: Cannot read properties of undefined（读取 this.name 时 this 为 undefined）
// undefined
// window（setTimeout 回调中，this 仍然指向全局对象）

// 解释：
// 1. fn() 是独立函数调用，严格模式下 this 为 undefined
// 2. foo() 独立调用，严格模式下 this 为 undefined
// 3. setTimeout 的回调中，this 是 window（由 setTimeout 内部绑定）

// 注意：setTimeout 的回调中，即使严格模式，this 仍然是 window
// 因为 setTimeout 在内部使用 apply 将 this 指向了全局对象
```

#### 知识点拓展

- 严格模式下默认绑定规则改变：`this` 为 `undefined` 而非全局对象
- 箭头函数不受严格模式影响（始终使用外层作用域的 `this`）
- `setTimeout` 回调中 `this` 为 `window`，与严格模式无关

### 题目 6：`new` 绑定与返回值（进阶）

#### 题干

```javascript
function Person(name) {
  this.name = name;
  this.age = 25;
  return { name: 'override' };
}

function Animal(name) {
  this.name = name;
  this.age = 3;
  return 123;
}

const p = new Person('Tom');
const a = new Animal('Dog');

console.log(p);
console.log(a);
```

#### 解题思路

`new` 绑定规则：
- 如果构造函数返回一个**对象**，则 `new` 表达式返回该对象
- 如果构造函数返回**基本类型**，则忽略该返回值，返回 `new` 创建的新对象

#### 正确代码实现

```javascript
// 输出：
// { name: 'override' }（Person 返回了对象，覆盖了 this）
// Animal { name: 'Dog', age: 3 }（Animal 返回了基本类型，被忽略）

// 解释：
// Person 显式返回了一个对象 { name: 'override' }，所以 new 返回该对象
// Animal 返回了 123（基本类型），被忽略，返回 new 创建的对象
```

#### 知识点拓展

- 构造函数如果显式返回对象，则 `new` 的结果是该对象
- 构造函数如果返回基本类型，则被忽略，返回 `this`
- 这就是为什么构造函数通常不显式 return 的原因

### 题目 7：eval 与执行上下文（高阶）

#### 题干

```javascript
var x = 'global';

function foo() {
  var x = 'local';
  eval('console.log(x); var x = "eval-local"; console.log(x);');
  console.log(x);
}

foo();
```

#### 解题思路

`eval` 在非严格模式下会**修改调用者的词法环境**，影响外层作用域。

#### 正确代码实现

```javascript
// 输出：
// undefined（eval 中的 var x 提升到 foo 作用域，覆盖了 'local'）
// eval-local
// eval-local（eval 修改了 foo 作用域中的 x）

// 解释：
// 1. eval 中的 var x 提升到 foo 作用域，覆盖了 x = 'local' 的声明
// 2. 第一个 console.log(x) 时，x 提升但未赋值，为 undefined
// 3. x = 'eval-local' 赋值
// 4. 第二个 console.log(x) 输出 'eval-local'
// 5. foo 最后的 console.log(x) 输出 'eval-local'

// 严格模式下 eval 不会影响外层作用域
'use strict';
function bar() {
  var x = 'local';
  eval('var x = "eval-local";');
  console.log(x); // 'local'（eval 中的 x 在独立作用域中）
}
```

#### 知识点拓展

- 非严格模式下 `eval` 可以修改调用者的作用域
- 严格模式下 `eval` 有自己的作用域，不会影响外层
- 实际开发中**避免使用 `eval`**，因为它会：
  - 导致性能问题（引擎无法优化）
  - 带来安全风险（代码注入）
  - 使代码难以调试

## 三、易错点与最佳实践

### 常见易错点

| 易错点 | 说明 | 正确做法 |
|--------|------|---------|
| 混淆变量提升与函数提升 | 认为 `var` 和函数声明提升优先级相同 | 函数声明优先级高于 `var` 声明 |
| 忽略暂时性死区 | 在 `let`/`const` 声明前访问变量 | 始终在声明后使用变量 |
| 误解箭头函数 `this` | 认为箭头函数有动态 `this` | 箭头函数 `this` 在定义时确定 |
| 回调函数中 `this` 丢失 | 将方法作为回调传递时 `this` 指向错误 | 使用箭头函数或 `.bind()` |
| 忽略严格模式的影响 | 认为 `this` 始终指向全局对象 | 严格模式下默认绑定为 `undefined` |

### 最佳实践

```javascript
// 1. 使用 let/const 替代 var
// ✅ 推荐
const name = 'Tom';
let count = 0;

// ❌ 避免
var name = 'Tom';
var count = 0;

// 2. 使用箭头函数保持 this 指向
class Timer {
  constructor() {
    this.seconds = 0;
  }

  start() {
    // ✅ 箭头函数捕获外层 this
    setInterval(() => {
      this.seconds++;
    }, 1000);
  }
}

// 3. 使用 bind 固定 this
const module = {
  x: 42,
  getX: function () {
    return this.x;
  }
};

const unboundGetX = module.getX;
console.log(unboundGetX()); // undefined

const boundGetX = module.getX.bind(module);
console.log(boundGetX()); // 42

// 4. 避免使用 eval
// ❌ 避免
const code = 'console.log("hello")';
eval(code);

// ✅ 替代方案
new Function('console.log("hello")')();

// 5. 使用严格模式
'use strict';
// 在文件或函数顶部使用严格模式，避免隐式全局变量
```

### 执行上下文工作流程

```
代码执行前：
  ┌────────────────────────────────────────────┐
  │ 创建全局执行上下文                           │
  │  ├─ 创建全局对象（window/global）            │
  │  ├─ 创建 this 并指向全局对象                  │
  │  ├─ 扫描函数声明并提升                        │
  │  └─ 扫描 var 声明并提升（赋值为 undefined）    │
  └────────────────────────────────────────────┘

函数调用时：
  ┌────────────────────────────────────────────┐
  │ 创建函数执行上下文                           │
  │  ├─ 创建 arguments 对象                      │
  │  ├─ 确定 this 指向                          │
  │  ├─ 创建函数作用域链                         │
  │  ├─ 扫描函数声明并提升                        │
  │  └─ 扫描 var 声明并提升（赋值为 undefined）    │
  └────────────────────────────────────────────┘

执行阶段：
  ┌────────────────────────────────────────────┐
  │ 逐行执行代码                                 │
  │  ├─ 变量赋值                                │
  │  ├─ 函数调用                                │
  │  └─ 执行完毕后弹出上下文栈                     │
  └────────────────────────────────────────────┘
```

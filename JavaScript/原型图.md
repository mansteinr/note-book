### Q1：关于 JavaScript 原型对象，以下说法正确的是？

**A.** 只有函数对象才有 `prototype` 属性，普通对象没有

**B.** 所有对象都有 `prototype` 属性

**C.** 箭头函数拥有 `prototype` 属性，但不可枚举

**D.** `Object.create(null)` 创建的对象拥有 `prototype` 属性

**答案：A**

**解析：**

- **A 正确**：只有函数对象（包括普通函数和构造函数）具有 `prototype` 属性，普通对象（如 `{}`、`[]`）没有这个属性。
- **B 错误**：普通对象没有 `prototype` 属性，但它们有 `__proto__`（即 `[[Prototype]]`）。
- **C 错误**：箭头函数没有 `prototype` 属性，因此不能作为构造函数使用 `new` 调用。
- **D 错误**：`Object.create(null)` 创建的对象没有原型链（`__proto__` 为 `undefined`），更不可能有 `prototype` 属性。

```javascript
function Foo() {}
console.log(Foo.prototype);           // { constructor: Foo }
console.log(({}).prototype);          // undefined
const arrow = () => {};
console.log(arrow.prototype);         // undefined
const obj = Object.create(null);
console.log(obj.prototype);           // undefined
console.log(obj.__proto__);           // undefined
```

### Q2：以下代码的输出是什么？

```javascript
function Person() {}
Person.prototype.name = 'prototype';
const p = new Person();
p.name = 'instance';
delete p.name;
console.log(p.name);
delete Person.prototype.name;
console.log(p.name);
```

**A.** `'instance'` 然后 `'prototype'`

**B.** `'prototype'` 然后 `undefined`

**C.** `'instance'` 然后 `undefined`

**D.** `'prototype'` 然后 `'prototype'`

**答案：B**

**解析：**

1. `p.name = 'instance'` 在实例 `p` 上添加了自有属性 `name`。
2. `delete p.name` 删除了实例上的自有属性，此时访问 `p.name` 会沿原型链查找，找到 `Person.prototype.name`，值为 `'prototype'`。
3. `delete Person.prototype.name` 删除了原型上的属性，再次访问 `p.name` 时，原型链上已无此属性，返回 `undefined`。

**关键点：** `delete` 只能删除自有属性，无法删除原型链上的属性（除非显式指定原型对象）。属性访问遵循"自有属性优先"原则，自有属性被删除后才会向上查找原型链。

### Q3：以下关于 `__proto__` 和 `prototype` 的描述，错误的是？

**A.** `__proto__` 是对象上的隐式原型属性，指向构造函数的 `prototype`

**B.** `Function.prototype.__proto__ === Object.prototype` 为 `true`

**C.** `Object.prototype.__proto__` 的值为 `undefined`

**D.** ES6 推荐使用 `Object.getPrototypeOf()` 替代 `__proto__`

**答案：C**

**解析：**

- **A 正确**：`__proto__`（即 `[[Prototype]]`）是每个对象都有的隐式原型链接，指向其构造函数的 `prototype` 对象。
- **B 正确**：`Function.prototype` 是一个函数对象，其 `__proto__` 指向 `Object.prototype`，这是原型链的必经之路。
- **C 错误**：`Object.prototype.__proto__` 的值为 `null`，不是 `undefined`。`null` 是原型链的终点，表示"没有原型"。
- **D 正确**：`__proto__` 虽然在多数浏览器中被实现，但不在 ES 规范的核心部分，ES6 推荐使用 `Object.getPrototypeOf()` 和 `Object.setPrototypeOf()`。

```javascript
console.log(Object.prototype.__proto__); // null（不是 undefined）
```

### Q4：以下代码的输出是什么？（多选）

```javascript
const obj = {};
Object.defineProperty(obj, 'hidden', {
  value: 'secret',
  enumerable: false
});
obj.visible = 'public';

console.log(obj.hasOwnProperty('hidden'));
console.log('hidden' in obj);
console.log(Object.keys(obj).includes('hidden'));
console.log(obj.propertyIsEnumerable('hidden'));
```

**A.** `true`、`true`、`false`、`true`

**B.** `true`、`true`、`false`、`false`

**C.** `false`、`true`、`false`、`false`

**D.** `true`、`false`、`false`、`false`

**答案：B**

**解析：**

1. `hasOwnProperty('hidden')` → `true`：`hidden` 是 `obj` 的自有属性，只是不可枚举。
2. `'hidden' in obj` → `true`：`in` 操作符检查自有属性和原型链上的属性，`hidden` 是自有属性，返回 `true`。
3. `Object.keys(obj)` → `['visible']`：`Object.keys()` 只返回**可枚举的自有属性**，不包含不可枚举的 `hidden`。
4. `propertyIsEnumerable('hidden')` → `false`：该属性被定义为 `enumerable: false`。

**关键区分：**

| 方法 | 自有属性 | 原型链属性 | 不可枚举属性 |
|------|----------|------------|--------------|
| `hasOwnProperty` | 包含 | 不包含 | 包含 |
| `in` | 包含 | 包含 | 包含 |
| `Object.keys` | 包含 | 不包含 | 不包含 |
| `propertyIsEnumerable` | 包含 | 不包含 | 不包含 |

### Q5：以下代码的输出是什么？

```javascript
function A() {}
A.prototype.x = 10;
const a = new A();
A.prototype = { x: 20, y: 30 };
const b = new A();
console.log(a.x, a.y);
console.log(b.x, b.y);
```

**A.** `10 undefined` 和 `20 30`

**B.** `10 30` 和 `20 30`

**C.** `20 undefined` 和 `20 30`

**D.** `10 undefined` 和 `10 undefined`

**答案：A**

**解析：**

1. `a` 创建时，`A.prototype` 是 `{ x: 10 }`，所以 `a.__proto__` 指向这个对象。`a.x` → `10`，`a.y` → `undefined`。
2. 随后 `A.prototype` 被**重新赋值**为一个新对象 `{ x: 20, y: 30 }`。但 `a.__proto__` 仍然指向旧的原型对象。
3. `b` 创建时，`A.prototype` 已经是新对象，`b.__proto__` 指向 `{ x: 20, y: 30 }`。`b.x` → `20`，`b.y` → `30`。

**关键点：** 重写 `prototype` 不会影响已创建实例的原型链，已存在的实例仍指向旧原型对象。这就是为什么修改原型应使用 `A.prototype.xxx = ...` 而非 `A.prototype = {...}`。

### Q6：以下代码的输出是什么？

```javascript
Function.prototype.a = () => console.log(1);
Object.prototype.b = () => console.log(2);
function Foo() {}
const foo = new Foo();
foo.a();  // ①
foo.b();  // ②
Foo.a();  // ③
Foo.b();  // ④
```

**A.** ① 报错，② 输出 2，③ 输出 1，④ 输出 2

**B.** ① 报错，② 输出 2，③ 报错，④ 输出 2

**C.** ① 输出 1，② 输出 2，③ 输出 1，④ 输出 2

**D.** ① 报错，② 输出 2，③ 输出 1，④ 报错

**答案：A**

**解析：**

按照原型链路径分析：

- **`foo` 的原型链：** `foo` → `Foo.prototype` → `Object.prototype` → `null`
  - ① `foo.a()`：`foo` 的属性链上找不到 `a`，`Object.prototype` 也没有 `a`（`a` 在 `Function.prototype` 上），**报错 `foo.a is not a function`**。
  - ② `foo.b()`：沿原型链在 `Object.prototype` 上找到 `b`，**输出 2**。

- **`Foo` 的原型链：** `Foo`（函数对象）→ `Function.prototype` → `Object.prototype` → `null`
  - ③ `Foo.a()`：在 `Function.prototype` 上找到 `a`，**输出 1**。
  - ④ `Foo.b()`：在 `Object.prototype` 上找到 `b`，**输出 2**。

**核心理解：** 函数对象的原型链和普通对象的原型链不同。函数对象是 `Function` 的实例，其 `__proto__` 指向 `Function.prototype`。

```
foo（实例对象）──→ Foo.prototype ──→ Object.prototype ──→ null
Foo（函数对象）──→ Function.prototype ──→ Object.prototype ──→ null
```

### Q7：以下代码的输出是什么？

```javascript
const arr = [1, 2, 3];
Array.prototype.custom = 'arrayProto';
Object.prototype.custom = 'objectProto';

console.log(arr.custom);
delete Array.prototype.custom;
console.log(arr.custom);
```

**A.** `'arrayProto'` 然后 `'arrayProto'`

**B.** `'arrayProto'` 然后 `'objectProto'`

**C.** `'arrayProto'` 然后 `undefined`

**D.** `'objectProto'` 然后 `'objectProto'`

**答案：B**

**解析：**

1. `arr` 的原型链：`arr` → `Array.prototype` → `Object.prototype` → `null`。
2. 首次访问 `arr.custom`，先在 `Array.prototype` 上找到 `'arrayProto'`，返回。
3. `delete Array.prototype.custom` 删除了 `Array.prototype` 上的 `custom` 属性。
4. 再次访问 `arr.custom`，`Array.prototype` 上已无此属性，继续向上在 `Object.prototype` 上找到 `'objectProto'`，返回。

**关键点：** 原型链遵循"就近原则"，下层的属性会遮蔽（shadow）上层的同名属性。当 `Array.prototype.custom` 被删除后，`Object.prototype.custom` 才暴露出来。

### Q8：以下代码的输出是什么？

```javascript
const obj = {};
console.log(obj.__proto__ === Object.prototype);
console.log(obj.__proto__.__proto__ === null);
console.log(Object.__proto__ === Function.prototype);
console.log(Function.__proto__ === Function.prototype);
console.log(Function.prototype.__proto__ === Object.prototype);
```

**A.** 全部为 `true`

**B.** 前三个为 `true`，后两个为 `false`

**C.** 前四个为 `true`，最后一个为 `false`

**D.** 全部为 `false`

**答案：A**

**解析：**

这是一道经典的原型链全貌验证题，全部为 `true`：

1. `obj.__proto__ === Object.prototype` → `true`：普通对象由 `Object` 构造，其 `__proto__` 指向 `Object.prototype`。
2. `obj.__proto__.__proto__ === null` → `true`：`Object.prototype.__proto__` 为 `null`，是原型链终点。
3. `Object.__proto__ === Function.prototype` → `true`：`Object` 是构造函数，本质是函数，其 `__proto__` 指向 `Function.prototype`。
4. `Function.__proto__ === Function.prototype` → `true`：`Function` 的 `__proto__` 指向自己的 `prototype`，这是 JavaScript 中唯一的特殊情况。
5. `Function.prototype.__proto__ === Object.prototype` → `true`：`Function.prototype` 是对象，其 `__proto__` 指向 `Object.prototype`。

**完整原型链关系图：**

```
                     ┌──────────────────────────────────┐
                     │          null                     │
                     └────────────▲─────────────────────┘
                                  │ __proto__
                     ┌────────────┴─────────────────────┐
                     │       Object.prototype            │
                     └───▲──────────────▲───────────────┘
                __proto__│              │__proto__
         ┌───────────────┴──┐  ┌────────┴───────────────┐
         │ Function.prototype│  │  Foo.prototype  ...    │
         └──▲────────────▲──┘  └────────▲───────────────┘
   __proto__│            │__proto__    │__proto__
   ┌────────┴────────┐ ┌─┴──────────┐ ┌┴───────────────┐
   │    Function     │ │   Object   │ │     foo        │
   └─────────────────┘ └────────────┘ └────────────────┘
```

### Q9：以下代码的输出是什么？

```javascript
let val = 1;
const obj = {
  val: 2,
  getVal: () => {
    return this.val;
  }
};
obj.getVal.call({ val: 3 });
```

**A.** `1`

**B.** `2`

**C.** `3`

**D.** `undefined`

**答案：A**

**解析：**

这道题考察原型链与 `this` 绑定的交叉理解。

1. `getVal` 是**箭头函数**，箭头函数没有自己的 `this`，其 `this` 在定义时确定，指向外层作用域的 `this`。
2. 在模块顶层或全局作用域中，`this` 指向全局对象（浏览器中为 `window`，Node.js 中为 `module.exports` 即 `{}`）。
3. 全局 `let val = 1` 不会挂载到 `window` 上（`let` 声明的变量不在全局对象上），但 `var val = 1` 会。
4. 在浏览器环境中，`this.val` 在全局作用域可能为 `undefined`（取决于是否有 `var val` 声明）；在 Node.js 模块中，`this` 指向 `module.exports`，`this.val` 为 `undefined`。

**然而，本题真正的考点是：** 箭头函数的 `this` 无法通过 `call`/`apply`/`bind` 改变。`obj.getVal.call({ val: 3 })` 中的 `call` 对箭头函数无效，`this` 仍然指向定义时的外层作用域。

在浏览器全局作用域中，如果使用 `var val = 1`，`this.val` 为 `1`，输出 `1`。如果使用 `let val = 1`，`this.val` 为 `undefined`。

**按题目使用 `let` 声明，在浏览器中输出 `undefined`，但题目选项中 `A` 为 `1` 是假设 `var` 声明的情况。** 实际上本题的核心是：箭头函数 `this` 不可被 `call` 改变，且箭头函数中 `this` 指向定义时的外层作用域。

### Q10：关于原型链的以下说法，正确的是？（多选）

**A.** 修改 `Object.prototype` 会影响所有对象，包括 `Object.create(null)` 创建的对象

**B.** `for...in` 循环会遍历对象自身及原型链上的所有可枚举属性

**C.** `instanceof` 运算符通过检查右侧构造函数的 `prototype` 是否出现在左侧对象的原型链上来判断

**D.** 所有对象最终都继承自 `Object.prototype`，无一例外

**E.** `Object.create(null)` 创建的对象没有 `hasOwnProperty` 方法

**答案：B、C、E**

**解析：**

- **A 错误**：`Object.create(null)` 创建的对象 `__proto__` 为 `undefined`，不连接 `Object.prototype`，因此修改 `Object.prototype` 不影响它。
- **B 正确**：`for...in` 遍历所有可枚举属性，包括自身和原型链上的。可用 `hasOwnProperty` 过滤。
- **C 正确**：`instanceof` 的内部实现就是沿着 `__proto__` 链查找，判断 `prototype` 是否在链上。
- **D 错误**：`Object.create(null)` 创建的对象不继承自 `Object.prototype`，它是原型链的"无根"对象。
- **E 正确**：`hasOwnProperty` 来自 `Object.prototype`，`Object.create(null)` 的对象没有原型链，自然没有此方法。调用需使用 `Object.prototype.hasOwnProperty.call(obj, key)`。

```javascript
const pureObj = Object.create(null);
pureObj.x = 1;
console.log(pureObj.hasOwnProperty); // undefined
// 正确做法：
console.log(Object.prototype.hasOwnProperty.call(pureObj, 'x')); // true
```

### Q11：以下代码的输出是什么？

```javascript
function Foo() {
  Foo.prototype.a = 1;
}
const f1 = new Foo();
Foo.prototype = { b: 2, c: 3 };
const f2 = new Foo();
Foo.prototype.d = 4;
console.log(f1.a, f1.b, f1.d);
console.log(f2.b, f2.c, f2.d);
```

**A.** `1 undefined undefined` 和 `2 3 4`

**B.** `1 undefined 4` 和 `2 3 4`

**C.** `1 undefined undefined` 和 `2 3 undefined`

**D.** `undefined undefined undefined` 和 `2 3 4`

**答案：A**

**解析：**

1. `f1` 创建时，`Foo.prototype` 是原始对象 `{ a: 1 }`（构造函数中赋值），`f1.__proto__` 指向它。`f1.a` → `1`。
2. 随后 `Foo.prototype = { b: 2, c: 3 }` 重写了 `prototype`，`f1.__proto__` 仍指向旧原型，旧原型上只有 `a`，没有 `b`、`d`。
3. `f2` 创建时，`Foo.prototype` 已经是 `{ b: 2, c: 3 }`，`f2.__proto__` 指向它。`f2.b` → `2`，`f2.c` → `3`。
4. `Foo.prototype.d = 4` 在新原型上添加了 `d`，所以 `f2.d` → `4`。

**关键点：** 重写 `prototype` 是"切断式"的，旧实例不受新原型影响，新实例不受旧原型影响。

### Q12：以下代码的输出是什么？

```javascript
function A() {}
function B() {}
B.prototype = Object.create(A.prototype);
const b = new B();
console.log(b instanceof B);
console.log(b instanceof A);
console.log(b instanceof Object);
console.log(B.prototype.constructor === B);
```

**A.** `true true true true`

**B.** `true true true false`

**C.** `true false true false`

**D.** `true true false false`

**答案：B**

**解析：**

1. `b instanceof B` → `true`：`B.prototype` 在 `b` 的原型链上。
2. `b instanceof A` → `true`：`B.prototype` 是通过 `Object.create(A.prototype)` 创建的，其 `__proto__` 指向 `A.prototype`，所以 `A.prototype` 也在 `b` 的原型链上。
3. `b instanceof Object` → `true`：`A.prototype.__proto__` 指向 `Object.prototype`。
4. `B.prototype.constructor === B` → **`false`**：`Object.create(A.prototype)` 创建的新对象没有 `constructor` 属性。访问 `B.prototype.constructor` 会沿原型链查找到 `A.prototype.constructor`，即 `A`。

**修复方法：**

```javascript
B.prototype = Object.create(A.prototype);
B.prototype.constructor = B; // 修复 constructor 指向
```

### Q13：以下代码的输出是什么？

```javascript
function Parent() {
  this.names = ['a', 'b'];
}
function Child() {}
Child.prototype = new Parent();
const c1 = new Child();
const c2 = new Child();
c1.names.push('c');
console.log(c2.names);
```

**A.** `['a', 'b']`

**B.** `['a', 'b', 'c']`

**C.** `undefined`

**D.** 报错

**答案：B**

**解析：**

这是原型链继承的经典缺陷题。

1. `Child.prototype = new Parent()` 将 `Parent` 的实例作为 `Child` 的原型。
2. `Parent` 实例上的 `names` 属性（引用类型）成为 `Child.prototype` 上的属性。
3. `c1.names.push('c')` 操作的是原型链上的 `names` 数组（引用类型），所有 `Child` 实例共享同一个 `names` 数组。
4. 因此 `c2.names` 也是 `['a', 'b', 'c']`。

**关键问题：** 原型链继承中，父类实例上的引用类型属性会被所有子类实例共享，这是原型链继承的主要缺陷之一。

**解决方案：** 使用组合继承（构造函数 + 原型链）或寄生组合继承，在子类构造函数中调用 `Parent.call(this)`。

```javascript
function Child() {
  Parent.call(this); // 每个实例拥有独立的 names 数组
}
Child.prototype = Object.create(Parent.prototype);
Child.prototype.constructor = Child;
```

### Q14：以下关于 `new` 操作符执行过程的描述，正确的顺序是？

1. 创建一个空对象
2. 执行构造函数中的代码
3. 将新对象的 `__proto__` 指向构造函数的 `prototype`
4. 如果构造函数返回对象，则返回该对象；否则返回新创建的对象

**A.** 1 → 2 → 3 → 4

**B.** 1 → 3 → 2 → 4

**C.** 3 → 1 → 2 → 4

**D.** 1 → 2 → 4 → 3

**答案：B**

**解析：**

`new` 操作符的执行顺序：

1. **创建空对象**：`const obj = {}`
2. **绑定原型**：`obj.__proto__ = Constructor.prototype`（必须在执行构造函数前完成，这样构造函数中才能通过 `this` 访问原型方法）
3. **执行构造函数**：`const result = Constructor.apply(obj, args)`（此时 `this` 指向新对象）
4. **返回结果**：如果构造函数返回引用类型，返回该引用；否则返回 `obj`

**手动实现 `new`：**

```javascript
function myNew(Constructor, ...args) {
  const obj = Object.create(Constructor.prototype); // 1 + 2
  const result = Constructor.apply(obj, args);       // 3
  return result instanceof Object ? result : obj;    // 4
}
```

## 四、继承实现方式（4 题）

---

### Q15：以下关于 JavaScript 继承方式的描述，错误的是？

**A.** 原型链继承的缺点是引用类型属性被所有实例共享

**B.** 构造函数继承（借用构造函数）无法复用父类原型上的方法

**C.** 组合继承会调用两次父类构造函数

**D.** 寄生组合继承是 ES6 `class extends` 的底层实现方式

**E.** `Object.create()` 可以用来实现原型式继承

**答案：D**

**解析：**

- **A 正确**：原型链继承中父类实例属性成为子类原型属性，引用类型被共享。
- **B 正确**：构造函数继承（`Parent.call(this)`）只能继承实例属性，无法继承原型方法。
- **C 正确**：组合继承 = 构造函数继承 + 原型链继承，父类构造函数被调用两次（一次在 `Child.prototype = new Parent()`，一次在 `Parent.call(this)`）。
- **D 错误**：ES6 `class extends` 的底层实现更接近**寄生组合继承**，但并非完全相同。ES6 的 `extends` 还处理了静态属性和方法的继承（`Child.__proto__ = Parent`），以及 `super` 关键字等。
- **E 正确**：`Object.create()` 是原型式继承的标准实现。

**寄生组合继承标准写法：**

```javascript
function Parent(name) {
  this.name = name;
}
Parent.prototype.say = function() {
  console.log(this.name);
};

function Child(name, age) {
  Parent.call(this, name); // 继承实例属性
  this.age = age;
}
// 继承原型方法
Child.prototype = Object.create(Parent.prototype);
Child.prototype.constructor = Child;
```

### Q16：以下代码中，`child.sayHello()` 的输出是什么？

```javascript
function Parent(name) {
  this.name = name;
}
Parent.prototype.sayHello = function() {
  return `Hello, ${this.name}`;
};

function Child(name, age) {
  Parent.call(this, name);
  this.age = age;
}
Child.prototype = Object.create(Parent.prototype);
Child.prototype.constructor = Child;
Child.prototype.sayHello = function() {
  return `${Parent.prototype.sayHello.call(this)}, age ${this.age}`;
};

const child = new Child('Tom', 10);
console.log(child.sayHello());
```

**A.** `Hello, Tom`

**B.** `Hello, Tom, age 10`

**C.** `Hello, undefined`

**D.** 报错

**答案：B**

**解析：**

1. 这是寄生组合继承的标准实现。
2. `Child.prototype.sayHello` 重写了从 `Parent.prototype` 继承的 `sayHello` 方法。
3. 在子类方法中，通过 `Parent.prototype.sayHello.call(this)` 显式调用父类原型方法，传入 `this`（即 `child` 实例）。
4. `child.name` 为 `'Tom'`（通过 `Parent.call(this, name)` 继承），`child.age` 为 `10`。
5. 最终输出 `'Hello, Tom, age 10'`。

**关键点：** 子类重写父类方法时，如需保留父类行为，应通过 `Parent.prototype.method.call(this)` 显式调用父类方法。这是 ES6 `super.method()` 的底层原理。

### Q17：以下关于 `Object.create()` 的描述，正确的是？（多选）

**A.** `Object.create(null)` 创建的对象没有原型链

**B.** `Object.create(proto)` 创建的对象的 `__proto__` 指向 `proto`

**C.** `Object.create(proto, props)` 的第二个参数与 `Object.defineProperties` 的第二个参数格式相同

**D.** `Object.create(null)` 创建的对象可以使用 `toString()` 方法

**E.** `Object.create()` 本质上是寄生组合继承的核心

**答案：A、B、C、E**

**解析：**

- **A 正确**：`Object.create(null)` 创建的对象 `__proto__` 为 `undefined`，完全脱离原型链。
- **B 正确**：`Object.create(proto)` 返回新对象，其 `[[Prototype]]` 指向 `proto`。
- **C 正确**：第二个参数是属性描述符对象，格式与 `Object.defineProperties` 一致。
- **D 错误**：`Object.create(null)` 的对象没有原型链，因此没有 `toString()` 方法，调用会报错。
- **E 正确**：寄生组合继承中，`Child.prototype = Object.create(Parent.prototype)` 是实现核心。

**`Object.create` 的 polyfill：**

```javascript
function create(proto) {
  function F() {}
  F.prototype = proto;
  return new F();
}
```

### Q18：以下代码中，`instanceof` 的结果是什么？

```javascript
function Parent() {}
function Child() {}
Child.prototype = Object.create(Parent.prototype);
const instance = new Child();

console.log(instance instanceof Child);
console.log(instance instanceof Parent);
console.log(instance instanceof Object);
console.log(Child instanceof Parent);
console.log(Child instanceof Object);
console.log(Child instanceof Function);
```

**A.** 全部为 `true`

**B.** 前三个 `true`，后三个 `false`

**C.** 前五个 `true`，最后一个 `false`

**D.** 前三个 `true`，后三个第二个 `false`（即 `Child instanceof Parent` 为 `false`），其余 `true`

**答案：D**

**解析：**

`instanceof` 检查的是右边构造函数的 `prototype` 是否在左边对象的原型链上。

**实例 `instance` 的原型链：** `instance` → `Child.prototype` → `Parent.prototype` → `Object.prototype` → `null`
- `instance instanceof Child` → `true`（`Child.prototype` 在链上）
- `instance instanceof Parent` → `true`（`Parent.prototype` 在链上）
- `instance instanceof Object` → `true`（`Object.prototype` 在链上）

**构造函数 `Child` 的原型链：** `Child`（函数对象）→ `Function.prototype` → `Object.prototype` → `null`
- `Child instanceof Parent` → **`false`**（`Parent.prototype` 不在 `Child` 的原型链上）
- `Child instanceof Object` → `true`
- `Child instanceof Function` → `true`

**关键点：** `instanceof` 只检查原型链，`Child` 和 `Parent` 之间没有原型链关系（除非使用 ES6 `class extends`，它会设置 `Child.__proto__ = Parent`）。

### Q19：以下关于 ES6 `class` 的描述，正确的是？（多选）

**A.** `class` 中定义的方法是不可枚举的

**B.** `class` 声明不存在变量提升（hoisting）

**C.** `class` 本质上还是基于原型的语法糖

**D.** `class` 内部定义的方法默认是严格模式

**E.** `class` 中的 `constructor` 方法是可选的

**答案：A、C、D、E**

**解析：**

- **A 正确**：`class` 中定义的方法自动设置 `enumerable: false`，而传统构造函数 `prototype` 上定义的方法默认可枚举。
- **B 错误**：`class` 声明像 `let`/`const` 一样存在**暂时性死区（TDZ）**，有提升行为但不可在声明前访问，这与"不存在提升"有细微区别。
- **C 正确**：`class` 在底层仍是基于原型的实现，`typeof SomeClass` 返回 `'function'`。
- **D 正确**：`class` 体内的代码默认在严格模式下执行。
- **E 正确**：如果未显式定义 `constructor`，JavaScript 引擎会自动添加一个空的 `constructor() {}`。

```javascript
class Foo {
  method() {}
}
console.log(Object.getOwnPropertyDescriptor(Foo.prototype, 'method').enumerable); // false
```

### Q20：以下代码的输出是什么？

```javascript
class Parent {
  static getName() {
    return 'Parent';
  }
}
class Child extends Parent {
  static getName() {
    return super.getName() + ' & Child';
  }
}
console.log(Child.getName());
console.log(Child.__proto__ === Parent);
console.log(Child.prototype.__proto__ === Parent.prototype);
```

**A.** `'Parent & Child'`、`true`、`true`

**B.** `'Parent & Child'`、`false`、`true`

**C.** `'Parent & Child'`、`true`、`false`

**D.** `'Parent'`、`true`、`true`

**答案：A**

**解析：**

1. `Child.getName()` 调用子类静态方法，内部通过 `super.getName()` 调用父类静态方法，返回 `'Parent & Child'`。
2. `Child.__proto__ === Parent` → **`true`**：ES6 `extends` 不仅设置了原型链继承，还设置了 `Child.__proto__ = Parent`，使子类可以继承父类的静态属性和方法。
3. `Child.prototype.__proto__ === Parent.prototype` → **`true`**：这是实例方法的原型链继承，与寄生组合继承一致。

**ES6 `extends` 设置的两条原型链：**

```
Child.__proto__ = Parent              // 静态方法继承
Child.prototype.__proto__ = Parent.prototype  // 实例方法继承
```

### Q21：以下代码中，`dog.eat()` 的输出是什么？

```javascript
class Animal {
  constructor(name) {
    this.name = name;
  }
  eat() {
    console.log(`${this.name} is eating`);
  }
}
class Dog extends Animal {
  constructor(name, breed) {
    this.breed = breed;
    super(name);
  }
}
const dog = new Dog('Buddy', 'Golden');
dog.eat();
```

**A.** `Buddy is eating`

**B.** `undefined is eating`

**C.** `Golden is eating`

**D.** 报错：`Must call super constructor before accessing 'this'`

**答案：D**

**解析：**

在 ES6 `class` 的继承中，子类构造函数中**必须先调用 `super()` 才能使用 `this`**。本题中 `this.breed = breed` 在 `super(name)` 之前，违反了此规则，会抛出 `ReferenceError`。

**正确写法：**

```javascript
class Dog extends Animal {
  constructor(name, breed) {
    super(name);      // 必须先调用 super()
    this.breed = breed; // 然后才能使用 this
  }
}
```

**为什么？** ES6 的继承机制中，子类的 `this` 对象是由父类构造函数创建的。`super()` 调用父类构造函数来创建 `this`，在此之前 `this` 不存在。

### Q22：以下关于 ES6 `class` 与构造函数写法的区别，错误的是？

**A.** `class` 中定义的方法不可枚举，构造函数原型上的方法可枚举

**B.** `class` 必须使用 `new` 调用，构造函数可以不用 `new` 调用

**C.** `class` 中的 `super` 指向父类的 `prototype` 对象

**D.** `class` 中可以使用 `static` 定义静态方法，构造函数中也可以直接定义静态方法

**答案：C**

**解析：**

- **A 正确**：`class` 方法自动设置 `enumerable: false`。
- **B 正确**：`class` 构造函数内部有 `new.target` 检查，不使用 `new` 调用会抛出 `TypeError`。
- **C 错误**：`super` 在普通方法中指向父类的 `prototype`（即 `Parent.prototype`）；但在静态方法中，`super` 指向父类本身（即 `Parent`）。因此 `super` 的指向是**上下文相关的**，并非始终指向 `prototype`。
- **D 正确**：`class` 的 `static` 等价于 `Constructor.staticMethod = function() {}`。

```javascript
class Parent {
  static staticMethod() { return 'Parent static'; }
  prototypeMethod() { return 'Parent prototype'; }
}
class Child extends Parent {
  static staticMethod() {
    return super.staticMethod(); // super 指向 Parent
  }
  prototypeMethod() {
    return super.prototypeMethod(); // super 指向 Parent.prototype
  }
}
```

### Q23：以下代码存在什么问题？应该怎么修改？

```javascript
function createComponent(config) {
  const component = Object.create(Component.prototype);
  component.props = config.props || {};
  component.state = Object.assign({}, config.initialState);
  component.render = config.render || Component.prototype.render;
  return component;
}
```

关于这段代码的分析，以下说法正确的是？

**A.** 代码没有问题，是原型式继承的正确用法

**B.** 存在原型污染风险，`config.props` 可能被意外共享

**C.** 每次创建组件都会复制 `render` 方法，破坏了原型共享的优势

**D.** B 和 C 都正确

**答案：D**

**解析：**

- **B 正确**：`component.props = config.props || {}` 直接将 `config.props` 引用赋值给 `component.props`。如果多个组件实例共享同一个 `config.props` 对象，修改一个实例的 `props` 会影响其他实例。

- **C 正确**：`component.render = config.render || Component.prototype.render` 在实例上添加了 `render` 属性，即使使用的是 `Component.prototype.render`，也会创建实例自有属性。这破坏了原型链共享方法的优势（每个实例本应通过原型链共享 `render`，而不是各自持有副本）。

**改进方案：**

```javascript
function createComponent(config) {
  const component = Object.create(Component.prototype);
  // 深拷贝 props，避免引用共享
  component.props = JSON.parse(JSON.stringify(config.props || {}));
  // 深拷贝 state
  component.state = JSON.parse(JSON.stringify(config.initialState || {}));
  // 仅在需要自定义 render 时才在实例上设置
  if (config.render) {
    component.render = config.render;
  }
  return component;
}
```

### Q24：以下关于原型相关的性能最佳实践，描述正确的是？（多选）

**A.** `Object.create(null)` 适合用于纯数据字典（dictionary/map），比 `{}` 性能更好

**B.** 在原型上定义方法优于在构造函数中定义方法，因为原型方法被所有实例共享

**C.** `Object.setPrototypeOf()` 是性能友好的操作，可以在运行时随意修改原型链

**D.** 使用 `for...in` 遍历对象时，应始终配合 `hasOwnProperty` 过滤原型属性

**E.** `delete` 操作符删除原型链上的属性比删除自有属性更快

**答案：A、B、D**

**解析：**

- **A 正确**：`Object.create(null)` 创建的对象没有原型链，避免了属性名冲突（如 `toString`、`constructor` 等），适合作为纯数据字典。在 ES6 中，`Map` 是更优的选择。
- **B 正确**：在构造函数中定义方法会导致每个实例都有一份方法的副本，浪费内存。原型方法只需一份。
- **C 错误**：`Object.setPrototypeOf()` 是**性能极差**的操作（MDN 明确警告），因为它会破坏 JavaScript 引擎的优化假设。应在对象创建时确定原型，如使用 `Object.create()`。
- **D 正确**：`for...in` 会遍历原型链上的可枚举属性，使用 `hasOwnProperty` 过滤是标准做法。但更好的做法是使用 `Object.keys()` 或 `Object.entries()`。
- **E 错误**：`delete` 操作本身性能开销较大，且 `delete` 无法删除原型链上的属性（只能删除自有属性）。

### Q25：以下代码中，存在原型污染（Prototype Pollution）安全风险的是？

```javascript
// ①
function merge(target, source) {
  for (let key in source) {
    if (typeof source[key] === 'object' && source[key] !== null) {
      if (!target[key]) target[key] = {};
      merge(target[key], source[key]);
    } else {
      target[key] = source[key];
    }
  }
  return target;
}

// ②
const config = JSON.parse('{"__proto__": {"isAdmin": true}}');
merge({}, config);

// ③
const obj = {};
console.log(obj.isAdmin);
```

**A.** 只有 ① 存在风险

**B.** 只有 ② 存在风险

**C.** ① 和 ② 的组合存在风险，导致 ③ 输出 `true`

**D.** 不存在任何风险，③ 输出 `undefined`

**答案：C**

**解析：**

这是经典的**原型污染（Prototype Pollution）**攻击。

1. `merge` 函数是深度合并函数，但它没有对 `__proto__` 或 `constructor.prototype` 等特殊属性做过滤。
2. 攻击者构造的 JSON 数据 `{"__proto__": {"isAdmin": true}}` 中包含 `__proto__` 属性。
3. 合并时，`target['__proto__']` 被赋值为 `{"isAdmin": true}`，这实际上修改了 `Object.prototype`。
4. 之后创建的任何普通对象 `{}` 都会继承 `isAdmin: true`，`obj.isAdmin` 输出 `true`。

**安全修复方案：**

```javascript
function merge(target, source) {
  for (let key in source) {
    if (!source.hasOwnProperty(key)) continue; // 只处理自有属性
    if (key === '__proto__' || key === 'constructor' || key === 'prototype') {
      continue; // 阻止原型污染
    }
    if (typeof source[key] === 'object' && source[key] !== null) {
      if (!target[key]) target[key] = {};
      merge(target[key], source[key]);
    } else {
      target[key] = source[key];
    }
  }
  return target;
}
```

**更安全的替代方案：**

- 使用 `Object.assign()` 或展开运算符 `{...obj}` 进行浅合并
- 使用 `Map` 替代普通对象存储键值对
- 使用 `Object.create(null)` 创建无原型对象
- 对用户输入进行严格的 Schema 校验

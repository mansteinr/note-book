## 一、微前端概述

### 1.1 什么是微前端？

**微前端（Micro-Frontend）** 是将微服务理念扩展到前端开发领域的架构模式。它将一个大型前端应用拆分为多个**独立开发、独立测试、独立部署**的小型前端应用，最后在运行时通过某种方式组合成一个完整的应用。

```
┌─────────────────────────────────────────────────────────────┐
│                     基座应用（Shell / Host）                    │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐       │
│  │ 用户管理  │ │ 订单管理  │ │ 商品管理  │ │ 数据分析  │       │
│  │ 子应用 A  │ │ 子应用 B  │ │ 子应用 C  │ │ 子应用 D  │       │
│  │ (Vue3)   │ │ (React)  │ │ (Vue3)   │ │ (Angular)│       │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘       │
│                    共享层：路由 / 通信 / 权限                     │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 微前端 vs 单体前端

| 维度 | 单体前端 | 微前端 |
|------|---------|--------|
| 代码规模 | 单一仓库，代码量巨大 | 多仓库，每个子应用独立 |
| 技术栈 | 统一技术栈 | 允许混合技术栈 |
| 团队协作 | 耦合严重，合并冲突频繁 | 独立开发，互不干扰 |
| 部署方式 | 整体部署，风险集中 | 独立部署，灰度发布 |
| 构建速度 | 全量构建，时间长 | 增量构建，速度快 |
| 测试成本 | 回归测试范围大 | 单元测试范围可控 |
| 新人上手 | 需理解全部代码 | 只需理解负责的子应用 |
| 运维复杂度 | 简单 | 较高 |

### 1.3 微前端解决的问题

- **巨型应用维护困难**：代码量膨胀导致构建慢、部署风险高
- **多团队协作冲突**：不同团队在同一仓库开发，合并冲突频繁
- **技术栈升级困难**：无法局部升级框架版本
- **增量迁移需求**：从旧技术栈逐步迁移到新技术栈

### 1.4 微前端核心设计原则

| 原则 | 说明 |
|------|------|
| **技术无关** | 各子应用可使用不同框架，基座不限制子应用技术选型 |
| **独立部署** | 子应用可独立构建、测试、部署，互不影响 |
| **团队自治** | 每个子应用由一个独立团队端到端负责 |
| **渐进迁移** | 支持逐步引入微前端，非侵入式改造现有系统 |
| **高内聚低耦合** | 子应用内部高度内聚，子应用之间低耦合 |

### 2.2 基座应用（Shell）职责

基座应用是微前端架构的入口，负责：

```
基座应用职责
├── 子应用注册与管理
│   ├── 子应用注册配置（name / entry / container / activeRule）
│   ├── 子应用生命周期管理（bootstrap / mount / unmount）
│   └── 子应用版本管理
├── 路由分发
│   ├── 根据 activeRule 匹配激活子应用
│   ├── 路由前缀隔离（如 /app-a/、/app-b/）
│   └── 404 与加载失败兜底
├── 全局共享
│   ├── 全局状态管理（用户信息、权限、主题）
│   ├── 公共依赖注入（lodash、moment、axios 等）
│   └── 通信总线（应用间事件通信）
├── 基础设施
│   ├── 统一鉴权与登录态管理
│   ├── 统一异常监控与上报
│   └── 统一 UI 规范（主题、布局、菜单）
└── 加载优化
    ├── 子应用预加载策略
    ├── Loading 态与骨架屏
    └── 加载失败重试机制
```

### 2.3 子应用（Micro App）规范

每个子应用必须遵循以下标准接口：

```typescript
// 子应用生命周期接口（标准规范）
interface MicroAppLifecycle {
  // 初次加载时调用，仅执行一次，用于初始化全局资源
  bootstrap(): Promise<void>;

  // 每次进入子应用时调用，挂载到 DOM
  mount(props: MicroAppProps): Promise<void>;

  // 每次离开子应用时调用，卸载并清理
  unmount(props: MicroAppProps): Promise<void>;

  // 可选：子应用独立更新
  update?(props: MicroAppProps): Promise<void>;
}

interface MicroAppProps {
  container: HTMLElement;        // 子应用挂载容器
  name: string;                  // 子应用名称
  baseroute: string;             // 基础路由前缀
  globalState: GlobalState;      // 全局状态
  eventBus: EventBus;            // 事件总线
  shared: Record<string, any>;   // 共享依赖
  onGlobalStateChange: (cb: Function) => void;
  setGlobalState: (state: any) => void;
}
```

### 3.2 推荐选型方案

| 场景 | 推荐方案 | 理由 |
|------|---------|------|
| 传统企业后台管理系统 | **qiankun** | 生态成熟，文档完善，社区活跃 |
| 构建工具为 Webpack 5 | **Module Federation** | 原生支持，运行时模块共享 |
| 需要 Vite 生态 | **micro-app** 或 **wujie** | 对 Vite 支持好，接入成本低 |

| 遗留系统渐进迁移 | **qiankun** + **wujie** | 兼容性好，逐步替换 |
| 强隔离安全性要求 | **wujie** | iframe 天然隔离，安全性最高 |

## 四、服务拆分策略

### 4.1 拆分原则

| 原则 | 说明 |
|------|------|
| **业务领域驱动** | 按业务领域（DDD 限界上下文）拆分，而非按技术层拆分 |
| **高内聚低耦合** | 子应用内功能高度相关，子应用间依赖最小化 |
| **独立部署** | 每个子应用可独立构建、测试、部署上线 |
| **团队对齐** | 按康威定律，一个团队负责一个子应用 |
| **数据自治** | 每个子应用拥有自己的数据存储逻辑 |
| **渐进拆分** | 从单体逐步拆出，优先拆分变更最频繁的模块 |

### 4.2 拆分策略矩阵

```
业务模块拆分策略
├── 按业务领域拆分（推荐）
│   ├── 用户中心（登录/注册/个人信息/权限管理）
│   ├── 订单管理（订单列表/详情/售后/退款）
│   ├── 商品管理（商品列表/分类/库存/上下架）
│   ├── 营销中心（优惠券/活动/推广）
│   ├── 数据分析（报表/看板/数据导出）
│   └── 系统设置（参数配置/日志/通知）
├── 按用户角色拆分
│   ├── 商家端（商品管理/订单处理/数据分析）
│   ├── 用户端（浏览/下单/支付/评价）
│   └── 管理端（审核/权限/系统配置）
├── 按页面路由拆分
│   └── 每个一级路由对应一个子应用
└── 按变更频率拆分
    ├── 核心业务（低变更频率，稳定）
    └── 创新业务（高变更频率，快速迭代）
```

### 5.2 全局事件总线（推荐方案）

```typescript
// shared-utils/src/event-bus.ts

type EventHandler = (...args: any[]) => void;

interface EventBusConfig {
  debug?: boolean;          // 是否开启调试日志
  namespace?: string;       // 命名空间隔离
}

class EventBus {
  private events: Map<string, Set<EventHandler>> = new Map();
  private config: EventBusConfig;

  constructor(config: EventBusConfig = {}) {
    this.config = { debug: false, namespace: 'global', ...config };
  }

  // 订阅事件
  on(event: string, handler: EventHandler): () => void {
    const namespacedEvent = this.getNamespacedEvent(event);
    if (!this.events.has(namespacedEvent)) {
      this.events.set(namespacedEvent, new Set());
    }
    this.events.get(namespacedEvent)!.add(handler);

    if (this.config.debug) {
      console.log(`[EventBus:${this.config.namespace}] on "${event}"`);
    }

    // 返回取消订阅函数
    return () => this.off(event, handler);
  }

  // 仅订阅一次
  once(event: string, handler: EventHandler): void {
    const onceHandler = (...args: any[]) => {
      handler(...args);
      this.off(event, onceHandler);
    };
    this.on(event, onceHandler);
  }

  // 发布事件
  emit(event: string, ...args: any[]): void {
    const namespacedEvent = this.getNamespacedEvent(event);
    const handlers = this.events.get(namespacedEvent);

    if (handlers) {
      handlers.forEach(handler => {
        try {
          handler(...args);
        } catch (error) {
          console.error(`[EventBus] Error in handler for "${event}":`, error);
        }
      });
    }

    if (this.config.debug) {
      console.log(`[EventBus:${this.config.namespace}] emit "${event}"`, ...args);
    }
  }

  // 取消订阅
  off(event: string, handler?: EventHandler): void {
    const namespacedEvent = this.getNamespacedEvent(event);
    if (!handler) {
      this.events.delete(namespacedEvent);
      return;
    }
    this.events.get(namespacedEvent)?.delete(handler);
  }

  // 清除所有事件
  clear(): void {
    this.events.clear();
  }

  private getNamespacedEvent(event: string): string {
    return `${this.config.namespace}:${event}`;
  }
}

// 导出全局单例
export const globalEventBus = new EventBus({ namespace: 'app', debug: false });

// 为子应用创建独立命名空间的事件总线
export function createAppEventBus(appName: string): EventBus {
  return new EventBus({ namespace: `app:${appName}`, debug: false });
}
```

```typescript
  user: {
    id: string;

    avatar: string;
    roles: string[];
    permissions: string[];
  } | null;
  theme: 'light' | 'dark';
  locale: string;
  collapsed: boolean;
  // 子应用间共享的临时状态
  shared: Record<string, any>;

// 全局状态（通过 qiankun 的 initGlobalState 传递给子应用）
const initialState: GlobalState = {
  user: null,
  theme: 'light',
  locale: 'zh-CN',
  collapsed: false,
  shared: {},
};

const state = reactive<GlobalState>({ ...initialState });

// 状态变更监听器
const listeners: Set<(state: GlobalState, prevState: GlobalState) => void> = new Set();

export const globalState = {
  getState(): Readonly<GlobalState> {
    return state;
  },

  setState(newState: Partial<GlobalState>): void {
    const prevState = { ...state };
    Object.assign(state, newState);
    // 通知所有监听器
    listeners.forEach(listener => {
      try {
        listener(state as GlobalState, prevState);
      } catch (e) {
        console.error('[GlobalState] listener error:', e);
      }
    });
  },

  onChange(callback: (state: GlobalState, prevState: GlobalState) => void): () => void {
    listeners.add(callback);
    return () => listeners.delete(callback);
  },

  // 用于 qiankun 的 initGlobalState
  toQiankunState() {
    return {
      ...state,
      onGlobalStateChange: (callback: Function) => {
        return globalState.onChange(callback as any);
      },
      setGlobalState: (newState: Partial<GlobalState>) => {
        globalState.setState(newState);
      },
    };
  },
};
```

### 5.5 通信方式对比

| 通信方式 | 适用场景 | 优点 | 缺点 |
|---------|---------|------|------|
| **事件总线** | 子应用间松耦合通信 | 解耦、灵活、实时 | 事件名需约定，难以追踪 |
| **全局状态** | 跨应用共享状态 | 可预测、可追溯 | 不适合大量数据 |
| **URL 参数** | 页面跳转传参 | 简单、可分享 | 数据量受限，不安全 |
| **localStorage** | 持久化数据共享 | 持久化、跨标签页 | 同步问题，无类型安全 |
| **共享 API** | 数据获取 | 统一数据源 | 后端依赖 |
| **postMessage** | 跨域 iframe 通信 | 安全、标准化 | API 较底层 |

### 6.4 状态持久化策略

```typescript
// shared-utils/src/storage.ts

interface StorageAdapter {
  get<T>(key: string): T | null;
  set<T>(key: string, value: T, expire?: number): void;
  remove(key: string): void;
  clear(): void;
}

class AppStorage implements StorageAdapter {
  private prefix: string;
  private storage: Storage;

  constructor(appName: string, type: 'local' | 'session' = 'local') {
    this.prefix = `app:${appName}:`;
    this.storage = type === 'local' ? localStorage : sessionStorage;
  }

  private getKey(key: string): string {
    return `${this.prefix}${key}`;
  }

  get<T>(key: string): T | null {
    try {
      const raw = this.storage.getItem(this.getKey(key));
      if (!raw) return null;

      const { value, expire } = JSON.parse(raw);
      if (expire && Date.now() > expire) {
        this.remove(key);
        return null;
      }
      return value as T;
    } catch {
      return null;
    }
  }

  set<T>(key: string, value: T, expire?: number): void {
    const data = {
      value,
      expire: expire ? Date.now() + expire : undefined,
    };
    this.storage.setItem(this.getKey(key), JSON.stringify(data));
  }

  remove(key: string): void {
    this.storage.removeItem(this.getKey(key));
  }

  clear(): void {
    const keys = Object.keys(this.storage);
    keys.forEach(key => {
      if (key.startsWith(this.prefix)) {
        this.storage.removeItem(key);
      }
    });
  }
}

// 创建各子应用的存储实例
export const userStorage = new AppStorage('user');
export const orderStorage = new AppStorage('order');
export const productStorage = new AppStorage('product');
```

```typescript
import { prefetchApps } from 'qiankun';

// 预加载策略配置
export enum PrefetchStrategy {
  /** 所有子应用静态资源在浏览器空闲时加载 */
  ALL = 'all',
  /** 只预加载指定的子应用 */
  SELECTIVE = 'selective',
  /** 不预加载 */
  NONE = 'none',
}

export function setupPrefetch(strategy: PrefetchStrategy) {
  switch (strategy) {
    case PrefetchStrategy.ALL:
      // 使用 requestIdleCallback 在浏览器空闲时预加载
      if ('requestIdleCallback' in window) {
        requestIdleCallback(() => {
          prefetchApps(microApps.map(app => ({
            name: app.name,
            entry: app.entry,
          })));
        });
      }
      break;

    case PrefetchStrategy.SELECTIVE:
      // 根据用户权限预加载相关子应用
      const userRoles = getCurrentUserRoles();
      const appsToPrefetch = microApps.filter(app => {
        return app.permissions?.some(p => userRoles.includes(p));
      });
      requestIdleCallback(() => {
        prefetchApps(appsToPrefetch.map(app => ({
          name: app.name,
          entry: app.entry,
        })));
      });
      break;

    case PrefetchStrategy.NONE:
    default:
      break;
  }
}
```

### 9.5 子应用缓存策略

```typescript
// packages/main-app/src/micro/cache.ts

interface CacheEntry {
  name: string;
  version: string;
  lastLoaded: number;
  assets: string[];
}

class MicroAppCache {
  private cache: Map<string, CacheEntry> = new Map();
  private readonly MAX_CACHE_SIZE = 10;
  private readonly CACHE_TTL = 30 * 60 * 1000; // 30分钟

  set(name: string, entry: CacheEntry): void {
    // LRU 淘汰
    if (this.cache.size >= this.MAX_CACHE_SIZE) {
      const oldest = this.getOldestEntry();
      if (oldest) {
        this.cache.delete(oldest);
      }
    }
    this.cache.set(name, { ...entry, lastLoaded: Date.now() });
  }

  get(name: string): CacheEntry | undefined {
    const entry = this.cache.get(name);
    if (!entry) return undefined;

    // 检查是否过期
    if (Date.now() - entry.lastLoaded > this.CACHE_TTL) {
      this.cache.delete(name);
      return undefined;
    }

    return entry;
  }

  has(name: string): boolean {
    return this.get(name) !== undefined;
  }

  clear(): void {
    this.cache.clear();
  }

  private getOldestEntry(): string | undefined {
    let oldestName: string | undefined;
    let oldestTime = Infinity;

    this.cache.forEach((entry, name) => {
      if (entry.lastLoaded < oldestTime) {
        oldestTime = entry.lastLoaded;
        oldestName = name;
      }
    });

    return oldestName;
  }
}

export const microAppCache = new MicroAppCache();
```

```typescript
const appPermissions: AppPermission[] = [
  {
    name: 'micro-app-user',
    requiredRoles: ['admin', 'user_manager'],

  },
  {
    name: 'micro-app-order',

// 检查用户是否有权访问子应用
export function canAccessApp(appName: string, user: { roles: string[]; permissions: string[] }): boolean {
  const appPerm = appPermissions.find(p => p.name === appName);
  if (!appPerm) return true; // 未配置权限的应用默认允许访问

  const hasRole = appPerm.requiredRoles.some(role => user.roles.includes(role));
  const hasPermission = appPerm.requiredPermissions.every(perm => user.permissions.includes(perm));

  return hasRole || hasPermission;
}

// 在路由守卫中使用
router.beforeEach((to, from, next) => {
  const user = useUserStore();
  const appName = getAppNameFromRoute(to.path);

  if (appName && !canAccessApp(appName, {
    roles: user.roles,
    permissions: user.permissions,
  })) {
    next('/403');
    return;
  }

  next();
});
```

### 10.5 跨应用通信安全

```typescript
// packages/shared-utils/src/secure-event-bus.ts

interface SecureEventPayload {
  source: string;       // 事件来源应用名
  timestamp: number;    // 时间戳
  signature: string;    // 签名（可选）
  data: any;            // 实际数据
}

class SecureEventBus extends EventBus {
  private trustedApps: Set<string>;
  private maxPayloadSize: number;

  constructor(options: {
    namespace?: string;
    trustedApps?: string[];
    maxPayloadSize?: number;
  } = {}) {
    super({ namespace: options.namespace });
    this.trustedApps = new Set(options.trustedApps || []);
    this.maxPayloadSize = options.maxPayloadSize || 1024 * 10; // 10KB
  }

  // 安全发布事件
  secureEmit(event: string, data: any, sourceApp: string): void {
    // 来源校验
    if (!this.trustedApps.has(sourceApp)) {
      console.warn(`[SecureEventBus] 拒绝未授权应用 "${sourceApp}" 的事件`);
      return;
    }

    // 数据大小校验
    const payload = JSON.stringify(data);
    if (payload.length > this.maxPayloadSize) {
      console.warn(`[SecureEventBus] 事件数据过大: ${payload.length} bytes`);
      return;
    }

    const securePayload: SecureEventPayload = {
      source: sourceApp,
      timestamp: Date.now(),
      signature: this.generateSignature(event, data),
      data,
    };

    this.emit(event, securePayload);
  }

  // 安全订阅事件（带来源校验）
  secureOn(event: string, handler: (data: any, source: string) => void, allowedSources?: string[]): () => void {
    return this.on(event, (payload: SecureEventPayload) => {
      // 校验事件来源
      if (allowedSources && !allowedSources.includes(payload.source)) {
        return;
      }

      // 校验时间戳（防止重放攻击，5分钟内有效）
      if (Date.now() - payload.timestamp > 5 * 60 * 1000) {
        console.warn('[SecureEventBus] 事件已过期');
        return;
      }

      handler(payload.data, payload.source);
    });
  }

  private generateSignature(event: string, data: any): string {
    // 简单签名（生产环境应使用 HMAC）
    const str = `${event}:${JSON.stringify(data)}`;
    let hash = 0;
    for (let i = 0; i < str.length; i++) {
      const char = str.charCodeAt(i);
      hash = ((hash << 5) - hash) + char;
      hash |= 0;
    }
    return hash.toString(36);
  }
}

export const secureEventBus = new SecureEventBus({
  namespace: 'app',
  trustedApps: ['micro-app-user', 'micro-app-order', 'micro-app-product'],
});
```

```typescript
interface MicroPlugin {
  name: string;
  version: string;

  // 生命周期钩子
  beforeAppLoad?(appName: string): Promise<void> | void;
  afterAppMount?(appName: string): Promise<void> | void;
  beforeAppUnmount?(appName: string): Promise<void> | void;
  onGlobalStateChange?(state: any, prev: any): void;
  onError?(error: Error, appName: string): void;
}

class PluginManager {
  private plugins: Map<string, MicroPlugin> = new Map();

  register(plugin: MicroPlugin): void {
    if (this.plugins.has(plugin.name)) {
      console.warn(`[PluginManager] 插件 "${plugin.name}" 已注册，将被覆盖`);
    }
    this.plugins.set(plugin.name, plugin);
    console.log(`[PluginManager] 插件 "${plugin.name}" v${plugin.version} 已注册`);
  }

  unregister(name: string): void {
    this.plugins.delete(name);
  }

  async executeHook(hook: keyof MicroPlugin, ...args: any[]): Promise<void> {
    const promises: Promise<void>[] = [];

    this.plugins.forEach(plugin => {
      const fn = plugin[hook] as Function;
      if (typeof fn === 'function') {
        promises.push(
          Promise.resolve(fn(...args)).catch(err => {
            console.error(`[PluginManager] 插件 "${plugin.name}" 钩子 "${hook}" 执行失败:`, err);
          })
        );
      }
    });

    await Promise.all(promises);
  }

  getPlugins(): MicroPlugin[] {
    return Array.from(this.plugins.values());
  }
}
```

### 11.2 子应用版本管理

```typescript
// packages/main-app/src/micro/version-manager.ts

interface AppVersionConfig {
  name: string;
  version: string;
  entry: string;
  changelog?: string;
  minBaseVersion?: string; // 最低基座版本要求
}

class VersionManager {
  private versions: Map<string, AppVersionConfig> = new Map();
  private currentVersions: Map<string, string> = new Map();

  // 注册子应用版本
  registerVersion(config: AppVersionConfig): void {
    this.versions.set(config.name, config);
  }

  // 检查版本兼容性
  checkCompatibility(appName: string, baseVersion: string): boolean {
    const config = this.versions.get(appName);
    if (!config?.minBaseVersion) return true;

    return this.compareVersions(baseVersion, config.minBaseVersion) >= 0;
  }

  // 灰度发布：根据比例分配不同版本
  getAppEntry(appName: string, userId?: string): string {
    const config = this.versions.get(appName);
    if (!config) throw new Error(`未找到子应用 "${appName}" 的版本配置`);

    // 灰度策略：根据 userId hash 分配版本
    if (userId && this.isInGrayRelease(appName, userId)) {
      return this.getGrayVersionEntry(appName);
    }

    return config.entry;
  }

  private isInGrayRelease(appName: string, userId: string): boolean {
    // 简单 hash 灰度
    const hash = this.hashString(userId + appName);
    return hash % 100 < 10; // 10% 灰度
  }

  private getGrayVersionEntry(appName: string): string {
    // 返回灰度版本地址
    return `https://cdn.example.com/${appName}-gray/`;
  }

  private compareVersions(v1: string, v2: string): number {
    const parts1 = v1.split('.').map(Number);
    const parts2 = v2.split('.').map(Number);

    for (let i = 0; i < Math.max(parts1.length, parts2.length); i++) {
      const n1 = parts1[i] || 0;
      const n2 = parts2[i] || 0;
      if (n1 !== n2) return n1 - n2;
    }
    return 0;
  }

  private hashString(str: string): number {
    let hash = 0;
    for (let i = 0; i < str.length; i++) {
      hash = ((hash << 5) - hash) + str.charCodeAt(i);
      hash |= 0;
    }
    return Math.abs(hash);
  }
}

export const versionManager = new VersionManager();
```

## 十三、面试题集

### 初级面试题

**Q1：什么是微前端？它解决了什么问题？**

> **答案**：微前端是将微服务理念扩展到前端开发的架构模式。它将一个大型前端应用拆分为多个独立开发、独立测试、独立部署的子应用，在运行时组合成一个完整的应用。
>
> **解决的问题**：
> - 巨型应用代码膨胀、构建慢、维护困难
> - 多团队协作冲突频繁
> - 技术栈升级困难，无法局部升级
> - 需要增量迁移旧系统
>
> **知识点**：微前端概念、架构设计
> **难度**：初级

**Q2：微前端的核心设计原则有哪些？**

> **答案**：
> 1. **技术无关**：各子应用可自由选择技术栈
> 2. **独立部署**：子应用可独立构建、测试、部署
> 3. **团队自治**：每个子应用由独立团队端到端负责
> 4. **渐进迁移**：支持逐步引入，非侵入式改造
> 5. **高内聚低耦合**：子应用内高度内聚，子应用间低耦合
>
> **知识点**：微前端设计原则
> **难度**：初级

**Q3：qiankun 的生命周期钩子有哪些？**

> **答案**：qiankun 提供三个生命周期钩子：
> - `bootstrap`：子应用首次加载时调用，仅执行一次，用于初始化全局资源
> - `mount`：每次进入子应用时调用，用于挂载应用到 DOM
> - `unmount`：每次离开子应用时调用，用于卸载并清理资源
>
> **知识点**：qiankun 生命周期
> **难度**：初级

### 中级面试题

**Q4：qiankun 是如何实现 JS 沙箱的？**

> **答案**：qiankun 提供两种 JS 沙箱模式：
>
> **SnapshotSandbox（快照沙箱）**：
> - 兼容不支持 Proxy 的浏览器
> - 在子应用激活时记录 window 快照，卸载时恢复快照
> - 缺点：遍历 window 属性，性能较差
>
> **ProxySandbox（代理沙箱）**：
> - 基于 ES6 Proxy 实现
> - 为每个子应用创建独立的 fakeWindow
> - 对 window 的读写操作进行拦截和隔离
> - 支持多子应用同时运行
> - 性能优于快照沙箱
>
> **知识点**：JS 沙箱、Proxy、作用域隔离
> **难度**：中级

**Q5：微前端中子应用间如何通信？**

> **答案**：主要有以下几种方式：
> 1. **全局事件总线**：基于 pub/sub 模式，子应用间通过事件进行松耦合通信
> 2. **全局状态管理**：通过 qiankun 的 `initGlobalState` 实现跨应用状态共享
> 3. **URL 参数传递**：页面跳转时通过 URL 参数传递数据
> 4. **localStorage / sessionStorage**：持久化数据共享
> 5. **共享 API 服务**：通过后端接口获取共享数据
>
> 推荐使用事件总线 + 全局状态管理的组合方案。
>
> **知识点**：微前端通信、事件总线、状态管理
> **难度**：中级

**Q6：微前端如何处理样式隔离？**

> **答案**：三种方式：
> 1. **Shadow DOM**（`strictStyleIsolation: true`）：将子应用包裹在 Shadow DOM 中，样式完全隔离，但可能影响弹窗等挂载到 body 的组件
> 2. **CSS Scope**（`experimentalStyleIsolation: true`）：为子应用样式添加特殊作用域前缀，如 `div[data-qiankun="app-name"]`
> 3. **约定规范**：使用 CSS Modules、BEM 命名、CSS-in-JS 等方式手动避免冲突
>
> **知识点**：样式隔离、Shadow DOM、CSS Modules
> **难度**：中级

**Q7：Module Federation 与 qiankun 的区别是什么？**

> **答案**：
>
> | 维度 | Module Federation | qiankun |
> |------|-------------------|---------|
> | 实现原理 | Webpack 运行时模块共享 | 基于 single-spa 的应用编排 |
> | 中心化 | 去中心化，无需基座 | 中心化，需要基座应用 |
> | 粒度 | 模块级共享 | 应用级整合 |
> | JS 沙箱 | 无内置沙箱 | 内置 Proxy 沙箱 |
> | 样式隔离 | 需自行处理 | 内置样式隔离 |
> | 构建工具 | 仅 Webpack 5 | 不限构建工具 |
> | 学习成本 | 中 | 低 |
>
> **知识点**：Module Federation、qiankun 对比
> **难度**：中级

### 高级面试题

**Q8：微前端架构中如何处理公共依赖？如何避免重复加载？**

> **答案**：
> 1. **external 配置**：将公共依赖（如 Vue、React、element-plus）设为 external，通过 CDN 或 importmap 统一引入
> 2. **Module Federation 共享**：通过 `shared` 配置声明共享依赖，Webpack 自动处理版本协商
> 3. **依赖版本统一**：在 monorepo 中通过 `pnpm overrides` 统一依赖版本
> 4. **手动注入**：基座将公共依赖挂载到 window，子应用检测并使用
> 5. **importmap**：浏览器原生模块映射，所有应用共享同一模块实例
>
> ```json
> // importmap 示例
> {
>   "imports": {
>     "vue": "https://cdn.example.com/vue@3.4.0/dist/vue.runtime.esm.js",
>     "vue-router": "https://cdn.example.com/vue-router@4.3.0/dist/vue-router.esm.js"
>   }
> }
> ```
>
> **知识点**：公共依赖管理、external、Module Federation
> **难度**：高级

**Q9：如何设计一个微前端的灰度发布方案？**

> **答案**：
> 1. **入口层灰度**：Nginx 根据 cookie 或 header 将用户路由到不同版本的子应用
> 2. **版本配置中心**：基座从配置中心获取子应用版本映射，按用户 ID hash 分配版本
> 3. **多版本共存**：CDN 上同时保留多个版本的子应用静态资源
> 4. **流量策略**：支持按比例、按用户分组、按地域等多种灰度策略
> 5. **快速回滚**：配置中心一键切换版本映射，无需重新部署
>
> ```typescript
> // 灰度策略示例
> function getAppEntry(appName: string, userId: string): string {
>   const grayConfig = await fetchGrayConfig(appName);
>   const hash = hashString(userId);
>   if (hash % 100 < grayConfig.percentage) {
>     return grayConfig.grayEntry; // 灰度版本
>   }
>   return grayConfig.stableEntry; // 稳定版本
> }
> ```
>
> **知识点**：灰度发布、版本管理、配置中心
> **难度**：高级

**Q10：微前端架构下如何保证应用的整体性能和用户体验？**

> **答案**：
> 1. **预加载策略**：利用 `requestIdleCallback` 在浏览器空闲时预加载子应用资源
> 2. **公共依赖提取**：将 Vue、React 等公共依赖提取为 external，避免重复加载
> 3. **缓存策略**：子应用资源使用强缓存 + hash 文件名，HTML 使用协商缓存
> 4. **骨架屏与 Loading**：子应用加载时展示骨架屏，提升感知性能
> 5. **keep-alive 缓存**：对频繁切换的子应用使用 keep-alive 保持状态
> 6. **按需加载**：子应用内部路由懒加载，减少首屏体积
> 7. **CDN 加速**：所有静态资源部署到 CDN，利用边缘节点加速
> 8. **性能监控**：接入 Web Vitals 监控，持续优化 LCP、FID、CLS
>
> **知识点**：性能优化、预加载、缓存策略
> **难度**：高级

**Q11：微前端架构中如何处理跨应用的路由跳转和参数传递？**

> **答案**：
> 1. **路由设计**：基座统一管理一级路由，子应用管理二级及以下路由
> 2. **路径前缀隔离**：如 `/app/user/*` → 用户管理，`/app/order/*` → 订单管理
> 3. **统一路由跳转**：提供全局路由跳转方法，自动处理前缀拼接
> 4. **参数传递方式**：
>    - URL query 参数：`/app/order/detail?id=123`
>    - 全局状态：通过 `setGlobalState` 传递
>    - 事件总线：`eventBus.emit('navigate', { path, params })`
> 5. **路由守卫**：基座统一处理权限校验，子应用处理内部鉴权
>
> ```typescript
> // 全局路由跳转方法
> export function navigateTo(target: string, params?: Record<string, string>) {
>   const { appName, path } = parseTarget(target);
>   const app = microApps.find(app => app.name === appName);
>   const query = params ? '?' + new URLSearchParams(params).toString() : '';
>   router.push(`${app.activeRule}${path}${query}`);
> }
> ```
>
> **知识点**：路由设计、跨应用导航
> **难度**：高级

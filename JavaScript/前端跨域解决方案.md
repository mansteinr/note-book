## 一、跨域问题概述

### 1.1 什么是跨域？

**同源策略（Same-Origin Policy）** 是浏览器最核心的安全机制。当两个 URL 的**协议、域名、端口**三者完全一致时，才属于同源。

| 对比项 | URL A | URL B | 是否同源 | 原因 |
|--------|-------|-------|----------|------|
| 案例 1 | `http://a.com/path` | `http://a.com/other` | ✅ 同源 | 仅路径不同 |
| 案例 2 | `http://a.com` | `https://a.com` | ❌ 跨域 | 协议不同 |
| 案例 3 | `http://a.com` | `http://b.com` | ❌ 跨域 | 域名不同 |
| 案例 4 | `http://a.com:80` | `http://a.com:8080` | ❌ 跨域 | 端口不同 |

### 1.2 同源策略的限制范围

| 允许 | 限制 |
|------|------|
| `<script src="...">` 加载外部 JS | Ajax（XMLHttpRequest / Fetch）跨域请求 |
| `<link href="...">` 加载外部 CSS | 跨域 iframe 的 DOM 访问 |
| `<img src="...">` 加载外部图片 | `localStorage` / `sessionStorage` 跨域访问 |
| `<video>` / `<audio>` 加载外部媒体 | `Cookie` 跨域读取 |
| `@font-face` 加载外部字体 | `WebSocket`（部分场景受限制） |

### 1.3 跨域方案全景图

```
跨域解决方案
├── 绕过浏览器限制
│   ├── JSONP（利用 <script> 标签）
│   └── WebSocket（独立协议，不受同源策略限制）
├── 浏览器原生支持
│   ├── CORS（服务端设置响应头）
│   ├── postMessage（跨文档通信）
│   └── document.domain（同主域子域通信）
├── 服务端中转
│   ├── 正向代理（Nginx / Node.js）
│   └── 反向代理（Nginx location 转发）
└── 其他方案
    ├── window.name
    ├── location.hash
    └── nginx 反向代理
```

## 二、JSONP

### 2.1 实现原理

JSONP（JSON with Padding）利用 `<script>` 标签不受同源策略限制的特性，通过动态创建 `<script>` 标签实现跨域数据请求。服务端返回的是一个函数调用，参数即为数据。

```
客户端                         服务端
   │                              │
   │  <script src="api?callback=cb">  │
   │──────────────────────────────>│
   │                              │
   │  cb({"name":"Tom","age":20}) │
   │<──────────────────────────────│
   │                              │
   │  执行 cb(data) 获取数据       │
```

### 2.2 完整实现

**前端代码：**

```javascript
/**
 * JSONP 封装函数
 * @param {string} url - 请求地址
 * @param {object} params - 请求参数
 * @param {string} callbackKey - 回调函数参数名（默认 'callback'）
 * @returns {Promise} - 返回 Promise 包装的响应数据
 */
function jsonp(url, params = {}, callbackKey = 'callback') {
  return new Promise((resolve, reject) => {
    // 1. 生成全局唯一的回调函数名
    const callbackName = `jsonp_${Date.now()}_${Math.random().toString(36).slice(2)}`;

    // 2. 将回调函数挂载到 window 上
    window[callbackName] = (data) => {
      resolve(data);
      cleanup();
    };

    // 3. 构建查询参数
    params[callbackKey] = callbackName;
    const queryString = Object.entries(params)
      .map(([key, value]) => `${encodeURIComponent(key)}=${encodeURIComponent(value)}`)
      .join('&');
    const scriptUrl = `${url}${url.includes('?') ? '&' : '?'}${queryString}`;

    // 4. 动态创建 script 标签
    const script = document.createElement('script');
    script.src = scriptUrl;

    // 5. 错误处理
    script.onerror = () => {
      reject(new Error(`JSONP request to ${url} failed`));
      cleanup();
    };

    // 6. 超时处理
    const timeout = setTimeout(() => {
      reject(new Error(`JSONP request to ${url} timed out`));
      cleanup();
    }, 10000);

    // 7. 清理函数
    function cleanup() {
      clearTimeout(timeout);
      if (script.parentNode) {
        script.parentNode.removeChild(script);
      }
      delete window[callbackName];
    }

    // 8. 插入 DOM，发起请求
    document.head.appendChild(script);
  });
}

// 使用示例
jsonp('https://api.example.com/user', { id: 123 })
  .then(data => console.log('获取数据:', data))
  .catch(err => console.error('请求失败:', err));
```

**服务端（Node.js Express）：**

```javascript

  const callbackName = req.query.callback;
  const userId = req.query.id;

    id: userId,
    name: 'Tom',
    age: 25,
    email: 'tom@example.com'
  };

  // 返回函数调用形式的响应
  res.setHeader('Content-Type', 'application/javascript');
  res.send(`${callbackName}(${JSON.stringify(data)})`);
});

app.listen(3000, () => {
  console.log('Server running on port 3000');
});
```

### 2.4 优缺点分析

| 维度 | 评价 | 说明 |
|------|------|------|
| 安全性 | ⚠️ 低 | 存在 XSS 风险，服务端可能被恶意注入脚本 |
| 实用性 | ⚠️ 中 | 仅支持 GET 请求，无法发送 POST/PUT/DELETE |
| 性能 | ✅ 好 | 无额外开销，请求流程简洁 |
| 错误处理 | ❌ 差 | 无法获取 HTTP 状态码，只能通过超时判断失败 |
| 适用场景 | 受限 | 仅适用于只读数据、无认证需求的简单 GET 请求 |

**优点：**

- 兼容性极好，支持所有浏览器包括 IE6+
- 不需要服务端额外配置（仅需支持 callback 参数）
- 实现简单，前端代码量少

**缺点：**

- 只支持 GET 请求，无法发送 POST 等请求
- 安全性差，容易被注入恶意代码
- 无法捕获 HTTP 错误状态码
- 不支持请求头自定义
- 不支持异步错误处理（try-catch 无效）

## 三、CORS（跨域资源共享）

### 3.1 实现原理

CORS（Cross-Origin Resource Sharing）是 W3C 标准，通过服务端设置响应头来告知浏览器允许跨域请求。浏览器根据请求类型分为**简单请求**和**预检请求**两种处理方式。

### 3.2 简单请求

**满足以下全部条件的请求为简单请求：**

| 条件 | 详细说明 |
|------|---------|
| 请求方法 | 仅限 `GET`、`HEAD`、`POST` |
| 请求头 | 仅限 Accept、Accept-Language、Content-Language、Content-Type |
| Content-Type | 仅限 `text/plain`、`multipart/form-data`、`application/x-www-form-urlencoded` |
| 其他限制 | 未使用 `ReadableStream`，未注册 `XMLHttpRequestUpload` 事件监听器 |

**前端代码（原生 Fetch）：**

```javascript
async function fetchUserData() {
  try {
    const response = await fetch('https://api.example.com/users', {
      method: 'GET',
      headers: {
        'Content-Type': 'application/x-www-form-urlencoded'
      },
      // 携带 Cookie（跨域默认不携带）
      credentials: 'include'
    });

    if (!response.ok) {
      throw new Error(`HTTP ${response.status}: ${response.statusText}`);
    }

    const data = await response.json();
    console.log('用户数据:', data);
    return data;
  } catch (error) {
    console.error('请求失败:', error);
  }
}
```

**前端代码（XMLHttpRequest）：**

```javascript
function xhrGetRequest(url) {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    xhr.open('GET', url, true);

    // 携带 Cookie
    xhr.withCredentials = true;

    xhr.onload = function() {
      if (xhr.status >= 200 && xhr.status < 300) {
        resolve(JSON.parse(xhr.responseText));
      } else {
        reject(new Error(`HTTP ${xhr.status}: ${xhr.statusText}`));
      }
    };

    xhr.onerror = function() {
      reject(new Error('Network error'));
    };

    xhr.send();
  });
}
```

**服务端响应头（简单请求只需设置）：**

```javascript
// Node.js Express
app.get('/users', (req, res) => {
  // 允许指定源（生产环境应指定具体域名，而非 *）
  res.setHeader('Access-Control-Allow-Origin', 'https://www.example.com');
  // 允许携带 Cookie
  res.setHeader('Access-Control-Allow-Credentials', 'true');
  // 允许客户端读取的响应头
  res.setHeader('Access-Control-Expose-Headers', 'X-Total-Count, X-Custom-Header');

  const users = [
    { id: 1, name: 'Tom' },
    { id: 2, name: 'Jerry' }
  ];
  res.json(users);
});
```

### 3.3 预检请求（Preflight Request）

不满足简单请求条件的请求（如 `Content-Type: application/json`、`PUT`/`DELETE` 方法、自定义请求头），浏览器会先发送一个 **OPTIONS** 预检请求，询问服务端是否允许，通过后才发送实际请求。

```
客户端                         服务端
   │                              │
   │  OPTIONS /api/users          │  ← 预检请求（Preflight）
   │  (Access-Control-Request-...)  │
   │──────────────────────────────>│
   │                              │
   │  HTTP 204                    │  ← 预检响应
   │  (Access-Control-Allow-...)  │
   │<──────────────────────────────│
   │                              │
   │  PUT /api/users              │  ← 实际请求
   │  Content-Type: application/json│
   │──────────────────────────────>│
   │                              │
   │  HTTP 200                    │  ← 实际响应
   │<──────────────────────────────│
```

**前端代码（触发预检的请求）：**

```javascript
async function updateUser(userId, userData) {
  try {
    const response = await fetch(`https://api.example.com/users/${userId}`, {
      method: 'PUT',                        // 非简单方法，触发预检
      headers: {
        'Content-Type': 'application/json', // 触发预检
        'X-Custom-Token': 'abc123'          // 自定义头，触发预检
      },
      credentials: 'include',
      body: JSON.stringify(userData)
    });

    const data = await response.json();
    return data;
  } catch (error) {
    console.error('更新失败:', error);
    throw error;
  }
}
```

**服务端完整 CORS 配置（处理预检）：**

```javascript
// Node.js Express 完整 CORS 中间件
app.use((req, res, next) => {
  const allowedOrigins = ['https://www.example.com', 'https://admin.example.com'];
  const origin = req.headers.origin;

  // 动态设置允许的源
  if (allowedOrigins.includes(origin)) {
    res.setHeader('Access-Control-Allow-Origin', origin);
  }

  // 允许携带 Cookie（此时 Allow-Origin 不能为 *）
  res.setHeader('Access-Control-Allow-Credentials', 'true');

  // 允许的请求方法
  res.setHeader('Access-Control-Allow-Methods', 'GET, POST, PUT, DELETE, PATCH, OPTIONS');

  // 允许的请求头
  res.setHeader('Access-Control-Allow-Headers', 'Content-Type, Authorization, X-Custom-Token');

  // 预检请求缓存时间（秒），减少预检频率
  res.setHeader('Access-Control-Max-Age', '86400');

  // 允许客户端读取的响应头
  res.setHeader('Access-Control-Expose-Headers', 'X-Total-Count, X-Request-Id');

  // OPTIONS 预检请求直接返回 204
  if (req.method === 'OPTIONS') {
    return res.sendStatus(204);
  }

  next();
});
```

```java
        }

    }
```
```javascript
}
```

### 3.5 优缺点分析

| 维度 | 评价 | 说明 |
|------|------|------|
| 安全性 | ✅ 高 | 服务端精确控制允许的源、方法、头，是 W3C 标准 |

**优点：**

- W3C 标准，浏览器原生支持
- 支持所有 HTTP 方法
- 服务端精确控制，安全性高
- 支持自定义请求头和 Cookie 携带

**缺点：**

- 非简单请求有额外预检开销
- 需要服务端配合配置
- IE8/IE9 支持不完整，需要特殊处理
- `Access-Control-Allow-Origin` 设为 `*` 时无法携带 Cookie

## 四、WebSocket

### 4.1 实现原理

WebSocket 是 HTML5 的独立协议（`ws://` / `wss://`），它不受浏览器同源策略限制。WebSocket 请求头中会携带 `Origin` 字段，服务端可通过验证 `Origin` 来决定是否建立连接。

```
客户端（ws://client.com）              服务端（ws://server.com）
   │                                        │
   │  HTTP Upgrade 请求                      │
   │  Origin: http://client.com              │
   │────────────────────────────────────────>│
   │                                        │
   │  HTTP 101 Switching Protocols          │
   │<────────────────────────────────────────│
   │                                        │
   │  ===== WebSocket 连接建立 =====          │
   │                                        │
   │  双向通信，全双工                         │
   │<───────────────────────────────────────>│
```

### 4.2 完整实现

**前端代码：**

```javascript
class WebSocketClient {
  constructor(url, options = {}) {
    this.url = url;
    this.ws = null;
    this.reconnectInterval = options.reconnectInterval || 3000;
    this.maxReconnectAttempts = options.maxReconnectAttempts || 5;
    this.reconnectAttempts = 0;
    this.listeners = new Map();
    this.connect();
  }

  // 连接 WebSocket
  connect() {
    this.ws = new WebSocket(this.url);

    this.ws.onopen = () => {
      console.log('WebSocket 连接已建立');
      this.reconnectAttempts = 0;
      this.emit('open');
    };

    this.ws.onmessage = (event) => {
      try {
        const data = JSON.parse(event.data);
        console.log('收到消息:', data);
        this.emit('message', data);
      } catch (e) {
        this.emit('message', event.data);
      }
    };

    this.ws.onerror = (error) => {
      console.error('WebSocket 错误:', error);
      this.emit('error', error);
    };

    this.ws.onclose = (event) => {
      console.log(`WebSocket 连接关闭: code=${event.code}, reason=${event.reason}`);
      this.emit('close', event);
      this.attemptReconnect();
    };
  }

  // 发送消息
  send(data) {
    if (this.ws && this.ws.readyState === WebSocket.OPEN) {
      const payload = typeof data === 'string' ? data : JSON.stringify(data);
      this.ws.send(payload);
    } else {
      console.warn('WebSocket 未连接，无法发送消息');
    }
  }

  // 关闭连接
  close(code = 1000, reason = '') {
    this.reconnectAttempts = this.maxReconnectAttempts; // 阻止重连
    if (this.ws) {
      this.ws.close(code, reason);
    }
  }

  // 事件监听
  on(event, callback) {
    if (!this.listeners.has(event)) {
      this.listeners.set(event, []);
    }
    this.listeners.get(event).push(callback);
  }

  // 触发事件
  emit(event, ...args) {
    const callbacks = this.listeners.get(event) || [];
    callbacks.forEach(cb => cb(...args));
  }

  // 自动重连
  attemptReconnect() {
    if (this.reconnectAttempts >= this.maxReconnectAttempts) {
      console.log('达到最大重连次数，停止重连');
      return;
    }
    this.reconnectAttempts++;
    console.log(`第 ${this.reconnectAttempts} 次重连，等待 ${this.reconnectInterval}ms...`);
    setTimeout(() => this.connect(), this.reconnectInterval);
  }
}

// 使用示例
const ws = new WebSocketClient('wss://api.example.com/ws', {
  reconnectInterval: 5000,
  maxReconnectAttempts: 3
});

ws.on('open', () => {
  ws.send({ type: 'subscribe', channel: 'news' });
});

ws.on('message', (data) => {
  console.log('收到推送:', data);
  // 更新 UI
});

ws.on('error', (error) => {
  console.error('连接错误:', error);
});

ws.on('close', (event) => {
  console.log('连接已关闭');
});
```

**服务端（Node.js ws 库）：**

```javascript
const WebSocket = require('ws');

const wss = new WebSocket.Server({ port: 8080 });

// 验证 Origin 实现跨域访问控制
wss.on('connection', (ws, req) => {
  const origin = req.headers.origin;
  const allowedOrigins = ['https://www.example.com', 'https://admin.example.com'];

  // 验证来源
  if (!allowedOrigins.includes(origin)) {
    console.log(`拒绝来自 ${origin} 的连接`);
    ws.close(4001, 'Origin not allowed');
    return;
  }

  console.log(`新连接来自: ${origin}`);
  console.log(`当前连接数: ${wss.clients.size}`);

  // 接收消息
  ws.on('message', (data) => {
    try {
      const message = JSON.parse(data);
      console.log('收到:', message);

      // 处理订阅
      if (message.type === 'subscribe') {
        ws.channel = message.channel;
        ws.send(JSON.stringify({
          type: 'subscribed',
          channel: message.channel
        }));
      }
    } catch (e) {
      console.error('消息解析错误:', e);
    }
  });

  // 发送欢迎消息
  ws.send(JSON.stringify({
    type: 'connected',
    message: '连接成功',
    timestamp: Date.now()
  }));

  // 心跳检测
  ws.isAlive = true;
  ws.on('pong', () => { ws.isAlive = true; });

  ws.on('close', (code, reason) => {
    console.log(`连接关闭: ${code} - ${reason}`);
  });
});

// 广播消息
function broadcast(data) {
  wss.clients.forEach((client) => {
    if (client.readyState === WebSocket.OPEN) {
      client.send(JSON.stringify(data));
    }
  });
}

// 心跳检测定时器
const heartbeat = setInterval(() => {
  wss.clients.forEach((ws) => {
    if (!ws.isAlive) {
      return ws.terminate();
    }
    ws.isAlive = false;
    ws.ping();
  });
}, 30000);

wss.on('close', () => clearInterval(heartbeat));
```

## 五、代理服务器

### 5.1 实现原理

## 六、postMessage

### 6.1 实现原理

`postMessage` 是 HTML5 提供的跨文档通信 API，允许不同源的窗口（iframe、弹出窗口、Worker）之间安全地传递消息。

```
父页面（http://a.com）              iframe（http://b.com）
   │                                    │
   │  iframe.postMessage(data, 'http://b.com')  │
   │───────────────────────────────────>│
   │                                    │
   │                                    │  window.addEventListener('message')
   │  window.addEventListener('message')│
   │                                    │
   │  parent.postMessage(data, 'http://a.com')  │
   │<───────────────────────────────────│
```

### 6.2 完整实现

**父页面（http://parent.com）：**

```html
<!DOCTYPE html>
<html>
<head>
  <title>父页面</title>
</head>
<body>
  <h1>父页面 (http://parent.com)</h1>

  <button onclick="sendMessage()">发送消息给 iframe</button>
  <div id="response"></div>

  <iframe
    id="childFrame"
    src="http://child.com/child.html"
    width="400"
    height="300"
  ></iframe>

  <script>
    const iframe = document.getElementById('childFrame');
    const responseDiv = document.getElementById('response');

    // 监听来自 iframe 的消息
    window.addEventListener('message', (event) => {
      // 安全校验：验证消息来源
      if (event.origin !== 'http://child.com') {
        console.warn('拒绝来自未知源的消息:', event.origin);
        return;
      }

      console.log('收到 iframe 消息:', event.data);

      if (event.data.type === 'response') {
        responseDiv.textContent = `子页面回复: ${event.data.payload}`;
      }
    });

    // 发送消息给 iframe
    function sendMessage() {
      iframe.contentWindow.postMessage(
        {
          type: 'request',
          payload: 'Hello from parent',
          timestamp: Date.now()
        },
        'http://child.com' // 指定目标源，增强安全性
      );
    }

    // iframe 加载完成后发送消息
    iframe.addEventListener('load', () => {
      iframe.contentWindow.postMessage(
        { type: 'init', payload: 'Parent page loaded' },
        'http://child.com'
      );
    });
  </script>
```

```html
</html>
```

### 6.3 跨域通信封装

```javascript
/**
 * 安全的跨域消息通信封装
 */
class CrossOriginMessenger {
  constructor(targetWindow, targetOrigin) {
    this.targetWindow = targetWindow;
    this.targetOrigin = targetOrigin;
    this.allowedOrigins = new Set([targetOrigin]);
    this.listeners = new Map();
    this.pendingRequests = new Map();

    window.addEventListener('message', this._handleMessage.bind(this));
  }

  // 发送消息
  send(type, payload) {
    const message = { type, payload, id: this._generateId() };
    this.targetWindow.postMessage(message, this.targetOrigin);
    return message.id;
  }

  // 发送请求并等待响应（类似 RPC）
  request(type, payload, timeout = 5000) {
    return new Promise((resolve, reject) => {
      const id = this._generateId();
      const message = { type, payload, id, isRequest: true };

      const timer = setTimeout(() => {
        this.pendingRequests.delete(id);
        reject(new Error(`Request ${type} timed out`));
      }, timeout);

      this.pendingRequests.set(id, { resolve, reject, timer });
      this.targetWindow.postMessage(message, this.targetOrigin);
    });
  }

  // 监听消息类型
  on(type, handler) {
    if (!this.listeners.has(type)) {
      this.listeners.set(type, []);
    }
    this.listeners.get(type).push(handler);
  }

  // 添加允许的源
  allowOrigin(origin) {
    this.allowedOrigins.add(origin);
  }

  // 处理接收到的消息
  _handleMessage(event) {
    if (!this.allowedOrigins.has(event.origin)) {
      console.warn(`拒绝来自 ${event.origin} 的消息`);
      return;
    }

    const { type, payload, id, isRequest } = event.data;

    // 处理响应
    if (id && this.pendingRequests.has(id)) {
      const { resolve, timer } = this.pendingRequests.get(id);
      clearTimeout(timer);
      this.pendingRequests.delete(id);
      resolve(payload);
      return;
    }

    // 处理请求
    if (isRequest) {
      const handlers = this.listeners.get(type) || [];
      Promise.all(handlers.map(h => h(payload))).then((results) => {
        this.targetWindow.postMessage(
          { type: `${type}:response`, payload: results[0], id },
          this.targetOrigin
        );
      });
      return;
    }

    // 触发事件监听器
    const handlers = this.listeners.get(type) || [];
    handlers.forEach(handler => handler(payload));
  }

  _generateId() {
    return `${Date.now()}_${Math.random().toString(36).slice(2, 9)}`;
  }

  // 销毁
  destroy() {
    window.removeEventListener('message', this._handleMessage);
    this.pendingRequests.forEach(({ timer, reject }) => {
      clearTimeout(timer);
      reject(new Error('Messenger destroyed'));
    });
    this.pendingRequests.clear();
    this.listeners.clear();
  }
}

// 使用示例
const messenger = new CrossOriginMessenger(
  iframe.contentWindow,
  'http://child.com'
);

messenger.on('userData', (data) => {
  console.log('收到子页面用户数据:', data);
});

// 发送请求并等待响应
messenger.request('getUserInfo', { userId: 123 })
  .then(userInfo => console.log('获取到用户信息:', userInfo))
  .catch(err => console.error('请求失败:', err));
```

## 七、document.domain

### 7.1 实现原理

`document.domain` 用于解决**主域相同、子域不同**的页面间跨域问题。将两个页面的 `document.domain` 设置为相同的主域后，即可互相访问 DOM。

```
场景：a.example.com 和 b.example.com 需要通信
主域：example.com
```

### 7.2 完整实现

**页面 A（http://a.example.com/pageA.html）：**

```html
<!DOCTYPE html>
<html>
<head>
  <title>页面 A</title>
</head>
<body>
  <h1>页面 A (a.example.com)</h1>

  <button onclick="accessIframe()">访问 iframe 中的 DOM</button>
  <div id="result"></div>

  <iframe id="frameB" src="http://b.example.com/pageB.html"></iframe>

  <script>
    // 设置主域（两个页面都必须设置）
    document.domain = 'example.com';

    function accessIframe() {
      const iframe = document.getElementById('frameB');
      try {
        // 现在可以访问 iframe 的 DOM
        const title = iframe.contentDocument.querySelector('h1').textContent;
        const data = iframe.contentWindow.getSharedData();

        document.getElementById('result').textContent =
          `iframe 标题: ${title}, 共享数据: ${data}`;
      } catch (e) {
        console.error('访问失败:', e);
        document.getElementById('result').textContent = '访问失败: ' + e.message;
      }
    }
  </script>
</body>
</html>
```

**页面 B（http://b.example.com/pageB.html）：**

```html
<!DOCTYPE html>
<html>
<head>
  <title>页面 B</title>
</head>
<body>
  <h1>页面 B (b.example.com)</h1>
  <div id="shared-data">共享数据区域</div>

  <script>
    // 设置主域
    document.domain = 'example.com';

    // 暴露共享方法
    function getSharedData() {
      return 'Shared data from b.example.com';
    }

    // 也可以访问父页面的 DOM
    function updateParent() {
      try {
        window.parent.document.getElementById('result').textContent =
          '由子页面 B 更新';
      } catch (e) {
        console.error('更新父页面失败:', e);
      }
    }
  </script>
</body>
</html>
```

### 7.3 限制与注意事项

| 限制项 | 说明 |
|--------|------|
| 端口限制 | 两个页面必须使用相同端口，或一个端口为 `null`（默认端口） |
| 设置范围 | 只能设置为当前域名的父域，不能设置为顶级域或完全不同域 |
| 单向设置 | 两个页面都必须设置 `document.domain`，仅一方设置无效 |
| 安全性 | 设置后，子域可能被其他同主域的子域访问 |
| 现代替代 | 推荐使用 `postMessage` 替代，`document.domain` 已逐步被废弃 |

**无法使用 `document.domain` 的场景：**

```
❌ a.example.com 和 b.other.com         → 主域不同
❌ a.example.com:3000 和 a.example.com:4000  → 端口不同
❌ 设置 document.domain = 'com'         → 不能设置为顶级域
```

### 7.4 优缺点分析

| 维度 | 评价 | 说明 |
|------|------|------|
| 安全性 | ❌ 低 | 设置后子域间可互相访问，存在安全风险 |
| 实用性 | ⚠️ 低 | 仅限同主域子域间通信，现代项目已不推荐 |
| 性能 | ✅ 好 | 无额外开销 |
| 适用场景 | 受限 | 旧项目维护、同主域子域页面通信 |

**优点：**

- 实现简单，一行代码即可
- 设置后可直接访问对方 DOM 和全局变量

**缺点：**

- 安全性差，可能被恶意子域利用
- 仅限同主域子域，应用场景极窄
- 所有子域间的隔离被打破
- 正在被逐步废弃，不推荐新项目使用

## 八、其他跨域方案

### 8.1 window.name

`window.name` 属性在不同页面间跳转时保持不变（最大 2MB），可利用此特性实现跨域数据传输。

```html
<!-- 页面 A (http://a.com) -->
<script>
  // 1. 在 a.com 下，将数据写入 iframe 的 window.name
  const iframe = document.createElement('iframe');
  iframe.style.display = 'none';

  iframe.onload = function() {
    // 2. 数据已写入，切换 iframe 到同源页面
    iframe.contentWindow.location = 'http://a.com/proxy.html';
  };

  // 先加载跨域页面写入数据
  iframe.src = 'http://b.com/data.html';
  document.body.appendChild(iframe);
</script>
```

```html
<!-- 数据页面 (http://b.com/data.html) -->
<script>
  // 将数据写入 window.name
  window.name = JSON.stringify({
    user: 'Tom',
    token: 'abc123'
  });
</script>
```

```html
<!-- 代理页面 (http://a.com/proxy.html) —— 同源，可读取 window.name -->
<script>
  // 此时 iframe 已经是同源，可以读取 window.name
  const data = window.name;
  window.parent.postMessage(data, 'http://a.com');
</script>
```

**局限性：** 实现复杂，需要同源代理页面，已被 `postMessage` 完全取代。

### 8.2 location.hash

通过修改 URL 的 hash 片段在不同源的 iframe 间传递数据（最大 URL 长度限制）。

```html
<!-- 页面 A (http://a.com) -->
<script>
  const iframe = document.createElement('iframe');
  iframe.src = 'http://b.com/page.html#data=hello';
  document.body.appendChild(iframe);

  // 监听 hash 变化
  window.onhashchange = function() {
    const data = location.hash.substring(1);
    console.log('收到数据:', data);
  };
</script>
```

**局限性：** 数据量受 URL 长度限制，只能单向传递，已不推荐使用。

### 8.3 nginx 反向代理

生产环境最常用的方案，将前端静态资源和后端 API 统一部署在同一域名下：

```nginx
server {
    listen 80;
    server_name www.example.com;

    # 前端静态资源
    location / {
        root /var/www/dist;
        try_files $uri $uri/ /index.html;
    }

    # 后端 API 代理
    location /api/ {
        proxy_pass http://localhost:8080/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### 8.4 nginx 正向代理（开发阶段）

```nginx
server {
    listen 80;
    server_name proxy.local;

    location /api/ {
        proxy_pass https://api.example.com/;
        proxy_set_header Host api.example.com;
    }
}
```

## 十、最佳实践建议

### 10.1 按场景推荐方案

```
┌─────────────────────────────────────────────────┐
│              前端跨域方案选择决策树                │
├─────────────────────────────────────────────────┤
│                                                   │
│  需要跨域通信？                                    │
│  ├── 前后端 API 调用                               │
│  │   ├── 生产环境 ───→ nginx 反向代理 + CORS       │
│  │   └── 开发环境 ───→ Vite/Webpack 代理           │
│  │                                                   │
│  ├── 实时通信（推送/聊天/协作）                      │
│  │   └──→ WebSocket + 服务端 Origin 验证            │
│  │                                                   │
│  ├── iframe 跨域通信                                │
│  │   └──→ postMessage + Origin 验证                 │
│  │                                                   │
│  ├── 同主域子域间通信（旧项目）                      │
│  │   └──→ postMessage（推荐）                       │
│  │       document.domain（不推荐，仅兼容旧代码）      │
│  │                                                   │
│  └── 第三方 API 调用（无服务端控制权）                │
│      ├── 对方支持 CORS ──→ CORS                     │
│      ├── 对方支持 JSONP ──→ JSONP（仅 GET）          │
│      └── 都不支持 ──────→ 自建代理服务器             │
│                                                   │
└─────────────────────────────────────────────────┘
```

### 10.2 安全最佳实践

| 实践 | 说明 |
|------|------|
| 精确指定 Origin | CORS 不使用 `*`，明确列出允许的域名 |
| 验证消息来源 | postMessage 始终验证 `event.origin` |
| 验证 WebSocket Origin | 服务端验证 `Origin` 请求头 |
| 使用 HTTPS | 生产环境强制 HTTPS，避免中间人攻击 |
| 最小权限原则 | 仅开放必要的 HTTP 方法和请求头 |
| 敏感接口额外认证 | 跨域接口配合 Token/Session 认证 |

### 10.3 开发与生产环境统一策略

```
开发环境：
  Vite proxy / Webpack devServer proxy
  → 前端本地开发，代理转发到后端 API

测试环境：
  nginx 反向代理 + CORS 配置
  → 模拟生产部署方式

生产环境：
  nginx 反向代理（同域部署）
  → 前端静态资源与 API 同域，天然无跨域
  + CORS 配置（应对第三方跨域调用）
```

### 10.4 常见问题排查清单

| 问题 | 排查方向 |
|------|---------|
| CORS 报错但服务端已配置 | 检查预检请求是否返回正确响应头，检查 `Access-Control-Allow-Origin` 值是否与请求 Origin 匹配 |
| 携带 Cookie 失败 | 检查 `withCredentials: true` 且 `Allow-Origin` 不能为 `*`，`Allow-Credentials: true` |
| 自定义头被拦截 | 检查 `Access-Control-Allow-Headers` 是否包含该自定义头 |
| JSONP 回调未执行 | 检查回调函数是否在 script 加载前已挂载到 window |
| postMessage 收不到消息 | 检查 `targetOrigin` 参数是否正确，检查 `event.origin` 验证逻辑 |
| WebSocket 连接失败 | 检查代理/负载均衡器是否支持 WebSocket 协议升级 |

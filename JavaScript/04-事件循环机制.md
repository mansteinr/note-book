# JavaScript 事件循环机制面试题

## 一、核心概念解析

### 1. 为什么 JavaScript 是单线程的？

JavaScript 的主要用途之一是操作 DOM，如果在多线程环境下，一个线程在某个 DOM 节点上添加内容，另一个线程删除了该节点，就会产生冲突。因此 JavaScript 选择使用**单线程模型**，通过**事件循环（Event Loop）** 来实现异步非阻塞。

### 2. 事件循环核心组件

```
┌─────────────────────────────────────────────────────┐
│                  Event Loop                          │
├─────────────────────────────────────────────────────┤
│  ┌──────────────────┐     ┌───────────────────────┐ │
│  │   Call Stack     │     │     Task Queues       │ │
│  │   (调用栈)       │     │                       │ │
│  └──────────────────┘     │  ┌─────────────────┐  │ │
│          │                │  │  Micro Task     │  │ │
│          ▼                │  │  微任务队列      │  │ │
│  ┌──────────────────┐     │  │ - Promise.then  │  │ │
│  │   Web APIs       │     │  │ - queueMicrotask│  │ │
│  │  - setTimeout    │     │  │ - MutationObser │  │ │
│  │  - DOM Events    │     │  └─────────────────┘  │ │
│  │  - fetch / AJAX  │     │  ┌─────────────────┐  │ │
│  │  - setInterval   │     │  │  Macro Task     │  │ │
│  └──────────────────┘     │  │  宏任务队列      │  │ │
│          │                │  │ - setTimeout    │  │ │
│          ▼                │  │ - setInterval   │  │ │
│  ┌──────────────────┐     │  │ - I/O           │  │ │
│  │   Callback Queue │     │  │ - UI rendering  │  │ │
│  └──────────────────┘     │  └─────────────────┘  │ │
└─────────────────────────────────────────────────────┘
```

### 3. 事件循环执行顺序

```
每次事件循环（Tick）：
  1. 从宏任务队列中取出一个任务执行
  2. 执行过程中产生的微任务追加到微任务队列
  3. 宏任务执行完毕后，清空所有微任务队列
  4. 执行 UI 渲染（如果需要）
  5. 进入下一个 Tick，从宏任务队列取下一个任务
```

### 4. 宏任务 vs 微任务

| 类型 | 宏任务（MacroTask） | 微任务（MicroTask） |
|------|-------------------|-------------------|
| 来源 | 浏览器/Node.js 提供 | ECMAScript 规范 |
| 优先级 | 低 | 高（在宏任务之间执行） |
| 常见 API | `setTimeout`, `setInterval`, `setImmediate`, `I/O`, `UI 渲染` | `Promise.then/catch/finally`, `queueMicrotask`, `MutationObserver`, `process.nextTick`(Node) |

## 二、面试题

### 题目 1：基础执行顺序（基础）

#### 题干

```javascript
console.log('1');

setTimeout(function () {
  console.log('2');
  Promise.resolve().then(() => console.log('3'));
}, 0);

Promise.resolve().then(() => console.log('4'));

console.log('5');
```

#### 解题思路

1. 同步代码：`1` → `5`
2. 微任务队列：`4`
3. 宏任务队列：`setTimeout` 回调
4. 执行微任务 `4`，输出 `4`
5. 执行宏任务 `setTimeout` 回调，输出 `2`，内部注册微任务 `3`
6. 清空微任务：输出 `3`

#### 正确代码实现

```javascript
// 输出：
// 1
// 5
// 4
// 2
// 3
```

#### 知识点拓展

- 宏任务内部的微任务会在该宏任务执行完毕后立即执行，而不是等到下一个 Tick
- 微任务可以源源不断地产生新微任务，导致宏任务"饿死"

### 题目 2：async/await 执行顺序（进阶）

#### 题干

```javascript
async function async1() {
  console.log('A');
  await async2();
  console.log('B');
}

async function async2() {
  console.log('C');
}

console.log('D');
setTimeout(() => console.log('E'), 0);
async1();
new Promise(resolve => {
  console.log('F');
  resolve();
}).then(() => console.log('G'));
console.log('H');
```

#### 解题思路

`async/await` 的本质是 Promise 的语法糖：
- `async` 函数内的同步代码立即执行
- `await` 后面的代码相当于 `.then` 回调，被放入微任务队列

#### 正确代码实现

```javascript
// 输出：
// D
// A
// C
// F
// H
// B
// G
// E

// 执行流程分析：
// 1. 同步：console.log('D') → D
// 2. 同步：setTimeout 回调 → 宏任务队列: [E]
// 3. 同步：async1() 调用
//    - 同步：console.log('A') → A
//    - 同步：await async2() → 执行 async2
//      - 同步：console.log('C') → C
//    - await 后面的代码注册为微任务：B
// 4. 同步：new Promise 构造器中的代码
//    - 同步：console.log('F') → F
//    - resolve() 后 .then(G) 注册为微任务
// 5. 同步：console.log('H') → H
// 6. 微任务队列: [B, G]
// 7. 执行 B → B
// 8. 执行 G → G
// 9. 宏任务队列: [E] → 执行 E → E
```

#### 知识点拓展

- `await` 相当于 `Promise.resolve().then()`，但 `await` 后面的代码是作为微任务执行的
- `async` 函数返回一个 Promise，`await` 会暂停执行直到 Promise 决议
- 注意：`await` 后面如果是普通值，会被 `Promise.resolve()` 包装

### 题目 3：微任务递归产生（进阶）

#### 题干

```javascript
setTimeout(() => console.log('A'), 0);

Promise.resolve()
  .then(() => {
    console.log('B');
    // 递归注册微任务
    return Promise.resolve().then(() => {
      console.log('C');
      return Promise.resolve().then(() => {
        console.log('D');
      });
    });
  })
  .then(() => console.log('E'));

console.log('F');
```

#### 解题思路

1. 同步代码：`F`
2. 宏任务：`setTimeout(A)` 进入宏任务队列
3. 微任务：第一个 `.then`（B 及其内部链）进入微任务队列
4. 执行微任务 B，输出 `B`，内部注册 `C` 的微任务
5. 外部 `.then`（E）注册到微任务队列
6. 此时微任务队列：`[C, E]`
7. 先执行 `C`，输出 `C`，内部注册 `D` 的微任务
8. 执行 `E`，输出 `E`
9. 执行 `D`，输出 `D`
10. 宏任务：执行 `A`，输出 `A`

#### 正确代码实现

```javascript
// 输出：
// F
// B
// C
// E
// D
// A
```

#### 知识点拓展

- 微任务队列在清空过程中，新加入的微任务会在**当前 Tick 内**继续执行
- 递归微任务可能导致宏任务被无限推迟（"饿死"）
- 浏览器有微任务队列的**最大执行次数限制**，防止页面卡死

### 题目 4：requestAnimationFrame 的执行时机（进阶）

#### 题干

```javascript
console.log('1');

setTimeout(() => console.log('2'), 0);

requestAnimationFrame(() => console.log('3'));

Promise.resolve().then(() => console.log('4'));

console.log('5');
```

#### 解题思路

`requestAnimationFrame（rAF）` 的执行时机在**微任务之后、渲染之前**，而不是在宏任务队列中。执行顺序：

1. 同步代码：`1` → `5`
2. 微任务：`4`
3. **rAF 回调**：`3`（在渲染之前执行）
4. 宏任务：`2`

#### 正确代码实现

```javascript
// 输出：
// 1
// 5
// 4
// 3
// 2

// 注意：rAF 的执行时机是在渲染之前，微任务之后
// 顺序：同步 → 微任务 → rAF → 渲染 → 宏任务
```

#### 知识点拓展

- `requestAnimationFrame` 的回调在**每一帧渲染之前**执行
- 执行顺序：`微任务 → rAF → 渲染 → 宏任务`
- `rAF` 适合做动画，因为它在渲染前执行，保证动画流畅
- `rAF` 的执行频率取决于显示器刷新率（通常 60Hz）

### 题目 5：Node.js 事件循环 vs 浏览器事件循环（进阶）

#### 题干

```javascript
// Node.js 环境
const fs = require('fs');

setTimeout(() => console.log('A'), 0);
setImmediate(() => console.log('B'));

fs.readFile(__filename, () => {
  setTimeout(() => console.log('C'), 0);
  setImmediate(() => console.log('D'));
  process.nextTick(() => console.log('E'));
});
```

#### 解题思路

**Node.js 事件循环阶段（Phase）**：

```
   ┌───────────────────────────┐
┌─>│           timers          │ ← setTimeout/setInterval 回调
│  └─────────────┬─────────────┘
│  ┌─────────────▼─────────────┐
│  │     I/O callbacks         │ ← 已完成 I/O 的回调
│  └─────────────┬─────────────┘
│  ┌─────────────▼─────────────┐
│  │     idle, prepare         │ ← 内部使用
│  └─────────────┬─────────────┘
│  ┌─────────────▼─────────────┐
│  │         poll              │ ← 获取新的 I/O 事件
│  └─────────────┬─────────────┘
│  ┌─────────────▼─────────────┐
│  │         check             │ ← setImmediate 回调
│  └─────────────┬─────────────┘
│  ┌─────────────▼─────────────┐
│  │    close callbacks        │ ← close 事件回调
│  └───────────────────────────┘
```

- `process.nextTick` 在**每个阶段切换之间**执行，优先级高于微任务
- `setTimeout` 在 `timers` 阶段执行
- `setImmediate` 在 `check` 阶段执行

#### 正确代码实现

```javascript
// 第一次 A 和 B 的顺序不确定（取决于性能）
// 可能输出：A B 或 B A

// 但在 I/O 回调（fs.readFile）内部：
// D 先于 C（setImmediate 在 check 阶段，setTimeout 在下一个 timers 阶段）
// E 在 D 和 C 之前（nextTick 在阶段切换时执行）

// 输出示例：
// A 或 B（不确定）
// B 或 A（不确定）
// E
// D
// C
```

#### 知识点拓展

- `process.nextTick` 并非标准微任务，它在每个阶段之间执行，优先级高于 Promise 的微任务
- Node.js 中 `setTimeout(fn, 0)` 和 `setImmediate` 在主模块中执行顺序不确定，在 I/O 回调中 `setImmediate` 优先
- 浏览器没有 `setImmediate` 和 `process.nextTick`

### 题目 6：复杂执行顺序综合题（高阶）

#### 题干

```javascript
async function async1() {
  console.log('async1 start');
  await async2();
  console.log('async1 end');
}

async function async2() {
  console.log('async2');
}

console.log('script start');

setTimeout(function () {
  console.log('setTimeout');
}, 0);

async1();

new Promise(function (resolve) {
  console.log('promise1');
  resolve();
}).then(function () {
  console.log('promise2');
});

process.nextTick(() => console.log('nextTick'));

console.log('script end');
```

（假设为 Node.js 环境）

#### 解题思路

这是一个综合题，考察同步代码、async/await、Promise、setTimeout、process.nextTick 的综合执行顺序。

#### 正确代码实现

```javascript
// 输出（Node.js 环境）：
// script start
// async1 start
// async2
// promise1
// script end
// nextTick
// async1 end
// promise2
// setTimeout

// 执行流程分析：
// 1. 同步：console.log('script start') → script start
// 2. 同步：setTimeout → 宏任务队列: [setTimeout]
// 3. 同步：async1() 调用
//    - 同步：console.log('async1 start') → async1 start
//    - 同步：await async2() → 执行 async2
//      - 同步：console.log('async2') → async2
//    - await 后面注册微任务: async1 end
// 4. 同步：new Promise
//    - 同步：console.log('promise1') → promise1
//    - resolve() → .then(promise2) 注册微任务
// 5. 同步：process.nextTick → 注册 nextTick（优先级高于微任务）
// 6. 同步：console.log('script end') → script end
// 7. 阶段切换：process.nextTick → nextTick
// 8. 微任务：async1 end → async1 end
// 9. 微任务：promise2 → promise2
// 10. 宏任务：setTimeout → setTimeout
```

#### 知识点拓展

- Node.js 中 `process.nextTick` 优先级高于 Promise 微任务
- 浏览器中无 `process.nextTick`，对应场景用 `queueMicrotask`
- 本题是面试高频题，综合考察了所有核心概念

### 题目 7：渲染阻塞与事件循环（高阶）

#### 题干

```javascript
document.body.innerHTML = 'Start';

setTimeout(() => {
  document.body.innerHTML = 'After Timeout';
}, 0);

Promise.resolve().then(() => {
  document.body.innerHTML = 'After Microtask';
});

requestAnimationFrame(() => {
  document.body.innerHTML = 'After RAF';
});

document.body.innerHTML = 'End';
```

#### 解题思路

1. 同步代码执行时，DOM 操作不会立即渲染，而是等待当前 Tick 结束
2. 同步代码执行完毕后，页面内容为 `End`（同步代码覆盖了之前的 `Start`）
3. 微任务优先，DOM 更新为 `After Microtask`，但仍未渲染
4. rAF 在下一次渲染前执行，DOM 更新为 `After RAF`
5. 渲染时显示 `After RAF`
6. 宏任务执行，DOM 更新为 `After Timeout`
7. 下一次渲染时显示 `After Timeout`

#### 正确代码实现

```javascript
// 用户实际看到的内容：
// 初始渲染: End
// 下一帧渲染: After RAF
// 再下一帧渲染: After Timeout

// 注意：用户不会看到 Start、After Microtask 这些中间状态
// 因为渲染在微任务 + rAF 之后才发生
```

#### 知识点拓展

- 浏览器渲染时机：**微任务清空 + rAF 执行完毕后才渲染**
- 多次 DOM 修改会被合并，只触发一次渲染
- `document.body.innerHTML = 'Start'` 被后续同步代码覆盖，不会触发渲染
- 理解渲染时机对性能优化至关重要

## 三、易错点与最佳实践

### 常见易错点

| 易错点 | 说明 | 正确理解 |
|--------|------|---------|
| `setTimeout(fn, 0)` 立即执行 | 误以为 0 延迟立即执行 | 即使 0 延迟，也会进入宏任务队列，在同步代码和微任务之后执行 |
| async/await 是同步的 | 误以为 `await` 后面的代码和同步代码一样 | `await` 后面的代码是微任务，在当前同步代码执行完毕后执行 |
| 宏任务优先级高于微任务 | 误以为宏任务先执行 | 微任务优先级高于宏任务，每次宏任务执行后都会清空微任务队列 |
| `requestAnimationFrame` 在宏任务队列中 | 误以为 rAF 是宏任务 | rAF 在微任务之后、渲染之前执行，不在宏任务队列中 |
| 浏览器和 Node.js 事件循环相同 | 误以为两者完全一样 | 浏览器有渲染阶段，Node.js 有多个阶段（phase）和 `nextTick` |

### 最佳实践

```javascript
// 1. 使用 queueMicrotask 替代 Promise.resolve().then()
queueMicrotask(() => {
  // 微任务
});

// 2. 避免长时间阻塞微任务队列
// ❌ 不要这样做：微任务递归可能导致宏任务饿死
function badMicrotask() {
  queueMicrotask(badMicrotask);
}

// 3. 使用 requestAnimationFrame 做动画
function animate() {
  element.style.transform = `translateX(${x}px)`;
  requestAnimationFrame(animate);
}

// 4. 使用 requestIdleCallback 处理低优先级任务
requestIdleCallback(() => {
  // 空闲时执行，不阻塞关键操作
});

// 5. 避免在微任务中执行耗时操作
// ❌ 微任务中执行耗时操作会延迟渲染
Promise.resolve().then(() => {
  heavyComputation(); // 阻塞渲染
});
```

### 执行顺序速查表

```
优先级从高到低：

1. 同步代码（调用栈）
2. process.nextTick（Node.js 特有）
3. 微任务（Promise.then, queueMicrotask, MutationObserver）
4. requestAnimationFrame
5. 浏览器渲染（Layout + Paint）
6. 宏任务（setTimeout, setInterval, I/O, UI 事件）

在宏任务内部：
  执行宏任务 → 产生的微任务追加到队列 → 宏任务结束 → 清空所有微任务
```

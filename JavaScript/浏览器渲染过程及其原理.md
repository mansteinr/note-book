## 一、浏览器渲染概述

浏览器渲染是将 HTML、CSS、JavaScript 转换为屏幕上像素的完整过程。整个过程涉及多个阶段，形成一条严密的**渲染流水线**。

### 1.1 渲染流水线总览

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        浏览器渲染流水线全景                              │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                    📥 输入阶段                                   │   │
│  │  HTML 文档 ─── CSS 样式表 ─── JavaScript 脚本                    │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                              │                                          │
│                              ▼                                          │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                 🔍 解析阶段（渲染主线程）                        │   │
│  │  HTML 词法分析 → DOM 树构建                                      │   │
│  │  CSS 词法分析 → CSSOM 树构建                                     │   │
│  │  JS 执行（可能修改 DOM/CSSOM）                                    │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                              │                                          │
│                              ▼                                          │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                 🎨 样式阶段（渲染主线程）                        │   │
│  │  样式声明收集 → 层叠优先级计算 → 继承值传播 → 默认值填充          │   │
│  │  → 生成 Computed Style（每个节点的最终样式）                      │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                              │                                          │
│                              ▼                                          │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                 📐 布局阶段（渲染主线程）                        │   │
│  │  构建布局树 → 计算几何信息（尺寸、位置）→ 确定包含块               │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                              │                                          │
│                              ▼                                          │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                 📚 分层阶段（渲染主线程）                        │   │
│  │  图层划分 → 绘制顺序确定（z-index 排序）                          │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                              │                                          │
│                              ▼                                          │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                 🖌️ 绘制阶段（渲染主线程）                        │   │
│  │  生成绘制指令集（类似 Canvas 绘图命令序列）                        │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                              │                                          │
│                              ▼                                          │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                 ⚡ 合成阶段（合成线程 + GPU）                    │   │
│  │  分块（Tiling） → 光栅化（Raster） → 合成（Composite）            │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                              │                                          │
│                              ▼                                          │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                 🖥️ 显示阶段（GPU 进程）                          │   │
│  │  系统调用 → GPU 硬件 → 屏幕像素显示                              │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 1.3 阶段间数据传递关系

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       数据传递链                                         │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  HTML 字节流 ──→ (UTF-8 解码) ──→ 字符流                               │
│       │                                                                 │
│       ▼                                                                 │
│  Token 序列 ──→ (语法分析) ──→ DOM 节点 ──→ (树形组装) ──→ DOM 树      │

│       │                                                                 │
│       ▼                                                                 │
│  布局树 ──→ (几何计算) ──→ 带位置尺寸的布局树                          │
│       │                                                                 │
│       ▼                                                                 │
│  图层树 ──→ (绘制顺序) ──→ 绘制指令集                                  │

│       ▼                                                                 │

│       │                                                                 │
│       ▼                                                                 │
│  合成指引 ──→ (提交) ──→ GPU 进程 ──→ 屏幕显示                        │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 1.4 核心概念速查

| 阶段 | 核心产物 | 执行线程 | 说明 |
|------|---------|---------|------|
| HTML 解析 | DOM 树 | 渲染主线程 | HTML → Token → DOM 节点 → 树 |
| CSS 解析 | CSSOM 树 | 渲染主线程 | CSS → Token → 规则 → 树 |
| 样式计算 | Computed Style | 渲染主线程 | 为每个 DOM 节点计算最终样式 |
| 布局 | 布局树 | 渲染主线程 | 计算每个节点的几何信息 |
| 分层 | 图层树 | 渲染主线程 | 将布局树划分为多个图层 |
| 绘制 | 绘制指令 | 渲染主线程 | 为每个图层生成绘图命令 |
| 分块 | Tile | 合成线程 | 将图层划分为多个小块 |
| 光栅化 | 位图 | GPU 进程 | 将矢量信息转换为像素 |
| 合成 | 合成指引 | 合成线程 | 组合各图层的位图 |
| 显示 | 屏幕像素 | GPU 硬件 | 最终输出到屏幕 |

## 二、HTML 解析过程

### 2.1 HTML 解析机制与步骤

HTML 解析是将 HTML 文本转换为 DOM 树的过程，由**渲染主线程**完成。

#### 解析步骤详解

```
┌─────────────────────────────────────────────────────────────────────────┐
│                     HTML 解析四步骤                                     │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  Step 1: 字节流解码                                                     │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  HTML 字节流 ──→ (UTF-8/GBK 解码) ──→ 字符流                    │   │
│  │                                                                 │   │
│  │  示例：                                                         │   │
│  │  字节流: 3C 68 74 6D 6C 3E (hex)                               │   │
│  │    │                                                            │   │
│  │    ▼                                                            │   │
│  │  字符流: <html>                                                 │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  Step 2: 词法分析（Tokenization）                                       │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  字符流 ──→ (状态机逐字符分析) ──→ Token 序列                    │   │
│  │                                                                 │   │
│  │  Token 类型：                                                   │   │
│  │  - StartTag:   <div>    → { type: 'start', name: 'div' }       │   │
│  │  - EndTag:     </div>   → { type: 'end', name: 'div' }        │   │
│  │  - AttrName:   class    → { type: 'attr', name: 'class' }     │   │
│  │  - AttrValue:  'container' → { type: 'text', value: 'container'}│   │
│  │  - Characters: '标题'    → { type: 'text', value: '标题' }     │   │
│  │  - Comment:    <!-- --> → { type: 'comment', value: '...' }    │   │
│  │  - Doctype:    <!DOCTYPE> → { type: 'doctype' }                │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  Step 3: 语法分析（Tree Construction）                                  │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  Token 序列 ──→ (栈机制构建树) ──→ DOM 节点                    │   │
│  │                                                                 │   │
│  │  使用栈来维护元素嵌套关系：                                     │   │
│  │  遇到 StartTag → 压栈，创建节点                                │   │
│  │  遇到 EndTag   → 出栈，建立父子关系                            │   │
│  │  遇到 Attr     → 设置当前节点属性                              │   │
│  │  遇到 Text     → 作为当前节点的子节点                          │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  Step 4: 构建 DOM 树                                                    │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  DOM 节点 ──→ (树形组装) ──→ 完整 DOM 树                        │   │
│  │                                                                 │   │
│  │  DOM 树特点：                                                   │   │
│  │  - 以 Document 为根节点                                         │   │
│  │  - 反映 HTML 的嵌套结构                                        │   │
│  │  - 包含所有元素、属性、文本节点                                  │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
```

### 2.3 HTML 解析中的阻塞行为

#### 阻塞行为分析表

| 资源类型 | 是否阻塞 HTML 解析 | 说明 |
|---------|-------------------|------|
| 外部 CSS（`<link>`） | **不阻塞** | 预解析线程负责下载和解析 CSS |
| 内联 CSS（`<style>`） | **不阻塞** | 在主线程中直接解析（不阻塞 HTML 解析） |
| 外部 JS（`<script>`） | **阻塞** | 等待下载和执行完成 |
| `async` JS | **不阻塞** | 下载不阻塞，下载完立即执行（执行时短暂阻塞） |
| `defer` JS | **不阻塞** | 下载不阻塞，DOM 解析完成后按序执行 |
| `<img>` | **不阻塞** | 异步加载，不影响 DOM 解析 |
| `<iframe>` | **部分阻塞** | iframe 加载会阻塞父页面 |

#### 阻塞行为示意图

```

HTML 解析:  ████████████████████████████████████████→
                                                    │
                             遇到 <script src="blocking.js">
                                                    │
                                    暂停解析 ──────→ 恢复解析
                                        │                │
                                        ▼                ▼
                               下载+执行JS         继续解析HTML
                               ██████████         ██████████

HTML 解析:  ████████████████████████░░░░░░░░████████████████→
                                    │        │
                             遇到 <script async>
                                    │        │
                         下载(并行) │  执行(短阻塞)
                            ██████████  ██
                                    │        │
HTML 解析:  ████████████████████████████████████░░░░████████→
                                                │       │
                                    遇到 <script defer>
                                                │       │
                                          下载(并行) │  执行(按序)
                                             ██████████  ██
                                                        │

```

#### CSS 与 JS 的阻塞机制详解

```html
<!-- 场景 1：外部 CSS（不阻塞 DOM 解析，但阻塞渲染） -->
<head>
  <link rel="stylesheet" href="style.css">
  <!-- HTML 解析继续进行 -->
  <!-- 但渲染会等待 CSS 加载完成（首屏白屏） -->
</head>

<!-- 场景 2：内联 CSS（不阻塞 DOM 解析） -->
<head>
  <style>
    body { color: red; }
  </style>
  <!-- 直接解析，无需等待网络 -->
</head>

<!-- 场景 3：普通 JS（完全阻塞） -->
<body>
  <script src="blocking.js"></script>
  <!-- 必须等 JS 下载并执行完，才解析后面的 HTML -->
  <p>这段文字会等 JS 执行完才出现</p>
</body>

<!-- 场景 4：async JS（下载不阻塞，执行时短暂阻塞） -->
<body>
  <script src="analytics.js" async></script>
  <!-- JS 下载与 HTML 解析并行 -->
  <!-- JS 下载完立即执行，可能短暂打断解析 -->
</body>

<!-- 场景 5：defer JS（完全不阻塞） -->
<body>
  <script src="app.js" defer></script>
  <!-- JS 下载与 HTML 解析并行 -->
  <!-- JS 在 DOM 解析完成后、DOMContentLoaded 前按序执行 -->
</body>
```

#### 为什么 JS 会阻塞 HTML 解析？

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    JS 阻塞 HTML 解析的原因                             │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  核心原因：JS 可能会修改 DOM 结构                                      │
│                                                                         │
│  场景 1：document.write                                                 │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │ <html>                                                           │   │
│  │   <body>                                                         │   │
│  │     <p>第一行</p>                                                │   │
│  │     <script>                                                     │   │
│  │       document.write('<p>动态内容</p>');  // 写入当前位置        │   │
│  │     </script>                                                    │   │
│  │     <p>第二行</p>                                                │   │
│  │   </body>                                                        │   │
│  │ </html>                                                          │   │
│  │                                                                 │   │
│  │  必须等 JS 执行完，才能确定 DOM 的最终结构                      │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  场景 2：DOM 操作可能影响后续解析                                      │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │ const div = document.createElement('div');                       │   │
│  │ document.body.appendChild(div);  // 修改 DOM 结构                │   │
│  │ // 如果不暂停解析，可能产生解析与修改的冲突                      │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  场景 3：JS 可能读取样式信息                                           │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │ // 这段 JS 依赖 CSS 的计算结果                                  │   │
│  │ const width = document.getElementById('box').offsetWidth;        │   │
│  │ // 如果不等待样式计算完成，width 可能不正确                      │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## 三、CSS 解析过程

### 3.1 CSS 解析机制

CSS 解析是将 CSS 文本转换为 CSSOM（CSS Object Model）树的过程，由**渲染主线程**完成。

#### CSS 解析步骤

```
┌─────────────────────────────────────────────────────────────────────────┐
│                     CSS 解析两步骤                                     │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  Step 1: 词法分析（Tokenization）                                       │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  CSS 文本 ──→ (状态机逐字符分析) ──→ Token 序列                  │   │
│  │                                                                 │   │
│  │  CSS Token 类型：                                               │   │
│  │  - Identifier:  .container     → { type: 'ident', value: 'container' } │
│  │  - Function:    rgba(255,0,0)  → { type: 'function', value: 'rgba' } │
│  │  - Hash:        #FF5733        → { type: 'hash', value: 'FF5733' } │
│  │  - Dimension:   12px           → { type: 'dimension', value: '12', unit: 'px' } │
│  │  - String:      'Arial'        → { type: 'string', value: 'Arial' } │
│  │  - AtKeyword:   auto           → { type: 'at-keyword', value: 'auto' } │
│  │  - Punctuation: { } ; , :      → { type: 'punct', value: '{' } │
│  │  - Comment:     /* comment */  → { type: 'comment', value: '...' } │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  Step 2: 语法分析（Parser）                                             │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  Token 序列 ──→ (规则解析) ──→ CSS 规则对象                    │   │
│  │                                                                 │   │
│  │  CSS 规则类型：                                                 │   │
│  │  - Style Rules:   .container { color: red; }                   │   │
│  │  - Media Rules:   @media (max-width: 600px) { ... }           │   │
│  │  - Keyframe Rules: @keyframes fadeIn { ... }                  │   │
│  │  - Font Face:     @font-face { ... }                           │   │
│  │  - Import:        @import url('...')                          │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

#### CSS 解析示例

```css
/* 原始 CSS */
.container {
  display: flex;
  justify-content: center;
  align-items: center;
  padding: 20px;
  background-color: #f0f0f0;
}

.title {
  font-size: 24px;
  color: #333;
  font-weight: bold;
}
```

**解析后的规则对象：**
```javascript
[
  {
    type: 'style',
    selector: '.container',
    declarations: [
      { property: 'display', value: 'flex' },
      { property: 'justify-content', value: 'center' },
      { property: 'align-items', value: 'center' },
      { property: 'padding', value: '20px' },
      { property: 'background-color', value: '#f0f0f0' }
    ]
  },
  {
    type: 'style',
    selector: '.title',
    declarations: [
      { property: 'font-size', value: '24px' },
      { property: 'color', value: '#333' },
      { property: 'font-weight', value: 'bold' }
    ]
  }
]
```

### 3.2 构建 CSSOM 树

#### CSSOM 树结构

**CSSOM（CSS Object Model）** 是所有样式规则的对象化表示，形成树形结构。

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       CSSOM 树结构示意图                                 │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│                       CSSStyleSheet                                     │
│                          │                                              │
│            ┌─────────────┴─────────────┐                               │
│            ▼                           ▼                                 │
│         .container                  @media (max-width: 600px)          │
│        ┌────┬────┐                   ┌────────────┐                      │
│        ▼    ▼    ▼                   ▼            ▼                      │
│      display padding background   .mobile      @keyframes fadeIn        │
│        │     │      │             │                │                    │
│        ▼     ▼      ▼             ▼                ▼                    │
│      flex  20px  #f0f0f0       .header          from { opacity: 0 }     │
│                                 height: 60px    to { opacity: 1 }      │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

#### CSSOM 树特点

| 特点 | 说明 |
|------|------|
| 以 CSSStyleSheet 为根 | 表示一个完整的样式表 |
| 按规则类型分层 | style rules, media rules, keyframes 等 |
| 存储所有选择器和声明 | 用于后续样式计算阶段 |
| 不区分来源 | 内联样式、外部样式、浏览器默认样式统一管理 |

### 3.3 CSS 解析与阻塞行为

#### CSS 资源的阻塞特性

```
┌─────────────────────────────────────────────────────────────────────────┐
│                  CSS 资源的阻塞行为分析                                 │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  CSS 资源类型                                                   │   │
│  ├─────────────────────────────────────────────────────────────────┤   │
│  │  1. 外部样式表: <link rel="stylesheet" href="style.css">        │   │
│  │     - 下载阻塞渲染（首屏等待）                                   │   │
│  │     - 但不阻塞 HTML 解析                                        │   │
│  │     - 阻塞渲染直到加载完成（避免 FOUC 闪烁）                      │   │
│  ├─────────────────────────────────────────────────────────────────┤   │
│  │  2. 内联样式: <style>...</style>                               │   │
│  │     - 立即解析，无网络延迟                                       │   │
│  │     - 不阻塞 HTML 解析                                          │   │
│  │     - 不阻塞渲染（立即可用）                                     │   │
│  ├─────────────────────────────────────────────────────────────────┤   │
│  │  3. 打印样式: <link rel="stylesheet" media="print">            │   │
│  │     - 仅在打印时生效，不阻塞屏幕渲染                             │   │
│  │     - 可能仍占用下载带宽                                        │   │
│  ├─────────────────────────────────────────────────────────────────┤   │
│  │  4. 动态加载: JavaScript 动态插入 <link>                      │   │
│  │     - 不阻塞初始渲染                                            │   │
│  │     - 可用于加载非关键样式                                       │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  ⚠️ 关键：CSS 阻塞的是「渲染」，而非「解析」                          │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

#### CSS 阻塞渲染的原因

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    CSS 为什么阻塞渲染？                                  │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  原因 1: 避免 FOUC（Flash of Unstyled Content）                          │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │ 如果不等待 CSS：                                                │   │
│  │ - 先显示原始 HTML（无样式）                                      │   │
│  │ - CSS 加载完成后突然应用样式                                      │   │
│  │ - 用户看到页面「闪烁」                                          │   │
│  │                                                                 │   │
│  │  等待 CSS 加载完成：                                             │   │
│  │ - 首次渲染即带完整样式                                           │   │
│  │ - 无闪烁，体验流畅                                              │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  原因 2: 样式计算依赖完整 CSSOM                                        │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │ 样式计算需要所有 CSS 规则：                                      │   │
│  │ - 层叠优先级计算需要完整的规则集                                  │   │
│  │ - 继承值传播需要完整的样式树                                      │   │
│  │ - 默认值填充需要完整的属性定义                                    │   │
│  │                                                                 │   │
│  │ 如果部分 CSS 未加载完成，无法进行准确的样式计算                    │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

#### 优化策略：CSS 加载优化

```html
<!-- 策略 1: 关键 CSS 内联 -->
<head>
  <style>
    /* 将首屏关键样式内联到 HTML 中 */
    body { margin: 0; font-family: sans-serif; }
    .header { height: 60px; background: #fff; }
    .hero { min-height: 400px; }
  </style>
  <!-- 非关键样式异步加载 -->
  <link rel="preload" href="non-critical.css" as="style" 
        onload="this.rel='stylesheet'">
</head>

<!-- 策略 2: 媒体查询优化 -->
<link rel="stylesheet" href="mobile.css" media="(max-width: 768px)">
<link rel="stylesheet" href="desktop.css" media="(min-width: 769px)">
<!-- 只加载当前设备需要的 CSS -->

<!-- 策略 3: 使用 preload 预加载 -->
<link rel="preload" href="critical.css" as="style">
<link rel="stylesheet" href="critical.css">
```

## 四、样式计算

### 4.1 样式计算概述

样式计算是将 DOM 树与 CSSOM 树结合，为每个 DOM 节点计算最终样式（Computed Style）的过程。

#### 样式计算总览

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       样式计算四步骤                                     │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  Step 1: 收集声明值 (Cascading)                                  │   │
│  │  ─────────────────────────────────────────────────────────────  │   │
│  │  收集匹配当前节点的所有 CSS 声明                                 │   │
│  │  - 浏览器默认样式（User Agent Stylesheet）                       │   │
│  │  - 用户样式（User Stylesheet）                                    │   │
│  │  - 外部样式表（Author Stylesheet）                                │   │
│  │  - 内联样式（Inline Style）                                      │   │
│  │  - 行内样式（Element Style Attribute）                            │   │
│  │                                                                 │   │
│  │  产物: 带多条声明的样式属性列表                                   │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                              │                                          │
│                              ▼                                          │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  Step 2: 解决冲突 (Cascade)                                     │   │
│  │  ─────────────────────────────────────────────────────────────  │   │
│  │  按三层优先级解决冲突：                                          │   │
│  │  1. Importance（重要性）                                        │   │
│  │     !important 声明 > 普通声明                                  │   │
│  │  2. Specificity（特异性）                                        │   │
│  │     行内样式 > ID 选择器 > 类选择器 > 类型选择器                  │   │
│  │  3. Source Order（源顺序）                                      │   │
│  │     后加载的样式 > 先加载的样式                                   │   │
│  │                                                                 │   │
│  │  产物: 每个属性的唯一值                                          │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                              │                                          │
│                              ▼                                          │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  Step 3: 使用继承 (Inheritance)                                 │   │
│  │  ─────────────────────────────────────────────────────────────  │   │
│  │  继承的基本原则：                                                │   │
│  │  - 可继承属性：颜色、字体、文本对齐等                             │   │
│  │  - 不可继承属性：边框、边距、定位等                               │   │
│  │                                                                 │   │
│  │  从父节点向子节点传播可继承属性                                   │   │
│  │                                                                 │   │
│  │  产物: 所有属性都有明确值的样式                                   │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                              │                                          │
│                              ▼                                          │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  Step 4: 使用默认值 (Defaulting)                                │   │
│  │  ─────────────────────────────────────────────────────────────  │   │
│  │  填充剩余的未设置属性：                                          │   │
│  │  - 初始值（Initial Value）: 规范定义的默认值                      │   │
│  │  - 继承值（inherit）: 显式从父元素继承                           │   │
│  │  - unset: 重置为初始值或继承值                                   │   │
│  │  - revert: 重置为浏览器默认值                                    │   │
│  │                                                                 │   │
│  │  产物: 完整的 Computed Style                                     │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 4.2 确定声明值

#### 声明值来源

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    CSS 声明值的来源层级                                  │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  优先级从高到低：                                                       │
│                                                                         │
│  1. 行内样式属性                                                        │
│     <div style="color: red;">                                          │
│     ↑ 用户直接设置的行内样式，优先级最高                                │
│                                                                         │
│  2. 作者样式表（外部/内联 CSS）                                        │
│     <link rel="stylesheet" href="style.css">                           │
│     <style>...</style>                                                 │
│     ↑ 开发者定义的样式                                                  │
│                                                                         │
│  3. 用户样式表                                                          │
│     ↑ 用户在浏览器中设置的自定义样式                                     │
│                                                                         │
│  4. 浏览器默认样式（User Agent Stylesheet）                             │
│     ↑ 浏览器内置的默认样式                                              │
│                                                                         │
│  ⚠️ 注意：带 !important 的声明优先级会被反转                            │
│      行内 !important > 作者 !important > 用户 !important > 普通声明     │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

#### 声明值收集示例

```html
<!-- HTML -->
<div id="box" class="container" style="color: red;">
  <p class="text">示例文字</p>
</div>
```

```css
/* 样式表 1: user-agent.css (浏览器默认) */
p { margin: 0; font-size: 16px; }

/* 样式表 2: author.css (外部样式) */
.container { color: blue; padding: 10px; }
#box { color: green; }
.text { color: purple; font-size: 14px; }

/* 样式表 3: inline style (行内样式) */
/* style="color: red;" */
```

**收集的声明值列表：**

| 属性 | 来源 | 值 | 来源优先级 |
|------|------|----|-----------|
| margin | user-agent | 0 | 最低 |
| font-size | user-agent | 16px | 最低 |
| color | author (.container) | blue | 中 |
| color | author (#box) | green | 高（ID 选择器） |
| color | inline style | red | 最高 |
| padding | author | 10px | 中 |

### 4.3 层叠优先级计算

#### 三层优先级体系

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       CSS 层叠优先级体系                                 │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  第一层: Importance（重要性）                                    │   │
│  │  ─────────────────────────────────────────────────────────────  │   │
│  │                                                                 │   │
│  │  带 !important 的声明 > 普通声明                                 │   │
│  │                                                                 │   │
│  │  !important 优先级:                                             │   │
│  │  ┌──────────────────────────────────────────────────────────┐ │   │
│  │  │  1. 行内 !important:     style="color: red !important"   │ │   │
│  │  │  2. 作者样式 !important:  .box { color: blue !important } │ │   │
│  │  │  3. 用户样式 !important:  用户在浏览器设置的 !important  │ │   │
│  │  │  4. 普通声明:             color: red                      │ │   │
│  │  └──────────────────────────────────────────────────────────┘ │   │
│  │                                                                 │   │
│  │  示例：                                                         │   │
│  │  .box { color: red !important; }  /* 不会被覆盖 */              │   │
│  │  .box { color: blue; }            /* 被 !important 覆盖 */       │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  第二层: Specificity（特异性）                                   │   │
│  │  ─────────────────────────────────────────────────────────────  │   │
│  │                                                                 │   │
│  │  特异性计算规则：                                                │   │
│  │  (行内样式数, ID 选择器数, 类/属性/伪类数, 元素/伪元素数)        │   │
│  │                                                                 │   │
│  │  计算示例：                                                     │   │
│  │  ┌──────────────────────────────────────────────────────────┐ │   │
│  │  │  选择器                      │ 特异性                     │ │   │
│  │  ├──────────────────────────────────────────────────────────┤ │   │
│  │  │  style="color: red"          │ (1, 0, 0, 0)              │ │   │
│  │  │  #id                         │ (0, 1, 0, 0)              │ │   │
│  │  │  #id .class                  │ (0, 1, 1, 0)              │ │   │
│  │  │  .class                      │ (0, 0, 1, 0)              │ │   │
│  │  │  .class:hover                │ (0, 0, 2, 0)              │ │   │
│  │  │  div                         │ (0, 0, 0, 1)              │ │   │
│  │  │  div p                       │ (0, 0, 0, 2)              │ │   │
│  │  │  :root                       │ (0, 0, 0, 1)              │ │   │
│  │  │  ::before                    │ (0, 0, 0, 1)              │ │   │
│  │  └──────────────────────────────────────────────────────────┘ │   │
│  │                                                                 │   │
│  │  比较规则：从左到右逐位比较，高位大者优先                        │   │
│  │  示例：(0,1,0,0) > (0,0,10,0) → ID 选择器 > 10 个类选择器     │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  第三层: Source Order（源顺序）                                   │   │
│  │  ─────────────────────────────────────────────────────────────  │   │
│  │                                                                 │   │
│  │  当 Importance 和 Specificity 相同时，按源顺序决定：             │   │
│  │  - 后加载的样式 > 先加载的样式                                    │   │
│  │  - `<style>` 内的样式 > `<link>` 外部样式                        │   │
│  │  - 文档后面的样式 > 文档前面的样式                                │   │
│  │                                                                 │   │
│  │  示例：                                                         │   │
│  │  /* style.css - 先加载 */                                       │   │
│  │  .box { color: red; }                                          │   │
│  │                                                                 │   │
│  │  /* 内联 style - 后加载 */                                      │   │
│  │  <style>                                                        │   │
│  │    .box { color: blue; }  /* 优先级更高 */                     │   │
│  │  </style>                                                       │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

#### 层叠优先级示例

```css
/* 场景：多个选择器设置 color 属性 */
body { color: black; }                    /* 特异性 (0,0,0,1) */
.container { color: blue; }               /* 特异性 (0,0,1,0) */
#header { color: red; }                   /* 特异性 (0,1,0,0) */
#header .nav { color: green; }            /* 特异性 (0,1,1,0) */
#header .nav li { color: purple; }        /* 特异性 (0,1,1,1) */
body.container#header.nav li { 
  color: orange;                          /* 特异性 (0,1,2,2) */
}

/* 最终结果：orange（特异性最高） */
```

## 五、布局（Layout）

### 5.1 布局阶段概述

布局（Layout）是根据 DOM 树和计算后的样式，计算每个节点几何信息（位置、尺寸）的过程。

#### 布局阶段在渲染流水线中的位置

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       渲染流水线中的布局阶段                             │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  DOM 树 ──→ CSSOM 树 ──→ 样式计算 ──→ 【布局】 ──→ 分层 ──→ 绘制 ...  │
│                                        │                                │
│                                        ▼                                │
│                              布局树 + 几何信息                           │
│                                                                         │
│  布局做什么？                                                           │
│  1. 构建布局树（Layout Tree）                                           │
│  2. 计算每个节点的位置和尺寸                                            │
│  3. 处理盒模型、浮动、定位等几何布局                                    │
│  4. 确定包含块（Containing Block）                                      │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 5.2 布局树构建

#### 布局树与 DOM 树的区别

布局树是从 DOM 树中筛选出需要参与布局的节点，并调整父子关系后形成的树。

```
┌─────────────────────────────────────────────────────────────────────────┐
│              DOM 树 vs 布局树 对比                                      │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  DOM 树（原始结构）:                                                    │
│  html                                                                   │
│  ├── head                                                               │
│  │   ├── meta (display:none)  ← 不进入布局树                          │
│  │   └── title (display:none) ← 不进入布局树                          │
│  └── body                                                               │
│      ├── header                                                         │
│      ├── main                                                           │
│      │   ├── p                                                          │
│      │   ├── div#hidden (display:none) ← 不进入布局树                 │
│      │   └── .content                                                  │
│      └── footer                                                         │
│                                                                         │
│  布局树（参与布局的节点）:                                              │
│  html                                                                   │
│  ├── body                                                               │
│  │   ├── header                                                         │
│  │   ├── main                                                           │
│  │   │   ├── p                                                          │
│  │   │   └── .content                                                  │
│  │   └── footer                                                         │
│                                                                         │
│  差异说明：                                                             │
│  - display:none 的元素不进入布局树                                      │
│  - head 中的元素通常不参与布局                                          │
│  - 布局树节点可能合并（如匿名盒）                                      │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

#### 布局树构建规则

| 规则 | 说明 |
|------|------|
| `display: none` | 元素及其子元素完全不进入布局树 |
| `display: block/inline/...` | 元素进入布局树 |
| 匿名盒（Anonymous Box） | 文本节点在某些上下文中会被包装成匿名块盒 |
| 浮动/绝对定位 | 虽然脱离正常流，但仍在布局树中 |
| 伪元素（::before/after） | 若有 `content` 属性，会创建伪节点进入布局树 |

### 5.3 几何信息计算

#### 盒模型计算

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       CSS 盒模型详解                                     │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  ┌───────────────────────────────────────────────────────────────────┐   │
│  │                            元素盒子                                │   │
│  │  ┌─────────────────────────────────────────────────────────────┐ │   │
│  │  │  margin-top                                                  │ │   │
│  │  │  ┌─────────────────────────────────────────────────────────┐ │ │   │
│  │  │  │  border-top                                             │ │ │   │
│  │  │  │  ┌───────────────────────────────────────────────────┐ │ │ │   │
│  │  │  │  │  padding-top                                     │ │ │ │   │
│  │  │  │  │  ┌─────────────────────────────────────────────┐ │ │ │ │   │
│  │  │  │  │  │  内容区域 (Content Area)                     │ │ │ │   │
│  │  │  │  │  │  width × height                             │ │ │ │   │
│  │  │  │  │  └─────────────────────────────────────────────┘ │ │ │ │   │
│  │  │  │  │  padding-bottom                                  │ │ │ │   │
│  │  │  │  └───────────────────────────────────────────────────┘ │ │ │   │
│  │  │  │  border-bottom                                         │ │ │   │
│  │  │  └─────────────────────────────────────────────────────────┘ │ │   │
│  │  │  margin-bottom                                              │ │   │
│  │  └─────────────────────────────────────────────────────────────┘ │   │
│  │  └───────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  │  尺寸计算：                                                         │
│  - 标准盒模型 (box-sizing: content-box):                                │
│    总宽度 = width + padding-left + padding-right +                       │
│             border-left + border-right + margin-left + margin-right      │
│                                                                         │
│  - 替代盒模型 (box-sizing: border-box):                                 │
│    width 包含 padding 和 border                                         │
│    总宽度 = width + margin-left + margin-right                          │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

#### 绝对尺寸信息

```css
/* 布局计算示例 */
.box {
  width: 200px;
  height: 100px;
  padding: 20px;
  border: 2px solid #ccc;
  margin: 10px;
  position: absolute;
  top: 50px;
  left: 100px;
}

/* 计算结果：
   - 内容宽度: 200px
   - 内容高度: 100px
   - 内边距: 20px (四周)
   - 边框: 2px (四周)
   - 外边距: 10px (四周)
   - 总宽度: 200 + 20*2 + 2*2 + 10*2 = 264px (content-box)
   - 总高度: 100 + 20*2 + 2*2 + 10*2 = 164px (content-box)
   - 位置: top=50px, left=100px (相对于包含块)
*/
```

#### 百分比尺寸

```css
.container {
  width: 500px;
  height: 300px;
}

.child {
  width: 50%;        /* 500 * 0.5 = 250px (相对于父元素内容宽度) */
  height: 50%;       /* 300 * 0.5 = 150px (相对于父元素内容高度) */
  padding: 10%;      /* 500 * 0.1 = 50px (百分比 padding 基于父元素宽度) */
  margin: 5%;        /* 500 * 0.05 = 25px (百分比 margin 基于父元素宽度) */
}
```

### 5.4 包含块确定规则

包含块（Containing Block）决定了百分比尺寸和绝对定位的参考基准。

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       包含块确定规则                                     │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  情况 1: 静态定位 (position: static)                             │   │
│  │  ─────────────────────────────────────────────────────────────  │   │
│  │  包含块 = 最近的块级祖先元素的内容区域                             │   │
│  │                                                                 │   │
│  │  <div style="padding: 20px;"> ← 包含块                         │   │
│  │    <div style="width: 50%;"> ← 50% 基于父元素内容宽度           │   │
│  │  </div>                                                         │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  情况 2: 绝对定位 (position: absolute)                            │   │
│  │  ─────────────────────────────────────────────────────────────  │   │
│  │  包含块 = 最近的非 static 定位祖先元素的内边距区域                │   │
│  │                                                                 │   │
│  │  .parent { position: relative; padding: 20px; }  ← 包含块     │   │
│  │  .child  { position: absolute; top: 10px; left: 10px; }         │   │
│  │                                                                 │   │
│  │  如果没有非 static 祖先，包含块为初始包含块（视口）              │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  情况 3: 固定定位 (position: fixed)                               │   │
│  │  ─────────────────────────────────────────────────────────────  │   │
│  │  包含块 = 视口（除非祖先有 transform）                           │   │
│  │                                                                 │   │
│  │  特殊情况：若祖先有 transform 属性                              │   │
│  │  fixed 定位的包含块变为该祖先的内边距区域                         │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  情况 4: 粘性定位 (position: sticky)                              │   │
│  │  ─────────────────────────────────────────────────────────────  │   │
│  │  包含块 = 正常流中的直接块级祖先                                 │   │
│  │  粘性定位受其父容器的滚动影响                                    │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## 六、分层（Layer）机制

### 6.1 分层机制概述

分层（Layer）是将布局树中的节点划分为多个独立图层的过程，每个图层可以独立进行合成和光栅化。

#### 分层在渲染流水线中的位置

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       渲染流水线中的分层阶段                             │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  布局树 ──→ 【分层】 ──→ 绘制指令 ──→ 分块 ──→ 光栅化 ──→ 合成          │
│              │                                                          │
│              ▼                                                          │
│          图层树（Layer Tree）                                            │
│                                                                         │
│  分层的目的：                                                           │
│  1. 减少重绘区域（只重绘变化的图层）                                    │
│  2. 启用 GPU 加速（每个图层独立光栅化）                                 │
│  3. 支持合成线程异步处理                                                │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

#### 层级树示意图

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       图层树结构示意图                                   │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  Layer Tree                                                             │
│  ├── Layer 0: Root Layer（根图层）                                      │
│  │   ├── Layer 1: Header（有 position: fixed）                          │
│  │   │   └── Layer 1.1: Logo                                           │
│  │   ├── Layer 2: Main Content（普通图层）                             │
│  │   │   ├── Layer 2.1: Card A（有 will-change: transform）             │
│  │   │   └── Layer 2.2: Card B（有 transition）                        │
│  │   └── Layer 3: Footer（有 position: fixed）                         │
│  │       └── Layer 3.1: Copyright                                      │
│                                                                         │
│  图层排序规则：                                                         │
│  - 子图层绘制在父图层之上                                               │
│  - 同级图层按 DOM 顺序排列                                              │
│  - z-index 影响同级图层的堆叠顺序                                       │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 6.3 分层的优化策略

#### 合理使用分层

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       分层优化策略                                       │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  ✅ 应该分层的场景                                                     │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  1. 高频动画元素：                                               │   │
│  │     .slider { transform: translateX(100px); }                    │   │
│  │     /* 动画期间创建独立图层，避免影响其他元素 */                   │   │
│  │                                                                 │   │
│  │  2. 固定定位元素：                                               │   │
│  │     .header { position: fixed; top: 0; }                        │   │
│  │     /* 独立图层可避免滚动时重绘整个页面 */                       │   │
│  │                                                                 │   │
│  │  3. 大型滚动容器：                                               │   │
│  │     .scroll-container { overflow: auto; }                       │   │
│  │     /* 独立图层可避免滚动时重绘 */                                │   │
│  │                                                                 │   │
│  │  4. 需要模糊效果的元素：                                         │   │
│  │     .blur-bg { backdrop-filter: blur(10px); }                    │   │
│  │     /* filter 会影响子元素，独立图层可减少重绘范围 */             │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  ❌ 不应过度分层的场景                                                 │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  1. 滥用 will-change：                                           │   │
│  │     * { will-change: transform; }  /* 错误！ */                  │   │
│  │     /* 为每个元素创建图层，消耗大量内存 */                        │   │
│  │                                                                 │   │
│  │  2. 非动画元素使用 GPU 加速：                                     │   │
│  │     .static { transform: translateZ(0); }  /* 不必要 */          │   │
│  │     /* 静态元素不需要独立图层 */                                  │   │
│  │                                                                 │   │
│  │  3. 层级过深的图层嵌套：                                         │   │
│  │     /* 过度嵌套的图层会增加合成复杂度 */                           │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  ⚠️ 性能权衡：                                                         │
│  - 更多图层 = 更多内存消耗                                             │
│  - 更多图层 = 更复杂的合成计算                                         │
│  - 更多图层 = 更大的光栅化开销                                         │
│  - 目标：只为需要动画/独立渲染的元素创建图层                           │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## 七、绘制（Paint）

### 7.1 绘制阶段概述

绘制（Paint）是为每个图层生成绘制指令集的过程，类似于将布局信息转换为 Canvas 绘图命令序列。

#### 绘制在渲染流水线中的位置

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       渲染流水线中的绘制阶段                             │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  布局树 ──→ 分层 ──→ 【绘制】 ──→ 分块 ──→ 光栅化 ──→ 合成             │
│                       │                                                  │
│                       ▼                                                  │
│                   绘制指令集                                             │
│                                                                         │
│  绘制做什么？                                                           │
│  1. 为每个图层生成绘图命令                                                │
│  2. 确定绘制顺序（z-index 从低到高）                                    │
│  3. 处理裁剪、透明度等效果                                               │
│  4. 最终生成矢量绘图指令（而非像素）                                     │
│                                                                         │
│  ⚠️ 关键：绘制生成的是矢量指令，而非位图                                │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 7.2 绘制指令生成

#### 绘制指令类型

绘制指令是一组类似 Canvas API 的命令序列，描述如何绘制图层内容。

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       绘制指令类型                                       │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  1. 矩形绘制指令                                                  │   │
│  │     drawRect(x, y, width, height, color)                        │   │
│  │     → 用于绘制背景色、边框等矩形区域                               │   │
│  │                                                                 │   │
│  │  2. 文本绘制指令                                                  │   │
│  │     drawText(text, x, y, font, color)                           │   │
│  │     → 用于绘制文字内容                                             │   │
│  │                                                                 │   │
│  │  3. 图像绘制指令                                                  │   │
│  │     drawImage(image, x, y, width, height)                       │   │
│  │     → 用于绘制图片内容                                             │   │
│  │                                                                 │   │
│  │  4. 阴影绘制指令                                                  │   │
│  │     drawShadow(path, blur, color)                               │   │
│  │     → 用于绘制 CSS box-shadow                                     │   │
│  │                                                                 │   │
│  │  5. 渐变绘制指令                                                  │   │
│  │     drawGradient(x1, y1, x2, y2, colors)                       │   │
│  │     → 用于绘制 CSS linear-gradient/radial-gradient               │   │
│  │                                                                 │   │
│  │  6. 裁剪指令                                                      │   │
│  │     clip(path) / clip(rect)                                      │   │
│  │     → 用于处理 overflow:hidden 等裁剪效果                        │   │
│  │                                                                 │   │
│  │  7. 变换指令                                                      │   │
│  │     save() / translate(x, y) / rotate(angle) / scale(sx, sy)    │   │
│  │     → 用于处理 CSS transform                                     │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  示例：一个简单元素的绘制指令集                                       │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  // <div style="width:100px; height:50px;                         │   │
│  │  //              background:red; border-radius:5px;">              │   │
│  │                                                                 │   │
│  │  save();                                                        │   │
│  │  translate(100, 200);  // 元素位置                              │   │
│  │  drawRoundRect(0, 0, 100, 50, 5);  // 圆角矩形路径               │   │
│  │  clip();  // 裁剪                                                │   │
│  │  drawRect(0, 0, 100, 50, 'red');  // 填充背景                     │   │
│  │  restore();                                                     │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

#### 绘制顺序

绘制阶段按照 z-index 从低到高的顺序处理图层：

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       绘制顺序示例                                       │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  图层树结构:                                                            │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  Layer 0: Root Layer (z-index: 0)                                │   │
│  │  ├── Layer 1: Background (z-index: 1)                            │   │
│  │  ├── Layer 2: Content (z-index: 2)                               │   │
│  │  │   ├── Element A (z-index: auto)                               │   │
│  │  │   └── Element B (z-index: auto)                               │   │
│  │  └── Layer 3: Popup (z-index: 1000)                              │   │
│  │      └── Dialog                                                  │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  绘制顺序:                                                              │
│  1. Layer 0 (Root)                                                     │
│  2. Layer 1 (Background)                                               │
│  3. Layer 2 (Content)                                                  │
│     3.1 Element A (DOM 顺序在前)                                        │
│     3.2 Element B (DOM 顺序在后)                                        │
│  4. Layer 3 (Popup)                                                    │
│     4.1 Dialog                                                         │
│                                                                         │
│  ⚠️ 规则：                                                             │
│  - z-index 值越大越后绘制（显示在上方）                                 │
│  - 同级元素按 DOM 顺序绘制                                             │
│  - 同一元素的绘制顺序：背景 → 边框 → 内容                              │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

#### 单个元素的绘制顺序

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       CSS 元素绘制顺序                                   │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  对单个元素，绘制顺序为：                                               │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  ① 背景色 (background-color)                                     │   │
│  │     ↓                                                           │   │
│  │  ② 背景图片 (background-image)                                   │   │
│  │     ↓                                                           │   │
│  │  ③ 边框 (border)                                                 │   │
│  │     ↓                                                           │   │
│  │  ④ 内容 (content, text, child elements)                          │   │
│  │     ↓                                                           │   │
│  │  ⑤ 轮廓 (outline)                                                │   │
│  │     ↓                                                           │   │
│  │  ⑥ 阴影 (box-shadow, text-shadow)                               │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  示例：<div style="background:red; border:1px solid; color:white">     │

│  2. 绘制边框                                                           │
│  3. 绘制子元素/文本内容                                                │
│  4. 绘制 outline（如果有）                                             │
│  5. 绘制 box-shadow（如果有）                                          │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## 八、分块（Tiling）处理

### 8.1 分块机制概述

分块（Tiling）是将大图层层划分为小方块（Tile）的过程，每个 Tile 独立进行光栅化处理。

#### 分块的目的

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       分块处理的目的                                     │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  1. 并行处理                                                            │
│     ┌─────────────────────────────────────────────────────────────┐   │
│     │  多个 Tile 可以同时进行光栅化，利用 GPU 并行计算能力           │   │
│     │  示意：                                                     │   │
│     │  ┌──────┬──────┬──────┐                                    │   │
│     │  │Tile 1│Tile 2│Tile 3│  ← GPU 并行处理                    │   │
│     │  ├──────┼──────┼──────┤                                    │   │
│     │  │Tile 4│Tile 5│Tile 6│                                    │   │
│     │  └──────┴──────┴──────┘                                    │   │
│     └─────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  2. 局部更新                                                            │
│     ┌─────────────────────────────────────────────────────────────┐   │
│     │  只重新光栅化变化的 Tile，避免处理整个图层                    │   │
│     │  例如：滚动时只需要处理视口内的 Tile                          │   │
│     └─────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  3. 内存优化                                                            │
│     ┌─────────────────────────────────────────────────────────────┐   │
│     │  每个 Tile 独立存储，不需要一次性存储整个大图层的位图          │   │
│     │  避免大块连续内存分配问题                                      │   │
│     └─────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  4. 滚动性能                                                            │
│     ┌─────────────────────────────────────────────────────────────┐   │
│     │  预加载屏幕外的 Tile，滚动时可直接显示                         │   │
│     │  避免滚动时突然出现的白屏                                      │   │
│     └─────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

#### Tile 大小

| 浏览器 | Tile 大小 | 说明 |
|--------|-----------|------|
| Chrome | 256×256 或 512×512 像素 | 通常根据设备像素比调整 |
| Firefox | 256×256 像素 | 固定大小 |
| Safari | 256×256 像素 | 可能根据场景变化 |

### 8.2 视口优先策略

浏览器在分块处理时采用视口优先策略，确保用户可见区域的渲染优先级。

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       视口优先策略示意图                                   │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  页面布局（视口在中间）:                                               │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                                                                 │   │
│  │  ┌──────┬──────┬──────┬──────┐                                 │   │
│  │  │Tile 1│Tile 2│Tile 3│Tile 4│  ← 高优先级（视口内）              │   │
│  │  ├──────┼──────┼──────┼──────┤                                 │   │
│  │  │Tile 5│Tile 6│Tile 7│Tile 8│  ← 高优先级（视口内）              │   │
│  │  ├──────┼──────┼──────┼──────┤                                 │   │
│  │  │Tile 9│Tile10│Tile11│Tile12│  ← 中优先级（视口边缘）            │   │
│  │  ├──────┼──────┼──────┼──────┤                                 │   │
│  │  │Tile13│Tile14│Tile15│Tile16│  ← 低优先级（屏幕外）              │   │
│  │  └──────┴──────┴──────┴──────┘                                 │   │
│  │                                                                 │   │
│  │  视口区域                                                         │   │
│  │  ┌─────────────────────────────────────────────────────────┐   │   │
│  │  │                    当前可见区域                          │   │   │
│  │  └─────────────────────────────────────────────────────────┘   │   │
│  │                                                                 │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  优先级排序：                                                           │
│  1. 视口内的 Tile（立即处理）                                          │
│  2. 视口边缘的 Tile（预加载，处理滚动缓冲）                            │
│  3. 屏幕外的 Tile（延迟处理）                                          │
│                                                                         │
│  滚动时的策略：                                                         │
│  - 用户快速滚动时，优先显示视口内区域                                  │
│  - 可接受视口边缘短暂白屏（因为会很快进入视口）                        │
│  - 绝对避免视口中心区域白屏                                            │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## 九、光栅化（Rasterization）

### 9.1 光栅化机制

光栅化是将矢量绘图指令转换为像素位图的过程，由 GPU 进程完成。

#### 光栅化过程

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       光栅化机制详解                                     │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  输入: 绘制指令（矢量）                                                 │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  drawRect(0, 0, 200, 100, 'red')                               │   │
│  │  → 这是矢量指令：绘制一个矩形，不是具体像素                     │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                              │                                          │
│                              ▼                                          │
│  处理: GPU 光栅化管线                                                  │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  1. 顶点处理（Vertex Processing）                                │   │
│  │     - 计算图元的顶点坐标                                         │   │
│  │     - 应用坐标变换                                               │   │
│  │                                                                 │   │
│  │  2. 栅格化（Rasterization）                                      │   │
│  │     - 将图元转换为像素片段（Fragment）                           │   │
│  │     - 确定每个像素的位置                                         │   │
│  │                                                                 │   │
│  │  3. 片元处理（Fragment Processing）                              │   │
│  │     - 计算每个像素的颜色                                         │   │
│  │     - 应用颜色、纹理、光照等                                     │   │
│  │                                                                 │   │
│  │  4. 帧缓冲输出（Framebuffer Output）                             │   │
│  │     - 将计算好的像素写入位图                                     │   │
│  │     - 存入 GPU 显存                                              │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                              │                                          │
│                              ▼                                          │
│  输出: 位图（像素数据）                                                 │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  Tile 位图:                                                    │   │
│  │  [[FF0000, FF0000, ...],  // 第一行                             │   │
│  │   [FF0000, FF0000, ...],  // 第二行                             │   │
│  │   ...]                                                         │   │
│  │  → 每个像素存储 RGBA 颜色值                                     │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

#### 光栅化示例

```
矢量绘制指令:
drawRect(10, 10, 30, 20, 'blue')

光栅化结果（30×20 像素的蓝色矩形）:
┌────────────────────────────────────┐
│                                    │
│    蓝色像素 (0x0000FF)             │
│    30 × 20 = 600 个像素            │
│                                    │
└────────────────────────────────────┘

实际像素数组:
Row 0: [0000FF, 0000FF, 0000FF, ..., 0000FF] (30 个)
Row 1: [0000FF, 0000FF, 0000FF, ..., 0000FF] (30 个)
...
Row 19: [0000FF, 0000FF, 0000FF, ..., 0000FF] (30 个)

总计: 30 × 20 = 600 个像素
每个像素: 4 字节 (RGBA)
总大小: 600 × 4 = 2400 字节
```

```
│  - CPU 光栅化: 约 1-10 MPixel/s                                      │
│  - GPU 光栅化: 约 100-1000 MPixel/s                                  │

│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 9.3 光栅化性能影响

#### 影响光栅化性能的因素

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    影响光栅化性能的因素                                   │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  1. 图层数量                                                            │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  更多图层 = 更多独立光栅化任务                                    │   │
│  │  每个图层需要单独光栅化成位图                                    │   │
│  │  优化：减少不必要的图层                                           │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  2. 图层大小                                                            │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  更大的图层 = 更多像素需要处理                                    │   │
│  │  1920×1080 全屏图层: ~2M 像素                                   │   │
│  │  如果有 Retina 屏 (2x): ~8M 像素                                │   │
│  │  优化：避免创建覆盖全屏的大图层                                   │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  3. 复杂绘制操作                                                        │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  影响因素：                                                      │   │
│  │  - 阴影绘制 (box-shadow): 每个阴影需要额外光栅化                  │   │
│  │  - 渐变填充: 需要逐像素计算颜色                                   │   │
│  │  - 滤镜效果 (filter): 每个像素需要额外计算                       │   │
│  │  - 背景模糊 (backdrop-filter): 需要读取背景像素                   │   │
│  │  - 混合模式 (mix-blend-mode): 需要与背景混合                     │   │
│  │  优化：合理使用复杂效果，避免滥用                                 │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  4. 设备像素比（DPR）                                                  │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  Retina 屏 (DPR=2): 像素数量 4 倍                                │   │
│  │  4K 屏 (DPR=4): 像素数量 16 倍                                   │   │
│  │  优化：使用 srcset 提供适配分辨率的图片                           │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## 十、合成与显示

### 10.1 合成阶段概述

合成（Composite）是将多个图层的光栅化结果（位图）叠加在一起，生成最终屏幕图像的过程。

#### 合成阶段在渲染流水线中的位置

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       渲染流水线中的合成阶段                             │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  布局树 → 分层 → 绘制 → 分块 → 光栅化 → 【合成】 → 屏幕显示            │
│                                                  │                      │
│                                                  ▼                      │
│                                           最终帧缓冲                    │
│                                                                         │
│  合成做什么？                                                           │
│  1. 将多个图层的位图按 z-index 顺序叠加                                 │
│  2. 处理图层间的混合、透明度等                                          │
│  3. 将合成结果提交给 GPU 进程                                          │
│                                                                         │
│  执行线程：合成线程（Compositor Thread）                                │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

#### 合成过程示意


## 十一、回流与重绘

### 11.1 回流（Reflow）

回流（Reflow）是当页面的几何信息发生变化时，浏览器重新计算部分或全部元素的几何信息的过程。

#### 什么会触发回流？

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    触发回流的操作汇总                                     │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  1. DOM 操作                                                            │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  - 添加/删除 DOM 节点                                            │   │
│  │  - 修改节点属性（如 className, style）                           │   │
│  │  - 移动节点位置                                                  │   │
│  │  - 修改 innerHTML / textContent                                  │   │
│  │  - 添加/删除伪元素 (::before, ::after)                           │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  2. 几何属性修改                                                        │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  - 修改 width, height, padding, margin, border                  │   │
│  │  - 修改 position, top, left, right, bottom                      │   │
│  │  - 修改 display, float                                          │   │
│  │  - 修改 font-size, line-height                                   │   │
│  │  - 修改 flex-direction, flex-wrap, justify-content              │   │
│  │  - 修改 grid-template-columns, grid-template-rows                │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  3. 用户交互                                                            │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  - 窗口大小变化 (resize 事件)                                    │   │
│  │  - 字体大小变化                                                  │   │
│  │  - 浏览器缩放                                                    │   │
│  │  - 滚动条出现/消失                                               │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  4. 内容变化                                                            │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  - 图片加载完成导致尺寸变化                                       │   │
│  │  - 字体加载完成（FOUT/FOIT）                                      │   │
│  │  - iframe 内容加载                                               │   │
│  │  - 表单元素内容变化                                              │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

#### 回流影响范围

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    回流影响范围示意                                       │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  1. 全量回流                                                            │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  触发条件：                                                      │   │
│  │  - 修改根元素 (html/body) 的几何属性                              │   │
│  │  - 修改全局字体设置                                               │   │
│  │  - 窗口大小变化                                                  │   │
│  │  - 添加/删除重要结构元素                                         │   │
│  │                                                                 │   │
│  │  影响范围：整个页面                                              │   │
│  │  性能影响：严重                                                  │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  2. 局部回流                                                            │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  触发条件：                                                      │   │
│  │  - 修改某个子树内的元素                                           │   │
│  │  - 修改不影响布局的父元素                                         │   │
│  │                                                                 │   │
│  │  影响范围：该元素及其后代                                         │   │
│  │  性能影响：较小                                                  │   │
│  │                                                                 │   │
│  │  示例：                                                          │   │
│  │  // 只影响 .card 及其内部元素                                     │   │
│  │  document.querySelector('.card').style.width = '200px';          │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  3. 增量回流                                                            │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  浏览器优化：并非每次都重新计算整个受影响区域                     │   │
│  │  现代浏览器会尽可能进行增量计算                                   │   │
│  │                                                                 │   │
│  │  优化策略：                                                      │   │
│  │  - 脏标记（Dirty Bit）：标记需要重新计算的节点                     │   │
│  │  - 子树复用：复用不依赖变化的子树                                 │   │
│  │  - 异步回流：在合适的时机批量执行                                 │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 11.2 重绘（Repaint）

重绘（Repaint）是当元素的外观改变但几何信息不变时，浏览器重新绘制该元素的过程。

#### 什么会触发重绘？

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    触发重绘的操作汇总                                     │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  1. 视觉属性修改（不影响布局）                                          │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  - 修改 color, background-color                                 │   │
│  │  - 修改 border-style, border-color（注意：border-width 会触发回流）│   │
│  │  - 修改 outline                                                  │   │
│  │  - 修改 text-decoration, text-shadow                              │   │
│  │  - 修改 visibility（注意：visibility: hidden 不触发回流）         │   │
│  │  - 修改 box-shadow, filter                                       │   │
│  │  - 修改 cursor, caret-color                                       │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  2. 状态变化                                                            │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  - :hover, :focus, :active 伪类状态变化                         │   │
│  │  - 主题切换（如从亮色模式切换到暗色模式）                         │   │
│  │  - 动画/过渡结束后的样式变化                                     │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  ⚠️ 关键区别：                                                          │
│  - 重绘不涉及几何计算，性能优于回流                                    │
│  - 重绘仍需重新生成绘制指令                                            │
│  - 在现代浏览器中，重绘通常很快                                        │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 11.3 合成（Composite）

合成（Composite）是当元素的外观变化既不影响布局也不触发重绘时，仅在合成阶段处理的操作。

#### 什么只触发合成？

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    仅触发合成的操作汇总                                   │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  1. Transform 变化（硬件加速）                                          │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  - transform: translateX/Y/Z                                    │   │
│  │  - transform: scaleX/Y/Z                                        │   │
│  │  - transform: rotateX/Y/Z                                       │   │
│  │  - transform: translate3d, matrix3d                            │   │
│  │                                                                 │   │
│  │  特点：                                                          │   │
│  │  - 已创建独立图层的元素                                          │   │
│  │  - 不影响布局和绘制                                              │   │
│  │  - 仅在合成阶段处理                                              │   │
│  │  - 由合成线程/GPU 完成                                           │   │
│  │  - 性能最高，适合动画                                            │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  2. Opacity 变化（配合独立图层）                                        │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  - opacity 变化（元素有独立图层）                                 │   │
│  │                                                                 │   │
│  │  特点：                                                          │   │
│  │  - 如果元素没有独立图层，opacity 变化会触发重绘                    │   │
│  │  - 配合 transform 或 will-change 可触发独立图层                   │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  3. Scroll 处理                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  - 滚动独立图层内容                                               │   │
│  │  - 如 position: fixed 的元素                                     │   │
│  │  - overflow: auto 的滚动容器                                     │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  性能对比：                                                             │
│  - 回流: 最慢（涉及布局计算）                                          │
│  - 重绘: 中等（涉及绘制指令生成）                                       │
│  - 合成: 最快（仅涉及图层合成）                                        │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

```

│  ┌─────────────────────────────────────────────────────────────────┐   │

│  │  (Repaint)│ text-decoration, text-shadow, visibility            │   │

│  - 避免回流（使用 transform、opacity 进行动画）                          │
│  - 减少重绘范围（使用独立图层）                                         │
│  - 尽可能只触发合成                                                    │
│                                                                         │

```

#### 强制同步布局（Layout Thrashing）

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    强制同步布局问题                                       │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  问题描述：                                                             │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  当你先读取一个会触发回流的属性，然后写入另一个会触发回流的属性  │   │
│  │  浏览器会被迫立即执行回流（而不是异步批量处理）                    │   │
│  │  这就是「强制同步布局」或「布局抖动」                              │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  问题代码：                                                             │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  const elements = document.querySelectorAll('.item');            │   │
│  │                                                                 │   │
│  │  // 错误：先读后写，触发多次回流                                   │   │
│  │  elements.forEach(el => {                                        │   │
│  │    const width = el.offsetWidth;  // 读取 → 触发回流            │   │
│  │    el.style.width = (width + 10) + 'px';  // 写入 → 触发回流   │   │
│  │  });                                                            │   │
│  │  // 每次循环都触发一次回流，100 个元素就是 100 次回流             │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  优化代码：                                                             │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  // 正确：先批量读取，再批量写入                                   │   │
│  │  const widths = elements.map(el => el.offsetWidth);  // 批量读取 │   │
│  │                                                                 │   │
│  │  elements.forEach((el, i) => {                                   │   │
│  │    el.style.width = (widths[i] + 10) + 'px';  // 批量写入       │   │
│  │  });                                                            │   │
│  │  // 只触发 1 次读取的回流 + 1 次写入的回流                        │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  会触发回流的读取操作：                                                  │
│  - offsetWidth, offsetHeight, offsetLeft, offsetTop                 │
│  - scrollWidth, scrollHeight, scrollLeft, scrollTop                │
│  - clientWidth, clientHeight, clientLeft, clientTop               │
│  - getBoundingClientRect()                                         │
│  - getComputedStyle()                                              │
│  - elementFromPoint()                                              │
│  - innerText（在某些浏览器中）                                       │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## 十二、关键渲染路径优化

### 12.1 关键渲染路径定义

关键渲染路径（Critical Rendering Path, CRP）是浏览器从接收 HTML 到渲染出首屏内容所需的最短时间。

#### CRP 优化目标

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    关键渲染路径优化目标                                   │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  核心目标：                                                             │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  1. 减少关键资源数量 → 减少请求数                                │   │
│  │  2. 减少关键资源大小 → 减少传输时间                              │   │
│  │  3. 优化关键资源加载顺序 → 尽早获取核心资源                       │   │
│  │  4. 尽早触发首屏渲染 → 减少白屏时间                              │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  CRP 时间线示意：                                                       │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  HTML 下载 → HTML 解析 → CSS 下载 → CSS 解析 → 样式计算 →       │   │
│  │  布局 → 绘制 → 光栅化 → 合成 → 首屏显示                         │   │
│  │                                                                 │   │
│  │  ↑                                              ↑               │   │
│  │  └──────────────── CRP 时间 ──────────────────┘                │   │
│  │                                                                 │   │
│  │  优化方向：                                                       │   │
│  │  - 减少 HTML 体积 → 缩短 HTML 下载和解析时间                     │   │
│  │  - 内联关键 CSS → 消除 CSS 下载瓶颈                              │   │
│  │  - 延迟非关键 JS → 避免阻塞渲染                                   │   │
│  │  - 使用资源提示 → 预加载关键资源                                  │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 12.2 优化策略详解

#### HTML 优化

```
│                    HTML 优化策略                                         │

│                                                                         │
```

#### CSS 优化

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    CSS 优化策略                                         │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  1. 内联关键 CSS                                                        │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  <head>                                                          │   │
│  │    <style>                                                       │   │
│  │      /* 首屏关键样式内联 */                                       │   │
│  │      body { margin: 0; }                                         │   │
│  │      .hero { min-height: 100vh; }                                │   │
│  │    </style>                                                      │   │
│  │    <link rel="stylesheet" href="non-critical.css">               │   │
│  │  </head>                                                         │   │
│  │                                                                 │   │
│  │  优点：消除首屏 CSS 下载延迟                                       │   │
│  │  缺点：HTML 体积增大，无法缓存                                    │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  2. 使用 media 查询按需加载                                             │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  <link rel="stylesheet" href="mobile.css"                        │   │
│  │        media="(max-width: 768px)">                               │   │
│  │  <link rel="stylesheet" href="desktop.css"                       │   │
│  │        media="(min-width: 769px)">                               │   │
│  │                                                                 │   │
│  │  只加载当前设备需要的 CSS，减少传输量                              │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  3. CSS 压缩与优化                                                     │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  - 使用 CSS 压缩工具（cssnano, clean-css）                        │   │
│  │  - 移除未使用的 CSS（PurgeCSS, UnCSS）                            │   │
│  │  - 合并重复规则                                                  │   │
│  │  - 使用 CSS 变量减少重复                                          │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  4. 非关键 CSS 异步加载                                                  │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  <link rel="preload" href="non-critical.css" as="style"          │   │
│  │        onload="this.rel='stylesheet'">                           │   │
│  │                                                                 │   │
│  │  先使用 preload 预加载，加载完成后转换为 stylesheet               │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

#### JavaScript 优化

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    JavaScript 优化策略                                    │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  1. 延迟执行 JS                                                         │

│  2. 代码分割                                                            │

│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  - 使用 requestAnimationFrame 进行动画                            │   │
│  │  - 避免长时间同步计算                                             │   │

│  │  - 虚拟列表处理大量数据                                           │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  4. 资源提示                                                            │
│  ┌─────────────────────────────────────────────────────────────────┐   │
```

### 12.3 性能指标体系

#### 核心性能指标

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    Web Vitals 核心性能指标                               │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  指标                          │  目标值         │  说明          │   │
│  ├─────────────────────────────────────────────────────────────────┤   │
│  │  LCP (Largest Contentful Paint) │ < 2.5s        │ 最大内容渲染时间│   │
│  │  - 衡量首屏主要内容何时完成渲染                                  │   │
│  │  - 通常对应最大的图片或文本块                                    │   │
│  │                                                                 │   │
│  │  FID (First Input Delay)       │ < 100ms       │ 首次输入延迟   │   │
│  │  - 用户首次交互的响应时间                                        │   │
│  │  - 衡量页面的交互准备就绪程度                                    │   │
│  │                                                                 │   │
│  │  CLS (Cumulative Layout Shift)  │ < 0.1         │ 累积布局偏移   │   │
│  │  - 衡量页面布局的稳定性                                          │   │
│  │  - 不期望的布局偏移会影响用户体验                                │   │
│  │                                                                 │   │
│  │  FCP (First Contentful Paint)   │ < 1.8s        │ 首次内容渲染   │   │
│  │  - 页面首次显示任何内容的时间                                    │   │
│  │  - 比白屏时间更有意义的指标                                      │   │
│  │                                                                 │   │
│  │  TTI (Time to Interactive)     │ < 3.8s        │ 可交互时间     │   │
│  │  - 页面完全可交互的时间                                          │   │
│  │  - 包括所有 JS 执行完毕                                          │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  指标关系：                                                             │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  TTFB → FCP → LCP → TTI                                         │   │
│  │                                                                 │   │
│  │  TTFB: Time To First Byte（首字节时间）                           │   │
│  │  FCP: First Contentful Paint（首次内容渲染）                      │   │
│  │  LCP: Largest Contentful Paint（最大内容渲染）                    │   │
│  │  TTI: Time To Interactive（可交互时间）                           │   │
│  │  FID: First Input Delay（首次输入延迟）                           │   │
│  │  CLS: Cumulative Layout Shift（累积布局偏移）                     │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

```javascript
function processElements(elements) {
```

### 13.1 浏览器渲染原理相关题目

#### Q1: 请详细描述浏览器的渲染过程？

**答案要点：**

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    浏览器渲染流程答案框架                                 │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  1. 解析阶段                                                            │
│     - HTML 解析 → DOM 树                                                │
│     - CSS 解析 → CSSOM 树                                               │
│     - JS 执行（可能修改 DOM/CSSOM）                                    │
│                                                                         │
│  2. 样式阶段                                                            │
│     - 收集声明值、解决冲突、继承、默认值填充                              │
│     - 生成 Computed Style                                               │
│                                                                         │
│  3. 布局阶段                                                            │
│     - 构建布局树（过滤 display:none 元素）                               │
│     - 计算几何信息（尺寸、位置）                                        │
│                                                                         │
│  4. 分层阶段                                                            │
│     - 根据条件将布局树划分为多个图层                                     │
│     - 触发条件：transform, opacity, position: fixed 等                   │
│                                                                         │
│  5. 绘制阶段                                                            │
│     - 为每个图层生成绘制指令                                            │
│     - 按 z-index 顺序生成                                               │
│                                                                         │
│  6. 合成阶段                                                            │
│     - 分块 → 光栅化 → 合成 → 提交给 GPU                                 │
│     - 由合成线程和 GPU 完成                                             │
│                                                                         │
│  7. 显示阶段                                                            │
│     - GPU 输出到帧缓冲区 → 屏幕显示                                    │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

#### Q2: 什么是回流、重绘、合成？它们的区别是什么？

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    回流 vs 重绘 vs 合成                                  │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  回流 (Reflow):                                                         │
│  - 定义：元素的几何信息（位置、尺寸）变化时重新计算                       │
│  - 触发：修改 width, height, position, display 等                        │
│  - 性能：最慢                                                            │
│  - 影响范围：自身 + 所有子元素 + 可能影响兄弟元素                        │
│                                                                         │
│  重绘 (Repaint):                                                        │
│  - 定义：元素的外观变化但几何信息不变时重新绘制                           │
│  - 触发：修改 color, background-color, box-shadow 等                    │
│  - 性能：中等                                                            │
│  - 影响范围：自身及其子元素                                              │
│                                                                         │
│  合成 (Composite):                                                      │
│  - 定义：仅在合成阶段处理的操作                                         │
│  - 触发：transform（有独立图层）、opacity（有独立图层）                   │
│  - 性能：最快                                                            │
│  - 影响范围：仅当前图层                                                 │
│                                                                         │
│  性能排序：合成 < 重绘 < 回流                                            │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

#### Q3: CSS 会阻塞渲染吗？JS 会阻塞 DOM 解析吗？

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    CSS 与 JS 的阻塞行为                                   │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  CSS 资源：                                                              │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  - 外部 CSS (<link>): 不阻塞 DOM 解析，但阻塞渲染                 │   │
│  │  - 内联 CSS (<style>): 立即解析，不阻塞任何阶段                   │   │
│  │  - 原因：避免 FOUC（无样式内容闪烁）                               │   │
│  │  - 优化：内联关键 CSS，预加载非关键 CSS                             │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  JS 资源：                                                              │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  - 普通 script: 阻塞 DOM 解析，阻塞渲染                           │   │
│  │  - async script: 下载不阻塞，执行时短暂阻塞                       │   │
│  │  - defer script: 完全不阻塞，DOM 解析完成后按序执行                │   │
│  │  - 原因：JS 可能修改 DOM 结构（document.write、DOM 操作）         │   │
│  │  - 优化：使用 defer/async，将 script 放在 body 底部                │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 13.2 性能优化相关题目

#### Q4: 如何优化浏览器渲染性能？

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    渲染性能优化答案框架                                   │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  1. 减少回流                                                            │
│     - 使用 transform 代替 top/left/left/right                          │

│     - 使用独立图层隔离动画元素                                          │
│     - 避免不必要的视觉属性变化                                          │
│     - 使用 CSS 变量减少重复计算                                        │
│                                                                         │
│  3. 使用合成                                                            │
│     - 动画使用 transform 和 opacity                                    │
│     - 触发独立图层（will-change, transform: translateZ(0)）             │
│     - GPU 加速                                                          │
│                                                                         │
│  4. 优化 CRP                                                            │
│     - 内联关键 CSS                                                      │
│     - 延迟非关键 JS（defer/async）                                     │
│     - 使用 preload/preconnect/dns-prefetch                              │
│     - 压缩 HTML/CSS/JS                                                 │
│                                                                         │
│  5. 优化交互性能                                                        │
│     - 避免强制同步布局                                                  │
│     - 使用 requestAnimationFrame 进行动画                               │
│     - 使用 Web Worker 处理耗时任务                                      │
│     - 减少主线程阻塞时间                                                │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

#### Q5: 什么是关键渲染路径？如何优化？

```
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  定义：                                                                 │
│  - 浏览器从接收 HTML 到渲染出首屏内容的最短时间路径                     │
│  - 包括：HTML 下载 → 解析 → CSS 下载 → 解析 → 样式计算 → 布局 → 绘制  │
│                                                                         │
│  优化方法：                                                             │
│                                                                         │
│  1. 优化 HTML                                                           │
│     - 压缩 HTML 文件大小                                                │
│     - 精简 DOM 结构                                                     │
│     - 延迟加载非关键资源                                                │
│                                                                         │
│  2. 优化 CSS                                                            │
│     - 内联关键 CSS（消除下载瓶颈）                                      │
│     - 按设备加载不同的 CSS（media query）                                │
│     - 使用 preload 预加载关键 CSS                                       │
│     - 压缩 CSS，移除未使用的规则                                        │
│                                                                         │
│  3. 优化 JavaScript                                                     │
│     - 将 script 放在 body 底部                                          │
│     - 使用 defer/async 延迟执行                                         │
│     - 代码分割（按需加载）                                              │
│     - 减少首屏 JS 代码量                                                │
│                                                                         │
│  4. 资源提示                                                            │
│     - <link rel="preload"> 预加载关键资源                                │
│     - <link rel="preconnect"> 预连接关键域名                                │
│     - <link rel="dns-prefetch"> DNS 预解析                              │
```

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    浏览器渲染流水线总结                                   │

│  渲染流水线：                                                           │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │

│  各阶段关键要点：                                                       │
│                                                                         │

│                                                                         │
│  CSS 解析:                                                              │

│  - 生成矢量绘制指令                                                     │
│  - 按 z-index 顺序绘制                                                 │
│                                                                         │
│  分块 + 光栅化:                                                         │
│  - 大图层层划分为 Tile                                                  │
│  - GPU 并行光栅化                                                       │
│  - 视口优先策略                                                         │

│  - 多图层按序叠加                                                       │
```

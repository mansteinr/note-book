## 一、向量数据库概述

### 1.1 什么是向量数据库

向量数据库（Vector Database）是专门用于存储、管理和查询高维向量数据的数据库系统。它将非结构化数据（如文本、图像、音频等）通过嵌入模型转换为高维向量，并提供高效的相似性搜索能力。

### 1.2 核心概念

- **向量（Vector）**：由嵌入模型生成的高维浮点数数组，表示数据的语义特征
- **嵌入（Embedding）**：将非结构化数据转换为向量的过程
- **相似性搜索（Similarity Search）**：基于距离度量（如余弦相似度、欧氏距离）查找最相似的向量
- **索引（Index）**：加速向量搜索的数据结构，如 HNSW、IVF 等

### 1.3 常见应用场景

| 应用场景 | 说明 |
|---------|------|
| RAG（检索增强生成） | 结合大语言模型，提供外部知识检索 |
| 语义搜索 | 基于语义相似度而非关键词匹配进行搜索 |
| 推荐系统 | 基于用户/物品向量相似度进行推荐 |
| 图像检索 | 以图搜图、相似图片查找 |
| 去重检测 | 文本/图像/音频的相似性检测与去重 |
| 异常检测 | 识别与正常模式偏离的异常数据 |

## 二、Milvus 向量数据库

### 2.1 简介

**Milvus** 是一款开源的、专为海量特征向量设计的高性能向量数据库，由 Zilliz 公司开发并捐赠给 Linux AI 基金会（LF AI & Data）。

**核心特点：**
- 开源免费，社区活跃
- 支持多种向量索引类型（HNSW、IVF、DiskANN 等）
- 支持分布式部署，水平扩展能力强
- 提供丰富的 SDK（Python、Java、Go、Node.js 等）
- 支持混合查询（向量搜索 + 标量过滤）
- 支持多租户和权限管理

**架构组件：**
- **Access Layer**：对外提供 RESTful API 和 SDK 接口
- **Coordinator Service**：集群管理、元数据管理、任务调度
- **Worker Nodes**：执行具体的计算任务（数据节点、查询节点、索引节点）
- **Storage**：底层存储（支持 MinIO、S3、HDFS 等）

### 2.3 常用语法（Python SDK）

#### 2.3.1 连接与集合管理

```python
from pymilvus import connections, Collection, FieldSchema, CollectionSchema, DataType

# 连接 Milvus
connections.connect("default", host="localhost", port="19530")

# 定义字段
fields = [
    FieldSchema(name="id", dtype=DataType.INT64, is_primary=True, auto_id=True),
    FieldSchema(name="text", dtype=DataType.VARCHAR, max_length=65535),
    FieldSchema(name="embedding", dtype=DataType.FLOAT_VECTOR, dim=768)
]

# 创建集合
schema = CollectionSchema(fields, description="文本向量集合")
collection = Collection(name="text_vectors", schema=schema)

# 创建索引
index_params = {
    "index_type": "HNSW",
    "metric_type": "COSINE",
    "params": {"M": 16, "efConstruction": 256}
}
collection.create_index(field_name="embedding", index_params=index_params)

# 加载集合到内存
collection.load()

# 删除集合
# collection.drop()
```

#### 2.3.2 数据插入

```python
import random

# 准备数据
texts = ["这是第一条文本", "这是第二条文本", "这是第三条文本"]
embeddings = [[random.random() for _ in range(768)] for _ in range(3)]

# 插入数据
data = [texts, embeddings]
result = collection.insert(data)
print(f"插入了 {result.insert_count} 条数据")
```

#### 2.3.3 向量搜索

```python
# 搜索参数
search_params = {
    "metric_type": "COSINE",
    "params": {"ef": 128}
}

# 执行搜索
results = collection.search(
    data=[query_embedding],  # 查询向量
    anns_field="embedding",  # 向量字段
    param=search_params,
    limit=10,                # 返回 Top-K
    output_fields=["text"]   # 输出字段
)

# 处理结果
for hits in results:
    for hit in hits:
        print(f"ID: {hit.id}, 距离: {hit.distance}, 文本: {hit.entity.get('text')}")
```

#### 2.3.4 混合查询（向量搜索 + 标量过滤）

```python
# 带过滤条件的搜索
results = collection.search(
    data=[query_embedding],
    anns_field="embedding",
    param=search_params,
    limit=10,
    expr="id > 100",  # 过滤条件
    output_fields=["text"]
)
```

#### 2.3.5 数据删除与更新

```python
# 删除数据（按主键）
collection.delete(expr="id in [1, 2, 3]")

# 更新数据（Milvus 不支持直接更新，需删除后重新插入）
collection.delete(expr="id == 1")
collection.insert([["更新后的文本"], [new_embedding]])
```

### 2.4 Milvus 支持的索引类型

| 索引类型 | 适用场景 | 特点 |
|---------|---------|------|
| **HNSW** | 中小规模数据，高召回率要求 | 基于图的索引，查询速度快，召回率高，内存占用大 |
| **IVF_FLAT** | 大规模数据，内存受限 | 倒排索引 + 暴力搜索，内存占用较小 |
| **IVF_PQ** | 超大规模数据，内存受限 | 倒排索引 + 乘积量化，压缩向量，内存占用小 |
| **DiskANN** | 超大规模数据，磁盘存储 | 基于磁盘的图索引，内存占用极小 |
| **FLAT** | 小规模数据，100% 召回率 | 暴力搜索，精确但速度慢 |

### 2.5 距离度量方式

| 度量方式 | 说明 | 适用场景 |
|---------|------|---------|
| **COSINE** | 余弦相似度 | 文本语义相似度，归一化向量 |
| **L2** | 欧氏距离 | 图像特征相似度 |
| **IP** | 内积 | 已归一化的向量，等价于余弦相似度 |

## 三、Pinecone 向量数据库

### 3.1 简介

**Pinecone** 是一款全托管的云原生向量数据库，无需管理基础设施，开箱即用。

**核心特点：**
- 全托管服务，无需运维
- 自动扩缩容，按需付费
- 支持实时索引更新
- 提供 RESTful API 和多语言 SDK
- 支持命名空间（Namespace）实现多租户隔离
- 内置向量元数据过滤

**适用场景：**
- 快速原型开发和 MVP
- 不想维护基础设施的团队
- 需要全球分布式部署的应用
- 对延迟要求较高的实时应用

### 3.2 安装与配置

```bash
pip install pinecone-client
```

```python
from pinecone import Pinecone

# 初始化客户端
pc = Pinecone(api_key="your-api-key")
```

### 3.3 常用语法（Python SDK）

#### 3.3.1 索引管理

```python
from pinecone import ServerlessSpec

# 创建索引
pc.create_index(
    name="text-vectors",
    dimension=768,                    # 向量维度
    metric="cosine",                  # 距离度量
    spec=ServerlessSpec(
        cloud="aws",                  # 云服务商
        region="us-west-2"            # 区域
    )
)

# 获取索引信息
index = pc.Index("text-vectors")
print(index.describe_index_stats())

# 删除索引
# pc.delete_index("text-vectors")
```

#### 3.3.2 数据插入

```python
# 单条插入
index.upsert(
    vectors=[
        {
            "id": "vec1",
            "values": [0.1, 0.2, ...],  # 768维向量
            "metadata": {"text": "这是第一条文本", "category": "tech"}
        }
    ],
    namespace="ns1"  # 命名空间（可选）
)

# 批量插入
vectors = [
    {"id": f"vec{i}", "values": embedding, "metadata": {"text": text}}
    for i, (text, embedding) in enumerate(data)
]
index.upsert(vectors=vectors, batch_size=100, namespace="ns1")
```

#### 3.3.3 向量搜索

```python
# 基础搜索
results = index.query(
    vector=query_embedding,
    top_k=10,
    include_metadata=True,
    namespace="ns1"
)

for match in results.matches:
    print(f"ID: {match.id}, 分数: {match.score}, 文本: {match.metadata['text']}")

# 带过滤条件的搜索
results = index.query(
    vector=query_embedding,
    top_k=10,
    filter={"category": {"$eq": "tech"}},  # 元数据过滤
    include_metadata=True
)
```

#### 3.3.4 数据删除

```python
# 按 ID 删除
index.delete(ids=["vec1", "vec2", "vec3"], namespace="ns1")

# 按过滤条件删除
index.delete(filter={"category": {"$eq": "old"}}, namespace="ns1")

# 删除命名空间下所有数据
index.delete(delete_all=True, namespace="ns1")
```

#### 3.3.5 更新向量

```python
# 更新向量及其元数据
index.update(
    id="vec1",
    values=new_embedding,
    set_metadata={"text": "更新后的文本", "category": "updated"},
    namespace="ns1"
)
```

### 3.4 Pinecone 索引类型

| 索引类型 | 说明 | 特点 |
|---------|------|------|
| **Serverless** | 无服务器索引 | 自动扩缩容，按使用量付费，适合波动负载 |
| **Provisioned** | 预配置索引 | 固定资源，可预测性能，适合稳定负载 |

### 3.5 元数据过滤操作符

| 操作符 | 说明 | 示例 |
|-------|------|------|
| `$eq` | 等于 | `{"category": {"$eq": "tech"}}` |
| `$ne` | 不等于 | `{"category": {"$ne": "old"}}` |
| `$gt` | 大于 | `{"score": {"$gt": 0.8}}` |
| `$gte` | 大于等于 | `{"score": {"$gte": 0.7}}` |
| `$lt` | 小于 | `{"score": {"$lt": 0.5}}` |
| `$in` | 在列表中 | `{"category": {"$in": ["tech", "ai"]}}` |
| `$nin` | 不在列表中 | `{"category": {"$nin": ["spam"]}}` |

## 四、常见面试题

### 4.1 基础概念题

**Q1：什么是向量数据库？与传统数据库有什么区别？**

**答：**
向量数据库是专门用于存储和查询高维向量的数据库，核心能力是高效的相似性搜索。

| 对比维度 | 传统数据库 | 向量数据库 |
|---------|-----------|-----------|
| 数据类型 | 结构化数据（行、列） | 高维向量 + 元数据 |
| 查询方式 | 精确匹配（WHERE） | 相似性搜索（最近邻） |
| 索引结构 | B+树、Hash | HNSW、IVF、PQ 等 |
| 典型场景 | 业务数据 CRUD | 语义搜索、推荐、RAG |

**Q2：什么是 Embedding？如何选择合适的 Embedding 模型？**

**答：**
Embedding 是将非结构化数据（文本、图像等）转换为固定维度向量的过程。

选择 Embedding 模型时考虑：
- **任务类型**：文本用 BERT/GTE，图像用 CLIP/ResNet
- **向量维度**：维度越高表达能力越强，但存储和计算成本增加
- **语言支持**：中文场景选择中文优化模型（如 bge-large-zh）
- **性能基准**：参考 MTEB 等榜单的排名

**Q3：常见的向量距离度量方式有哪些？分别适用于什么场景？**

**答：**

| 度量方式 | 公式 | 适用场景 |
|---------|------|---------|
| 余弦相似度 | cos(θ) = A·B / (||A|| × ||B||) | 文本语义相似度，方向敏感 |
| 欧氏距离 | √Σ(Ai - Bi)² | 图像特征，绝对距离敏感 |
| 内积 | A·B = ΣAi × Bi | 已归一化向量，等价余弦 |

### 4.2 索引与性能题

**Q4：HNSW 索引的原理是什么？有什么优缺点？**

**答：**
HNSW（Hierarchical Navigable Small World）是基于图的分层索引结构。

**原理：**
- 构建多层导航图，上层稀疏用于快速定位，下层稠密保证召回率
- 搜索时从顶层开始，逐层向下导航，最终在底层找到最近邻

**优点：**
- 查询速度极快（O(log N)）
- 召回率高（可达 99%+）
- 支持增量更新

**缺点：**
- 内存占用大（需存储图结构）
- 构建索引时间长
- 不适合超大规模数据（需配合分布式）

**Q5：如何优化向量数据库的查询性能？**

**答：**

1. **索引优化**
   - 选择合适的索引类型（HNSW 适合中小规模，IVF 适合大规模）
   - 调整索引参数（HNSW 的 M 和 efConstruction）

2. **查询优化**
   - 调整搜索参数（HNSW 的 ef，IVF 的 nprobe）
   - 使用标量过滤减少候选集
   - 批量查询代替单条查询

3. **架构优化**
   - 水平扩展查询节点
   - 使用 SSD 存储索引
   - 预热热点数据到内存

4. **向量优化**
   - 降维（PCA、AutoEncoder）
   - 向量量化（PQ、SQ）
   - 归一化预处理

**Q6：向量数据库如何保证高可用性？**

**答：**

- **副本机制**：数据多副本存储，节点故障自动切换
- **分片策略**：数据分片分布到多个节点，避免单点故障
- **Raft 协议**：元数据节点使用 Raft 保证一致性
- **健康检查**：定期检测节点状态，自动剔除故障节点
- **灰度发布**：滚动升级，避免全集群不可用

### 4.3 应用场景题

**Q7：RAG 系统中向量数据库的作用是什么？**

**答：**

在 RAG（Retrieval-Augmented Generation）中，向量数据库负责：

1. **知识存储**：将外部知识文档转换为向量并存储
2. **语义检索**：根据用户问题检索最相关的知识片段
3. **上下文构建**：将检索结果作为上下文提供给 LLM

**流程：**
```
用户问题 → Embedding → 向量检索 → Top-K 文档 → 构建 Prompt → LLM 生成回答
```

**优化点：**
- 文档分块策略（按段落、固定长度、语义分块）
- 混合检索（向量检索 + 关键词检索）
- 重排序（Reranker 对检索结果二次排序）

**Q8：向量数据库在推荐系统中的应用？**

**答：**

1. **用户/物品向量化**：将用户行为和物品特征转换为向量
2. **相似性召回**：基于向量相似度快速召回候选物品
3. **实时推荐**：用户行为更新后实时调整推荐结果

**优势：**
- 支持海量候选集的高效召回
- 捕捉深层语义相似性
- 支持多模态推荐（文本 + 图像 + 视频）

**Q9：如何处理向量数据库的更新操作？**

**答：**

向量数据库的更新策略：

| 策略 | 说明 | 适用场景 |
|-----|------|---------|
| 删除 + 插入 | 先删除旧向量，再插入新向量 | 更新频率低的场景 |
| Upsert | 如果 ID 存在则更新，否则插入 | 需要原子更新的场景 |
| 版本管理 | 保留历史版本，查询时指定版本 | 需要追溯历史的场景 |

**注意事项：**
- 频繁更新会影响索引性能
- 批量更新优于单条更新
- 更新后需重新计算向量（如果原始数据变化）

### 4.4 对比与选型题

**Q10：Milvus 和 Pinecone 如何选择？**

**答：**

| 对比维度 | Milvus | Pinecone |
|---------|--------|----------|
| 部署方式 | 自建/云托管 | 全托管 SaaS |
| 开源性 | 开源 | 闭源 |
| 成本 | 自建成本低，云版本较高 | 按使用量付费 |
| 运维复杂度 | 需自行运维（自建） | 零运维 |
| 定制性 | 高度可定制 | 有限定制 |
| 数据主权 | 数据在自己手中 | 数据在第三方 |
| 适用场景 | 大规模、高定制需求 | 快速开发、中小规模 |

**选择建议：**
- 选择 Milvus：数据敏感、需要私有化部署、有运维能力、大规模数据
- 选择 Pinecone：快速验证、不想运维、中小规模、预算充足

**Q11：向量数据库与传统数据库的 ANN 搜索有什么区别？**

**答：**

| 对比维度 | 向量数据库 | 传统数据库 ANN |
|---------|-----------|---------------|
| 索引结构 | 专用向量索引（HNSW、IVF） | 通用索引（B+树） |
| 查询性能 | 毫秒级（百万级数据） | 秒级（需全表扫描或近似） |
| 扩展性 | 水平扩展，支持十亿级向量 | 垂直扩展，扩展性有限 |
| 功能完整性 | 支持混合查询、元数据过滤 | 需额外开发 |

**Q12：向量数据库的局限性有哪些？**

**答：**

1. **语义鸿沟**：Embedding 模型无法完全捕捉所有语义信息
2. **更新成本**：向量更新需重新计算，成本较高
3. **可解释性差**：向量相似度难以解释业务含义
4. **存储成本**：高维向量占用大量存储空间
5. **冷启动问题**：新数据缺乏历史行为，Embedding 质量低

**解决方案：**
- 混合检索（向量 + 关键词）弥补语义鸿沟
- 增量索引减少更新成本
- 结合业务规则提升可解释性
- 向量压缩技术降低存储成本

## 五、总结

向量数据库是 AI 时代的关键基础设施，Milvus 和 Pinecone 分别代表了开源和云托管两种典型方案。选择合适的向量数据库需要综合考虑数据规模、运维能力、成本预算和数据主权等因素。

**核心要点：**
1. 理解向量数据库的核心价值：高效的相似性搜索
2. 掌握索引原理：HNSW、IVF 等索引的适用场景
3. 熟悉 RAG 应用：向量数据库在 LLM 应用中的关键作用
4. 关注性能优化：索引参数、查询策略、架构设计
5. 合理选型：根据业务需求选择开源或云托管方案

# 面试题文档生成器

## 技能用途

根据指定的技术方向，生成结构完整、内容详实的 Markdown 面试题文档。适用于前端、后端、移动端、算法、架构等各类技术面试备考场景。

## 触发条件

当用户的请求符合以下任一情况时调用本技能：

- 「生成 XX 面试题」「XX 高频面试题」「XX 面试问题详解」
- 「XX 常见问题及答案」「XX 面试题库」
- 「XX 面试问题与详细回答」
- 用户要求输出某技术栈的面试准备文档

## 文档结构规范

生成的文档必须包含以下完整结构，**不可省略任何模块**：

### 1. 文档头部

- 一级标题：`# XX 面试题与详细回答`
- 引用块：文档定位、适用人群、阅读建议

### 2. 目录（必须符合 Markdown 语法）

- 使用无序列表 `- [标题](#锚点)` 格式
- 锚点为标题的小写拼音或英文（自动生成）
- 包含所有二级标题和重要三级标题

### 3. 章节内容

按「由浅入深」的原则组织章节，每道题包含：

- **核心答案**：简明扼要的结论
- **原理讲解**：深入分析为什么
- **代码示例**：完整可运行的代码片段（带注释）
- **对比表格**：多方案对比时使用
- **项目实战踩坑**：真实生产环境的问题与解决方案
- **Mermaid 图**：架构图、流程图、时序图（至少 3-5 个）

### 4. 速答卡片（必选）

- 10-15 道 20 秒可答完的高频问题
- 一问一答格式，便于面试前快速过一遍

### 5. 实战踩坑案例（必选）

- 8-10 个真实生产环境踩坑案例
- 表格格式：场景 / 现象 / 根因 / 解决

### 6. 复习优先级表（必选）

- P0（必考）/ P1（高频）/ P2（中频）/ P3（低频）
- 每级别标注考察概率和建议复习时间

### 7. Mermaid 流程图（必选）

- 至少一张复习路线图（P0 → P1 → P2 → P3）

## 题量与章节规划建议

| 文档规模 | 题量 | 章节数 | 适用 |
|---------|------|--------|------|
| 小型 | 15-20 题 | 5-6 章 | 单一概念（如 Promise、Flex） |
| 中型 | 30-40 题 | 7-8 章 | 技术方向（如 Vue3、小程序） |
| 大型 | 40-50+ 题 | 8-10 章 | 完整技术栈（如 React 全家桶、Hybrid） |

默认按「中型」生成，除非用户明确要求数量。

## 常见技术方向题库模板

生成时根据方向自动匹配以下模块：

### 前端方向
1. 基础概念（HTML/CSS/JS）
2. 框架核心（Vue/React 原理）
3. 工程化（构建、打包、性能）
4. 浏览器原理（渲染、事件、存储）
5. 网络与安全（HTTP、HTTPS、XSS）
6. 综合实战设计题

### 移动端 / Hybrid 方向
1. 视口与适配（DPR、REM/VW）
2. WebView 与 JSBridge
3. 事件与手势（Touch、passive）
4. 性能优化（首屏、长列表）
5. 兼容性（iOS/Android 差异）
6. 框架结合（Vue3/React 在 Hybrid 中）

### 后端方向
1. 语言基础（Java/Python/Go）
2. 框架原理（Spring、Django）
3. 数据库（MySQL、Redis）
4. 中间件（Kafka、MQ）
5. 系统设计（缓存、限流、分布式）
6. 算法与数据结构

## 输出要求

1. **代码注释用中文**（与用户语言一致）
2. **所有代码必须包含完整 import / 依赖**，确保可运行
3. **对比表格至少 5 列以上**，信息密度高
4. **Mermaid 图用 flowchart / sequenceDiagram / stateDiagram**
5. **每章至少 1 个表格或 1 个代码块**
6. 避免空洞的「看情况」「视需求而定」，给出明确选型建议

## 交付路径

- 默认保存到当前工作目录，文件名：`XX面试题详解.md`
- 如用户指定 JavaScript 目录，移动到 `M:\note-book\JavaScript\`
- 生成后简要汇报章节数、题量、特色模块

## 质量自检清单

生成完成后必须验证：

- [ ] 目录结构完整，锚点可跳转
- [ ] 每题有核心答案 + 代码/表格/图至少一项
- [ ] 包含速答卡片、踩坑案例、优先级表
- [ ] Mermaid 图数量 ≥ 3
- [ ] 代码无语法错误，import 完整
- [ ] 无敏感信息、无真实密钥/URL

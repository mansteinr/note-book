## 一、埋点监控概述

### 1.1 什么是前端埋点监控？

**前端埋点监控（Frontend Instrumentation & Observability）** 是在用户访问 Web 页面或 App 的过程中，通过在特定位置（按钮、页面、组件、接口调用）主动嵌入"探针"（即埋点代码），采集用户行为、页面性能、技术异常、业务转化等数据，经过清洗、建模、存储后，用于可视化分析、异常告警、驱动产品迭代的一整套工程体系。

```
┌─────────────────────────────────────────────────────────────────┐
│                      前端埋点监控闭环                               │
│                                                                   │
│   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐     │
│   │  埋点采集 │ → │ 数据传输 │ → │ 处理建模 │ → │ 可视化分析│     │
│   │  (SDK)   │   │ (Kafka)  │   │(ETL/CK)  │   │(Grafana) │     │
│   └──────────┘   └──────────┘   └──────────┘   └────┬─────┘     │
│        ↑                                              │           │
│        │ 埋点规范/动态配置                     告警/决策/洞察      │
│        │                                              ↓           │
│   ┌──────────┐                                  ┌──────────┐     │
│   │ 埋点管理平台│ ←── 数据驱动的埋点迭代 ──────── │ 产品与运营  │     │
│   └──────────┘                                  └──────────┘     │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 埋点监控的核心价值

| 价值维度 | 具体收益 | 典型场景 |
|---------|---------|---------|
| **数据驱动产品决策** | 用真实用户行为替代"拍脑袋"判断 | 首页改版后核心按钮点击率下降 20% → 立即回滚 |
| **转化漏斗诊断** | 精准定位用户流失环节 | 下单流程支付环节流失率从 5% → 排查发现支付 SDK 报错率异常 |
| **体验度量与优化** | 量化页面性能（LCP/FID/CLS），指导性能优化 | LCP 从 3.2s → 优化至 1.5s，转化率提升 8% |
| **线上问题秒级定位** | 无需用户复现，通过埋点还原操作路径 | 用户反馈"白屏" → 排查到特定浏览器下 JS 报错率突增 |
| **运营效果量化** | 评估活动、弹窗、推荐位 ROI | 618 活动 Banner 带来 GMV 2000 万，ROI 1:5 |
| **安全与合规审计** | 敏感操作可追溯、风控告警 | 批量异常登录 → 触发风控告警并自动封禁 IP |

### 1.3 埋点监控 vs 传统 APM vs 错误监控

| 维度 | **前端埋点监控（本方案）** | **传统 APM（New Relic / Datadog）** | **纯错误监控（Sentry）** |
|------|--------------------------|------------------------------------|------------------------|
| 采集重点 | 用户行为 + 性能 + 错误 + 业务转化全链路 | 接口性能、资源加载、调用链路 | 仅 JS/Promise/接口报错 |
| 业务语义 | ✅ 强（事件名、自定义参数、漏斗） | ❌ 弱（仅资源/接口维度） | ❌ 几乎无 |
| 可视化 | ✅ 自定义看板、漏斗、留存 | ✅ 通用看板 | ⚠️ 仅错误面板 |
| 定制化程度 | 高（SDK 全开源，事件任意扩展） | 中（闭源 SaaS 限制） | 低（固定错误字段） |
| 成本 | 低（自建 ClickHouse） | 高（按 GB/事件数计费） | 中 |
| 数据归属 | ✅ 自有存储、完全可控 | ❌ 数据发送给第三方 | ⚠️ 发送给第三方 |

## 三、埋点数据模型与规范

### 3.1 三类核心埋点

```
埋点分类体系
├── 1. 曝光埋点（Exposure / Show）
│   ├── 定义：元素出现在可视区域 ≥ N% 且持续 T 毫秒
│   ├── 触发：IntersectionObserver + 时间阈值防抖
│   └── 典型场景：商品卡片、Banner 位、推荐结果、页面首屏
│
├── 2. 点击埋点（Click / Action）
│   ├── 定义：用户主动触发的交互操作
│   ├── 触发：addEventListener('click') / Vue 指令 / React onClick
│   └── 典型场景：按钮、Tab 切换、下单、收藏、搜索
│
└── 3. 页面/流程埋点（PageView / Event）
    ├── 定义：页面级或业务流程级事件
    ├── 触发：Vue Router beforeEach / React Router onRouteChange
    └── 典型场景：页面进入/离开、下单开始→完成、注册流程各步骤
```

| 类型 | 前缀 | 示例 | 采集方式 |
|------|-----|------|---------|
| **曝光** | `show_xxx` / `expose_xxx` | `show_product_card` | 自动（IntersectionObserver） |
| **点击** | `click_xxx` / `tap_xxx` | `click_add_to_cart` | 指令/Hook + 手动 |
| **页面访问** | `page_xxx` | `page_product_detail` | 路由钩子自动 |
| **业务流程** | `evt_xxx` / `biz_xxx` | `evt_order_create_success` | 代码手动 |
| **技术事件** | `tech_xxx` | `tech_js_error`、`tech_web_vitals` | SDK 自动 |

### 3.3 用户身份标识方案

```
身份识别优先级（从高到低）
├── 1. 登录态 user_id（后端 SSO/JWT）  ← 首选（最稳定）
│      ↳ 登录事件时触发 setIdentity(user_id)
│      ↳ 退出登录时回退到 anonymous_id
│
├── 2. 历史登录痕迹（login_id_30d cookie）
│      ↳ 用户 30 天内登录过，优先作为 distinct_id
│
└── 3. 匿名设备 ID（anonymous_id，存储于 localStorage + 双写 cookie）
       ↳ 生成规则: 'a_' + uuid_v4()
       ↳ 同时存储在 localStorage（永久）和一级域名 cookie（365 天），跨子域
       ↳ 兼容 Safari 7 天 ITP 限制：首次访问后降级为后端生成的 device_id
```

```typescript
// sdk/src/identity.ts
export class IdentityManager {
  private readonly ANONYMOUS_KEY = 'track_anonymous_id';
  private readonly USER_KEY = 'track_user_id';

  getAnonymousId(): string {
    let id = localStorage.getItem(this.ANONYMOUS_KEY)
          ?? this.getCookie(this.ANONYMOUS_KEY);
    if (!id) {
      id = 'a_' + this.uuidv4();
      localStorage.setItem(this.ANONYMOUS_KEY, id);
      this.setCookie(this.ANONYMOUS_KEY, id, 365);
    }
    return id;
  }

  setUserId(userId: string | null): void {
    if (userId) localStorage.setItem(this.USER_KEY, userId);
    else localStorage.removeItem(this.USER_KEY);
  }

  getDistinctId(): string {
    return localStorage.getItem(this.USER_KEY) || this.getAnonymousId();
  }

  login(user_id: string): void {
    const old_distinct = this.getDistinctId();
    this.setUserId(user_id);
    const new_distinct = user_id;
    // 上报身份合并事件,服务端打通匿名→登录前后行为
    track('tech_user_bind', {
      old_distinct_id: old_distinct,
      new_distinct_id: new_distinct,
      bind_type: 'login',
    });
  }

  private uuidv4(): string {
    if (crypto && typeof crypto.randomUUID === 'function') return crypto.randomUUID();
    return 'xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx'.replace(/[xy]/g, (c) => {
      const r = (Math.random() * 16) | 0;
      return (c === 'x' ? r : (r & 0x3) | 0x8).toString(16);
    });
  }
  // setCookie / getCookie 实现略
}
```

### 3.4 埋点命名与版本规范

```typescript
import { IdentityManager } from './identity';
import { ContextCollector } from './context';
import { PerformanceMonitor } from './performance';
import { ErrorCollector } from './error';
import { RequestManager } from './request';
import type { TrackingEvent } from './types';

export interface TrackingSDKOptions {
  endpoint: string;
  app_id: string;
  app_version: string;
  batchSize?: number;
  flushInterval?: number;
  sampleRate?: number;       // 0 ~ 1
  debug?: boolean;
  plugins?: Array<(sdk: TrackingSDK) => void>;
}

export class TrackingSDK {
  private options: Required<TrackingSDKOptions>;
  private queue: EventQueue;
  private identity: IdentityManager;
  private ctx: ContextCollector;
  private perf: PerformanceMonitor;
  private err: ErrorCollector;
  private req: RequestManager;
  private started = false;
  private static _instance: TrackingSDK | null = null;

  static getInstance(options?: TrackingSDKOptions): TrackingSDK {
    if (!TrackingSDK._instance) {
      if (!options) throw new Error('[SDK] 首次初始化必须传 options');
      TrackingSDK._instance = new TrackingSDK(options);
    }
    return TrackingSDK._instance;
  }

  private constructor(options: TrackingSDKOptions) {
    this.options = Object.assign({
      batchSize: 20,
      flushInterval: 5000,
      sampleRate: 1.0,
      debug: false,
      plugins: [],
    }, options);
    this.queue = new EventQueue({
      maxSize: this.options.batchSize,
      onFlush: (batch) => this.req.sendBatch(batch),
    });
    this.identity = new IdentityManager();
    this.ctx = new ContextCollector();
    this.req = new RequestManager({ endpoint: this.options.endpoint, app_id: this.options.app_id });
    this.perf = new PerformanceMonitor((evt) => this.track(evt.event, evt.properties));
    this.err = new ErrorCollector((evt) => this.track(evt.event, evt.properties));
  }

  start(): void {
    if (this.started) return;
    this.started = true;
    // 采样控制:未命中采样则仅初始化但不上报
    if (Math.random() > this.options.sampleRate) return;

    this.perf.start();
    this.err.start();
    this.queue.startAutoFlush(this.options.flushInterval);

    // 页面可见性变化 & 关闭时立即刷
    document.addEventListener('visibilitychange', () => {
      if (document.visibilityState === 'hidden') this.queue.flush(true);
    });
    window.addEventListener('pagehide', () => this.queue.flush(true));

    // 安装插件
    this.options.plugins.forEach(p => p(this));

    // 启动事件
    this.track('page_app_launch', { cold_launch: true });
  }

  /** 核心埋点方法 */
  track(event: string, properties: Record<string, any> = {}): void {
    if (!this.started) return;
    // 采样过滤
    if (Math.random() > this.options.sampleRate) return;

    const baseCtx = this.ctx.collect();
    const evt: TrackingEvent = {
      event,
      event_id: this.uuid(),
      timestamp: Date.now(),
      local_time: new Date().toISOString(),
      event_version: this.ctx.getEventVersion(event),
      send_time: 0,
      ...baseCtx,
      user_id: this.identity.getUserId() || undefined,
      anonymous_id: this.identity.getAnonymousId(),
      distinct_id: this.identity.getDistinctId(),
      login_status: this.identity.getLoginStatus(),
      app_version: this.options.app_version,
      sdk_version: SDK_VERSION,
      session_id: this.identity.getSessionId(),
      session_event_index: this.identity.nextSessionIndex(),
      properties,
    };

    if (this.options.debug) {
      console.log(`[Track:%c${event}%c]`, 'color:#2ea043;font-weight:bold', '', evt);
    }
    this.queue.push(evt);
  }

  /** 身份绑定 */
  login(user_id: string, extra: Record<string, any> = {}) {
    this.identity.login(user_id);
    this.track('tech_user_bind', { bind_type: 'login', ...extra });
  }
  logout() {
    this.identity.logout();
    this.track('tech_user_bind', { bind_type: 'logout' });
  }

  /** 插件调用 */
  getContextCollector(): ContextCollector { return this.ctx; }
  getIdentity(): IdentityManager { return this.identity; }
  forceFlush(): Promise<void> { return this.queue.flush(true); }

  private uuid(): string {
    if (crypto && 'randomUUID' in crypto) return crypto.randomUUID();
    return 'ev_' + Math.random().toString(36).slice(2) + Date.now().toString(36);
  }
}

export const SDK_VERSION = '2.1.0';
```

```typescript
// sdk/src/core/event-queue.ts
import type { TrackingEvent } from './types';

interface QueueOptions {
  maxSize: number;
  onFlush: (batch: TrackingEvent[]) => Promise<void>;
}
/**
 * 事件队列：批量合并 + 空闲上报 + 页面卸载立即上报
 */
export class EventQueue {
  private buffer: TrackingEvent[] = [];
  private timer: number | null = null;
  private flushing = false;
  constructor(private options: QueueOptions) {}

  push(evt: TrackingEvent) {
    this.buffer.push(evt);
    if (this.buffer.length >= this.options.maxSize) {
      this.flush(false);
    }
  }

  startAutoFlush(intervalMs: number) {
    if (this.timer) return;
    this.timer = window.setInterval(() => this.flush(false), intervalMs);
  }

  async flush(immediate: boolean): Promise<void> {
    if (this.flushing && !immediate) return;
    if (this.buffer.length === 0) return;
    const batch = this.buffer.splice(0);
    // 补 send_time
    batch.forEach(e => e.send_time = Date.now());
    this.flushing = true;
    try {
      await this.options.onFlush(batch);
    } catch (e) {
      // 失败回滚
      this.buffer.unshift(...batch);
      console.warn('[Track] flush fail, rollback', e);
    } finally {
      this.flushing = false;
    }
  }
}
```

```typescript
// sdk/src/core/request.ts
export class RequestManager {
  constructor(private cfg: { endpoint: string; app_id: string }) {}

  /** 优先 sendBeacon(后台异步, 页面unload仍执行), 失败降级 fetch keepalive */
  async sendBatch(batch: TrackingEvent[]): Promise<void> {
    const payload = JSON.stringify({
      app_id: this.cfg.app_id,
      send_ts: Date.now(),
      events: batch,
    });
    const blob = new Blob([payload], { type: 'application/json' });

    // 1. sendBeacon (gzip 需服务端支持，此处由 Nginx 透明压缩)
    if (navigator.sendBeacon && navigator.sendBeacon(this.cfg.endpoint, blob)) {
      return;
    }
    // 2. fetch keepalive 兜底
    await fetch(this.cfg.endpoint, {
      method: 'POST',
      body: payload,
      headers: { 'Content-Type': 'application/json' },
      keepalive: true,
      credentials: 'include',
    });
  }
}
```

### 4.3 曝光采集（IntersectionObserver）

```typescript
// sdk/src/plugins/exposure.ts
import type { TrackingSDK } from '../core/sdk';

export interface ExposureOptions {
  threshold?: number;       // 元素可见比例阈值: 0.5 = 50% 进入视口
  minDuration?: number;     // 最短停留时间: 1000ms (防止快速滑动误统计)
  rootMargin?: string;      // 提前触发: '0px 0px -20% 0px'
  once?: boolean;           // 一次曝光后停止观察
}

/**
 * 曝光埋点插件:
 *   v-track:exposure="'show_product_card'"
 *   v-track:exposure="{event:'show_product_card', props:{sku_id:'xxx'}}"
 */
export function createExposureManager(sdk: TrackingSDK, defaultOpts: ExposureOptions = {}) {
  const defaults = {
    threshold: 0.5,
    minDuration: 1000,
    rootMargin: '0px',
    once: true,
    ...defaultOpts,
  };

  // 元素 → 进入时间
  const enterMap = new WeakMap<Element, number>();
  // 已曝光过的元素去重
  const exposed = new WeakSet<Element>();

  const io = new IntersectionObserver((entries) => {
    entries.forEach((entry) => {
      const el = entry.target;
      const binding = (el as any).__trackExposure as { event: string; props: any; opts: ExposureOptions };
      if (!binding) return;
      const opts = { ...defaults, ...binding.opts };

      if (entry.isIntersecting && entry.intersectionRatio >= opts.threshold!) {
        enterMap.set(el, Date.now());
        return;
      }
      // 离开视口 → 检查停留时长是否达标
      if (!entry.isIntersecting) {
        const enterAt = enterMap.get(el);
        enterMap.delete(el);
        if (!enterAt) return;
        const duration = Date.now() - enterAt;
        const exposureRatio = entry.intersectionRatio;
        if (duration >= opts.minDuration! && (!opts.once || !exposed.has(el))) {
          exposed.add(el);
          sdk.track(binding.event, {
            ...binding.props,
            _exposure: { duration, ratio: exposureRatio },
          });
          if (opts.once) io.unobserve(el);
        }
      }
    });
  }, { threshold: [0, defaults.threshold, 1.0], rootMargin: defaults.rootMargin });

  return {
    observe(el: Element, binding: { event: string; props?: any; opts?: ExposureOptions }) {
      (el as any).__trackExposure = binding;
      io.observe(el);
    },
    unobserve(el: Element) {
      io.unobserve(el);
      enterMap.delete(el);
    },
  };
}
```

### 4.4 Vue 3 指令埋点与组合式 API

```typescript
// sdk/src/integrations/vue3-plugin.ts
import type { App, Directive, DirectiveBinding } from 'vue';
import type { TrackingSDK } from '../core/sdk';
import { createExposureManager } from '../plugins/exposure';

/**
 * 使用方式:
 *   1. 安装: app.use(VueTrackingPlugin, { sdk })
 *   2. 点击: <button v-track:click="'click_submit_order'">提交订单</button>
 *           <button v-track:click="{event:'click_buy', props:{sku_id:'s1', price:99}}">购买</button>
 *   3. 曝光: <div v-track:exposure="'show_product_card'"
 *                v-track-exposure-props="{sku_id:'s1'}"></div>
 *   4. 页面: <router-view />（由 RouterPlugin 自动）
 */
export function VueTrackingPlugin(app: App, options: { sdk: TrackingSDK }) {
  const { sdk } = options;
  const exposureMgr = createExposureManager(sdk);

  const parseBinding = (binding: DirectiveBinding) => {
    if (typeof binding.value === 'string') return { event: binding.value, props: {} };
    return { event: binding.value.event, props: binding.value.props ?? {} };
  };

  // 点击/曝光通用指令 v-track:click / v-track:exposure
  const TrackDirective: Directive<HTMLElement> = {
    mounted(el, binding) {
      const arg = binding.arg || 'click';
      const { event, props } = parseBinding(binding);
      if (arg === 'click') {
        (el as any).__trackClickHandler = (ev: MouseEvent) => {
          sdk.track(event, {
            ...props,
            _element: {
              text: (el.textContent || '').trim().slice(0, 50),
              tag: el.tagName.toLowerCase(),
              id: el.id,
            },
            _mouse: { x: ev.clientX, y: ev.clientY },
          });
        };
        el.addEventListener('click', (el as any).__trackClickHandler, true);
      } else if (arg === 'exposure') {
        exposureMgr.observe(el, { event, props });
      }
    },
    unmounted(el, binding) {
      const arg = binding.arg || 'click';
      if (arg === 'click') {
        el.removeEventListener('click', (el as any).__trackClickHandler, true);
      } else if (arg === 'exposure') {
        exposureMgr.unobserve(el);
      }
    },
    updated(el, binding) {
      if (binding.arg === 'exposure' && binding.oldValue !== binding.value) {
        const { event, props } = parseBinding(binding);
        (el as any).__trackExposure.props = props;
        (el as any).__trackExposure.event = event;
      }
    },
  };

  app.directive('track', TrackDirective);

  // 全局 API: this.$track / useTrack()
  const trackApi = (event: string, props?: any) => sdk.track(event, props);
  app.config.globalProperties.$track = trackApi;
  app.provide('trackApi', trackApi);
}

/** 组合式 API hook */
import { getCurrentInstance } from 'vue';
export function useTrack() {
  const ctx = getCurrentInstance();
  const sdk = (ctx?.appContext.config.globalProperties as any)?._sdk
    ?? TrackingSDK.getInstance();
  return {
    track: (event: string, props?: any) => sdk.track(event, props),
    login: (uid: string) => sdk.login(uid),
    logout: () => sdk.logout(),
  };
}
```

### 6.2 数据清洗、校验与脱敏

```typescript
// server/src/etl/cleaner.ts
export class EventCleaner {
  private requiredFields = ['event', 'event_id', 'timestamp', 'distinct_id'];
  private maxPropertyBytes = 8 * 1024; // 单事件 properties 最多 8KB

  clean(events: any[]): any[] {
    const cleaned: any[] = [];
    for (const raw of events) {
      // 1. 必填字段
      if (!this.requiredFields.every(f => raw[f] !== undefined && raw[f] !== '')) continue;
      // 2. 时间校验(客户端篡改): 漂移超过 ±24h 以服务端接收时间覆盖
      const now = Date.now();
      if (Math.abs(raw.timestamp - now) > 24 * 3600 * 1000) raw.timestamp = now;
      // 3. 脱敏: 手机号/身份证/邮箱 打码; 敏感 cookie 丢弃
      raw.properties = this.desensitize(raw.properties || {});
      // 4. 超长截断
      const propStr = JSON.stringify(raw.properties);
      if (Buffer.byteLength(propStr, 'utf8') > this.maxPropertyBytes) {
        raw.properties_too_large = true;
        raw.properties = { _truncated: true };
      }
      // 5. 注入分区日期 (ClickHouse MergeTree 分区键)
      raw.partition_date = new Date(raw.timestamp).toISOString().slice(0, 10);
      cleaned.push(raw);
    }
    return cleaned;
  }

  private desensitize(props: Record<string, any>) {
    const rules: Array<[RegExp, (v: string) => string]> = [
      [/mobile|phone|^tel$/i, v => v.replace(/(\d{3})\d{4}(\d{4})/, '$1****$2')],
      [/email|mail/i, v => v.replace(/^(.).*@(.)/, '$1***@$2')],
      [/id_card|idcard|身份证/i, v => v.replace(/^(.{6})(.{8})(.{4})$/, '$1********$3')],
    ];
    const out: any = {};
    for (const [k, v] of Object.entries(props)) {
      if (typeof v === 'string') {
        const rule = rules.find(([re]) => re.test(k));
        out[k] = rule ? rule[1](v) : v;
      } else {
        out[k] = v;
      }
    }
    return out;
  }
}
```

## 九、性能优化与隐私合规

### 9.1 采集对页面性能的影响控制

**控制指标：SDK 对主线程占用 < 0.5%（10s 内占用 < 50ms），体积 < 30KB（gzip）。**

| 优化点 | 手段 | 效果 |
|-------|-----|-----|
| **代码体积** | Tree-shaking、纯 TS（无第三方运行时依赖）、插件按需引入 | gzip 20~25KB |
| **事件队列** | 批量发送 20 条/次，减少 HTTP 建联开销 | 上报次数减少 20× |
| **主线程避让** | 所有重操作（序列化/字段补全）包裹 `requestIdleCallback` / `setTimeout(,0)` | FID/INP 无明显上涨 |
| **曝光采集** | IntersectionObserver 全局共享实例，不为每个元素单独创建 | 0 DOM 开销 |
| **错误采集** | `addEventListener('error', ...)` 共享一个 handler，避免重复 | 原生几乎无开销 |
| **采样降载** | 流量高峰期可配置采样 10%，优先保留错误/性能事件 | 大幅降低数据量 |

```typescript
// 主线程避让封装
function idleRun<T>(fn: () => T, deadline = 50): Promise<T> {
  return new Promise((resolve) => {
    if ('requestIdleCallback' in window) {
      requestIdleCallback(() => resolve(fn()), { timeout: deadline });
    } else {
      setTimeout(() => resolve(fn()), 0);
    }
  });
}
```

### 9.2 数据上报策略（批量/离线/断点续传）

```
上报策略
├── 1. 批量上报（默认）
│   ├── 触发条件: buffer ≥ 20 条 ｜ 每 5 秒定时 ｜ 页面 visibilitychange 隐藏
│   └── 传输: navigator.sendBeacon + Blob（gzip 压缩）
│
├── 2. 离线/弱网降级
│   ├── 检测: navigator.onLine === false ｜ fetch 连续失败 2 次
│   ├── 存储: IndexedDB（localStorage 5MB 不够用），按 session_id 分片
│   └── 恢复: ononline 事件触发，从最早开始按序重发，每批 50 条
│
├── 3. 断点续传
│   ├── 每批带 last_event_id，服务端返回已接收最大 id，客户端跳过
│   └── 极端情况二次去重依赖 ClickHouse 侧 event_id + ReplacingMergeTree
│
└── 4. 紧急关闭
    ├── 配置中心下发 disabled: true，SDK 立即停止采集
    └── 同时 Nginx /api/track/* 临时返回 204 丢弃，服务端降级
```

```typescript
// IndexedDB 离线队列（简化版）
export class OfflineQueue {
  private db: IDBDatabase | null = null;
  private DB = 'track_offline'; private STORE = 'events';
  async open(): Promise<void> {
    if (this.db) return;
    return new Promise((resolve, reject) => {
      const req = indexedDB.open(this.DB, 1);
      req.onupgradeneeded = (e: any) => {
        const db: IDBDatabase = e.target.result;
        db.createObjectStore(this.STORE, { keyPath: 'seq', autoIncrement: true });
      };
      req.onsuccess = (e: any) => { this.db = e.target.result; resolve(); };
      req.onerror = reject;
    });
  }
  async enqueue(batch: any[]) {
    if (!this.db) await this.open();
    const tx = this.db!.transaction(this.STORE, 'readwrite');
    batch.forEach(e => tx.objectStore(this.STORE).add(e));
  }
  async dequeue(n: number): Promise<any[]> {
    if (!this.db) await this.open();
    return new Promise((resolve) => {
      const tx = this.db!.transaction(this.STORE, 'readwrite');
      const req = tx.objectStore(this.STORE).openCursor();
      const out: any[] = [];
      req.onsuccess = (e: any) => {
        const cur: IDBCursor = e.target.result;
        if (cur && out.length < n) { out.push(cur.value); cur.delete(); cur.continue(); }
        else resolve(out);
      };
    });
  }
}
```

### 9.3 隐私合规（GDPR / 个保法）

**强制合规清单：**

| 法规要求 | 实现方案 |
|---------|---------|
| 用户同意（Consent） | 首次访问弹出 Cookie/埋点授权弹窗，未授权前 SDK 不上报；仅采集必要信息 |

| 跨境数据传输 | 用户在中国大陆 → 数据存储于境内；海外节点按 GDPR 本地化存储 |

```typescript
export function createPrivacyPlugin(sdk: TrackingSDK) {

      localStorage.clear();

        method: 'POST',
        body: JSON.stringify({ distinct_id: did }),

    },
  };
```

### 10.4 常见问题排查手册

| 现象 | 可能根因 | 排查步骤 |
|-----|---------|---------|
| **没有任何埋点上报** | ① 未调用 `sdk.start()` ② 隐私授权未过 ③ endpoint 配置错 ④ CORS 跨域被拦截 | DevTools Network 过滤 `/v1/events` 查看是否发送 → Console 看 `[Track]` 日志（debug=true）→ 检查 `sendBeacon` 返回 false |

## 十一、前端埋点监控面试题集

### 初级面试题

**Q1：什么是前端埋点？它和后端打点有什么区别？**

> **答案**：前端埋点是在浏览器/小程序/APP 端主动嵌入探针代码，采集用户行为（点击/曝光/页面）、技术性能（Web Vitals）、错误（JS 报错）等事件；后端打点主要记录接口请求、数据库操作等服务端行为。两者最大差异：① 前端面向用户行为体验，后端面向系统运行；② 前端数据存在客户端篡改/弱网/SDK 兼容性风险，需服务端校验清洗；③ 前端数据量通常是后端 10~100 倍，对存储和查询引擎有更高要求。
>
> **知识点**：前端埋点的定义与定位
> **难度**：初级

**Q2：曝光埋点是什么？如何保证曝光埋点不重复、不漏、不误报？**

> **答案**：曝光埋点统计元素真实被用户看到的次数。实现要点：
>
> 1. **IntersectionObserver** 而不是 scroll 事件（不阻塞主线程）
> 2. **可视比例阈值**：元素 ≥ 50% 面积进入视口才视为曝光
> 3. **最短停留时长**：≥ 1000ms 才计曝光，防止快速滑动误统计
> 4. **去重**：WeakSet 记录已曝光元素；默认 once 模式曝光后停止观察
> 5. **滚动容器嵌套**：显式指定 `root` 参数为滚动父级
>
> **知识点**：IntersectionObserver、曝光口径
> **难度**：初级

**Q3：sendBeacon 是什么？为什么埋点 SDK 要用它？**

> **答案**：`navigator.sendBeacon(url, data)` 是浏览器原生 API，用于以异步 POST 请求在**后台**发送少量数据（约 64KB 上限）。
>
> 优势：
> - 即便在 `unload` / `visibilitychange` 等页面即将被销毁时，浏览器也会**保证请求发出**（普通 `fetch`/XHR 在页面销毁时会被取消）
> - **不阻塞主线程、不影响导航切换**（fetch keepalive 也能但兼容性差）
> - 不占用连接数配额
>
> 失败兜底：sendBeacon 返回 false 时，SDK 会用 `fetch(..., { keepalive: true })` 兜底，最后降级到 IndexedDB 离线队列。
>
> **知识点**：sendBeacon API 原理与使用场景
> **难度**：初级

### 中级面试题

**Q4：埋点数据链路中如何保证"不丢、不重、不乱"？**

> **答案**：
>
> 1. **不丢**：
>    - 三重上报通道（sendBeacon → fetch keepalive → IndexedDB 离线队列）
>    - Kafka 生产失败写磁盘重试；消费者消费失败死信队列
>    - ClickHouse 副本 + 每小时数据量对账（UV 同比波动）
> 2. **不重**：
>    - 每个事件生成 `uuid`（event_id）作为唯一键
>    - 接入网关用布隆过滤器按 event_id 24h 内去重
>    - ClickHouse 用 `ReplacingMergeTree(event_id)` 最终一致去重
> 3. **不乱（顺序）**：
>    - 同一用户事件 key 用 distinct_id，hash 到同一 Kafka 分区，保证分区内有序
>    - 事件自增 `session_event_index`；ClickHouse 查询时按 timestamp + index 重排
>
> **知识点**：去重、队列有序、丢数据治理
> **难度**：中级

**Q5：设计一个 SDK 需要考虑哪些性能影响控制？如果业务反馈接入埋点后页面变卡，如何定位？**

> **答案**：需要考虑的控制点（参见 9.1 节）：
>
> - 体积：gzip < 30KB，Tree-shaking + 插件按需
> - 事件循环：所有重操作走 `requestIdleCallback`，单次阻塞 < 5ms
> - DOM 监听：全局共享 1 个 IntersectionObserver，不为每个元素新实例
> - 内存：曝光 WeakMap/WeakSet 自动 GC
>
> 定位卡顿时：
> 1. Chrome Performance 面板录制 → 看 Main 主线程 Long Task 超过 50ms 调用栈
> 2. 二分排查：注释 SDK vs 不注释 SDK 对比，确认是 SDK 引入
> 3. SDK debug=true 看日志，统计 `track()` 调用次数 / 单次耗时
> 4. 排查重点：`JSON.stringify(properties)` 超大对象、曝光回调逻辑重复执行、批量上报里同步计算耗时
>
> **知识点**：性能优化、Long Task、Profiling
> **难度**：中级

**Q6：点击埋点如何用 Vue 3 自定义指令实现？写出核心代码。**

> **答案**：核心代码见本文档 4.4 节 `VueTrackingPlugin`。关键实现点：
> 1. 在 `mounted(el, binding)` 中解析绑定，支持字符串 `'click_add_to_cart'` 或对象 `{event, props}`
> 2. `addEventListener('click', handler, true)` 用捕获阶段保证即使业务方 `stopPropagation` 也能采集到
> 3. handler 中调用 `sdk.track()`，同时携带 `text/tag/id/mouse XY` 上下文
> 4. **`unmounted` 必须 `removeEventListener`**，否则 HMR/路由切换会造成内存泄漏和重复上报
> 5. 用全局 `__trackClickHandler` 挂载到元素上，保证 dev 模式重复挂载不会多次绑定
>
> **知识点**：Vue3 自定义指令、事件捕获与冒泡
> **难度**：中级

### 高级面试题

**Q7：如果日新增埋点事件 5 亿条，ClickHouse 该如何设计表结构 + 分区 + 索引 + TTL，保证查询速度 < 2s、月成本可控？**

> **答案**：
>
> 1. **表引擎**：`MergeTree`（默认），不要用 TinyLog/Log，不支持索引和并发。聚合视图用 `SummingMergeTree` / `AggregatingMergeTree` 预聚合减少明细扫描。
> 2. **分区键**：`PARTITION BY toYYYYMM(partition_date)`，按月分区 → 每分区数据量均匀，方便 TTL 自动删除。
> 3. **排序键（最重要）**：`ORDER BY (event, partition_date, cityHash64(distinct_id))`。核心查询模式是 "按事件 + 日期范围 + 用户去重"，cityHash64 让同 distinct_id 聚集方便 uniqExact。
> 4. **TTL 策略**：明细数据保留 365 天（`TTL partition_date + INTERVAL 365 DAY`）；聚合视图保留 3 年。
> 5. **索引粒度**：`index_granularity = 8192`（默认即可），大跨度扫描合适。
> 6. **宽表 vs JSON properties**：高频查询字段拆成独立列（event、distinct_id、platform、geo_*、session_id），长尾字段放 properties String，用 `JSONExtract` 查。**避免使用 Map 类型**（CH Map 不支持索引、空间膨胀）。
> 7. **冷热分层**：近 30 天 SSD，30~365 天 HDD，用 `storage_policy = 'ssd_hdd'` 自动迁移，成本下降 60%。
> 8. **查询加速**：业务看板全部走 `daily_event_pvuv` 这类 SummingMergeTree 预聚合表，而非明细表；Top N 查询用 `limit N by ...`。
>
> 按 5 亿/天估算：3 副本 × 每条平均 1.2KB（含索引）≈ 每日 1.8TB，365 天约 657TB；冷热分层 + 3 副本 LZ4 压缩（约 1:6），实际物理存储约 110TB，成本可控。
>
> **知识点**：ClickHouse 性能调优、MergeTree、分布式成本估算
> **难度**：高级

**Q8：如何设计一个"埋点零代码/低代码"方案？让产品同学在后台配置埋点，前端不用每次发版？**

> **答案**：分三层实现：
>
> **A. 配置层（埋点平台）**
> - 可视化选择器：用 Chrome 插件选中 DOM，自动生成稳定 CSS selector（避开动态 class，选 `data-track-id` / id / nth-child 组合）
> - 规则 DSL：`{ type: 'click', selector: '.product-list .item', event: 'click_product_item', props_map: { sku_id: 'dataset.skuId', title: 'innerText|slice(0,20)' } }`
> - 版本号 + 灰度规则（按 distinct_id hash 5% 生效）
>
> **B. SDK 层（动态执行引擎）**
> - 启动时拉取规则 JSON（缓存 + ETag）
> - **点击规则**：`document.addEventListener('click', 事件委托)` → 匹配 selector → 上报
> - **曝光规则**：对 selector 命中的所有元素调 IntersectionObserver.observe
> - **页面规则**：路由变化后匹配路径模式 → 触发 page_xxx
> - 灰度过滤：命中才生效，失败静默降级
>
> **C. 风险控制**
> - 规则必须走审批流 + 沙盒（先在 UAT 环境录屏回放验证）
> - 规则执行时长熔断：单规则 > 3ms 强制禁用，避免卡死页面
> - 规则变更版本化，支持一键回滚
> - 监控指标：零代码埋点事件量 / 匹配耗时 / 失败比
>
> **典型收益**：80% 的常规曝光/点击埋点可零代码配置，前端发版周期从 3 天降到小时级。
>
> **知识点**：埋点平台、事件委托、CSS selector 稳定化
> **难度**：高级

**Q9：埋点 SDK 如何做隐私合规？（GDPR / 个保法）如何设计用户的"被遗忘权"删除接口，保证 ClickHouse 中近 1 年相关数据都被物理删除？**

> **答案**：
>
> **合规章程（SDK 侧）**：见 9.3 节。核心三要素：① 首次授权弹窗（Consent Management Platform，CMP），未授权前 SDK 不发起任何请求；② 本地 PII 全部脱敏；③ 提供本地和服务端双重"被遗忘"API。
>
> **被遗忘权删除接口设计（难点）**：
>
> 1. **接口**：`POST /api/v1/privacy/forget { distinct_id, sign, reason }` 记录删除请求到 MySQL `privacy_forget_requests`。
> 2. **标记阶段（立即生效的逻辑删除）**：Redis BloomFilter `privacy_forget:distinct_id` 标记后，任何查询 API 都先过布隆过滤过滤掉；查询层统一加 `WHERE distinct_id NOT IN (SELECT distinct_id FROM privacy_forget_requests WHERE created_at > ...)`。
> 3. **物理删除阶段（CH 异步执行，CH 不适合行级 DELETE 高频）**：
>    - 每小时执行一次异步任务：`ALTER TABLE tracking.tracking_events DELETE WHERE distinct_id IN (SELECT distinct_id FROM privacy_forget_requests WHERE status = 'PENDING')`
>    - ClickHouse 的 `DELETE` 是 mutation，本质是生成新 part + 旧 part 标记墓碑；真实物理删除要等 `optimize table ... final` 或合并策略（后台自动合并通常 10~30 分钟）
>    - 对大分区（1 年）避免一次删太多导致 IO 打爆：按 partition_date 分片批量 1 个月/批
> 4. **审计**：每次删除生成不可篡改审计日志（写入专用 append-only log 库），留存 5 年以备监管核查
> 5. **验证**：删完后立即查询该 distinct_id 事件数量应为 0，且 7 天后再次抽查，防止物化视图残留。
>
> **知识点**：GDPR、个保法、被遗忘权、ClickHouse mutation
> **难度**：高级
